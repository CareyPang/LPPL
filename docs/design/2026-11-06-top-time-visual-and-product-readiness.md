# 顶部时间研究网站：视觉方向、交互设计与公众产品差距

日期：2026-11-06。当前用户目标：同时研究几周级局部高点和1–6个月上涨阶段的高点，重点提示阶段性高点；预测时间区间，不承诺随后跌幅。本文为设计与验收方案，本轮未改生产前端、未部署。

证据：**VERIFIED**为本轮源码、公开页面或实际查看内容；**NOT_ESTABLISHED**为建议、推断风险或未建立能力；**NOT_INSPECTED**为未检。设计目标不等于当前达标。主模型验证见[顶部时间协议](../research/2026-11-06-top-time-interval-validation-protocol.md)，当前产品路线见[顶部时间产品规划](../planning/2026-11-06-top-time-product-plan.md)。

## 1. 现状判断：保留品牌资产，重组用户主流程

**VERIFIED（公开页面，桌面）：**`https://careypang.github.io/LPPL/`本轮打开的是指数研究终端；海水品牌页位于[`home.html`](https://careypang.github.io/LPPL/home.html)。海水页首屏有日落海面、中文衬线大字、下潜叙事和“进入工作站”；主要按钮进入`index.html`，没有直接股票查询框。

这说明当前有辨识度很高的品牌场景，但主入口没有对应“普通用户输入A股代码看顶部窗口”的核心任务。先明确正式入口和产品层级，比继续叠加视觉特效更重要。

**VERIFIED（源码）：**`home.html`在≤900px隐藏整组顶部导航，直接“个股”入口也在其中；主按钮和工具推荐仍进入指数工作站。**NOT_ESTABLISHED（本轮移动UI）：**浏览器尺寸覆盖没有实际应用到所检查标签页，读回仍为1280×720，因此不把本轮截图冒充390px实测。390px风险依据CSS和既有合成截图，后续必须重新做真实移动验收。

**VERIFIED（PR分支源码）：**已有数据适配、独立行情加载、当前/历史任务、任务恢复与版本/数据指纹检查。不是只有视觉样机。当前缺口集中在用户入口、状态解释、结果追踪和真实生产验收；没有证据要求立即重写整个前端框架。

从这些参考中借鉴的是：明确的视觉主题、字体层级、进入场景的节奏、页面转场和有反馈的操作。为本产品重新设计查询与时间区间的表达，不照搬大号营销数字、连续滚动劫持、长时间开场或未经验证的“预测成功率”。

## 3. 三种完整视觉方向

### 海洋观测台——建议先试

保留海洋的品牌记忆，采用深海蓝、暖白与少量浅蓝光。首页像一个面向海面的观测台，进入分析页后变为清晰、中性的研究桌面。

- 首屏左侧是品牌短句与用途说明，查询框成为主动作；右侧展示明确标注“界面示意”的时间窗口卡，或已验证状态的真实产品预览。
- 海面只承担背景和空间感；查询框位于稳定、不透明的阅读区域，焦点和文字不能随水面明暗变化。
- 查股后过渡为固定导航、价格图和顶部时间面板，海洋动效退出主分析区。
- 下潜叙事缩短为“观察行情→形成候选→记录验证”，不要求用户看完故事才使用工具。
- 声音默认关闭、不会因滚动开启；手机保留查询和静态场景，重视频/3D按能力和网络降级。

适合：延续现有识别度，同时让普通用户马上知道可以做什么。新增成本主要在入口、视觉系统和信息结构，不是重做海洋素材。

### 时间地形——更独特的替代方向

采用浅石色或深蓝底、低密度等高线和沿时间轴展开的层叠切片。空间表达“不同时间尺度”，不把装饰曲线伪装成市场概率。

- 首页中心是查询，侧边以不同间距的线带解释短期与阶段性观察。
- 切换尺度时改变时间密度和文字标签；不是用红色爆闪告诉用户要崩盘。
- 进入个股后，价格历史与未来时间带共用明确日历；短期/阶段两条轨道可比较或同时显示。
- 使用SVG/CSS或有限Canvas实现主要构图，静态回退仍完整。WebGL只用于可删去的装饰。

适合：把“时间区间”变成产品的独特视觉语言。风险是抽象过度，必须通过用户能否解释短期/阶段差别来验收。

### 纸感研究室——最利于长期阅读

暖灰/米白背景、墨色正文、低饱和蓝强调，编辑式网格和日期档案贯穿全站。品牌页仍可以有克制的图像和细节动效。

- 首页像当日研究简报：查询居首，最近关注与方法入口随后；避免密集金融终端。
- 结果页用一个清楚的时间判断、一个主图和一条版本时间线组成核心区。
- 预测修订像档案版本，能逐次比较原区间、变更原因和结果；动效用于解释变化。
- 适合阅读和移动端，不依赖大型媒体即可形成完整体验。

适合：用户每天回来查看、多资产跟踪和以后付费研究工具。风险是视觉趋于普通，需要靠字体、节奏、图表标注和档案交互形成辨识度。

三个方向可以共用业务组件与数据契约。建议先比较海洋观测台与时间地形的同一查询任务，再决定；不要为了比较视觉而维护三套生产状态逻辑。

## 4. 首页具体如何改

### 第一屏

导航收敛为“查股票 / 我的关注 / 预测记录 / 方法与证据”。初期未实现的账户能力不放假入口；“研究终端”放次级入口，保留原URL兼容。

主内容：一句用途说明、代码或名称搜索、示例股票、数据/研究状态。品牌句可以保留“浪成于微澜之间”，但必须搭配明确用途，例如“观察短期与阶段性顶部的可能时间窗口”。当前未建立能力时加“研究版”，不写“精准逃顶”。

搜索支持代码和名称候选，显示交易所，避免同名误选；回车和点击结果一致。选择股票后立即进入页面壳，行情与已有研究结果分别加载。最近查询可先保存在本机，跨设备同步留给后续账户功能。

### 首屏之后

顺序建议为：产品如何阅读→可交互但明确标示的示例→原始预测与后续结果记录→方法和证据边界。不要先展示多屏原理再让用户找到个股入口。

成功和失败案例使用相同结构、预先固定的选取规则；示例必须保留首次发布时间与模型版本。不能把后验拟合动画呈现成当时已经发出的预测。

## 5. 个股页：围绕“什么时候、哪一级、现在能信什么”

桌面核心布局建议为左侧约2/3价格图，右侧约1/3时间窗口摘要；下方是区间版本记录和可展开依据。390px改为资产身份→当前状态→主图→两类时间窗口→变化记录，研究参数折叠。

顶部必须同时看见：资产名称/代码/交易所、行情截至日、预测首次发出时间、最近更新时间。价格数据新鲜不能掩盖模型结果过旧。

| 区域 | 默认内容 | 展开内容 |
|---|---|---|
| 当前判断 | 阶段性窗口优先；短期窗口其次；尺度待判可独立存在 | 拟合支持、不同尺度的分歧、方法版本 |
| 时间图 | 历史价格和独立的未来时间轴；预测区间有明确端点 | 历次原区间、升级/撤回、验证标签（复盘模式） |
| 变化记录 | 首次发布、更新、失效各自的日期与原因 | 数据/代码版本、原始研究记录 |
| 后续研究 | 价格情景、抄底辅助作为独立入口 | 各自证据与方法，不借用顶部时间成绩 |

当前日线组件主要是收盘折线；若用户确实需要OHLC看盘，再引入K线组件和交易日历测试。不要把折线界面描述为完整K线产品。

不能用长历史拟合窗命名“阶段性顶部已确认”。预测输出尺度和模型输入窗口分别呈现；短期与阶段可能重合，也可能尚不能区分。当前层级识别能力**NOT_ESTABLISHED**，只有完成对应验证后才启用实际分类。

### 结果状态要可理解

| 状态 | 推荐表达 |
|---|---|
| 数据未到 | 正在读取日线；已有结果仍可查看 |
| 当前在算 | 新研究结果生成中；说明上次截至日 |
| 派发未确认 | 任务提交状态待确认；不能冒充计算正在进行 |
| 无符合条件的候选 | 本次没有形成可发布区间，不代表市场安全 |
| 有候选但尺度不清 | 候选时间区间存在，短期/阶段级别暂未判明 |
| 研究证据不足 | 暂不显示预测区间，说明缺少哪类证据 |
| 数据过旧或不适用 | 明确日期和原因；不显示为0风险 |
| 区间更新/失效 | 保留原区间；注明变化，不重新计算首次发出时间 |

阶段性高点可以获得更显著的视觉层级，但不能用夸大的警报、倒计时或红色闪烁制造确定性。

## 6. 动效规范

以下是待验证的设计目标：点击反馈约100–180ms，状态/小面板变化约180–280ms，页面转场约250–400ms；重要内容不等待开场动画。所有时长以设备实测和reduced-motion行为调整，不是性能实测结果。

- 入场：先出现可操作内容和静态海面，再增强视频/空间层。
- 搜索：名称候选、选中状态和载入反馈清楚；不让文字跳动影响输入。
- 图表：切换时间范围保持位置感；预测带变化先保留旧带，再呈现新带与日期差异。
- 历史记录：滑动查看“当时视图”，未来结果默认隔离；复盘需明确切换。
- 性能降级：先关粒子、折射和视差，再降视频质量，最后静态poster；查询与图表功能完整保留。
- 页面隐藏/离开品牌区时暂停装饰渲染。自动持续运动应提供暂停/停止机制；非必要交互动效支持减少运动偏好。[W3C自动运动说明](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide)、[交互动效说明](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions)

声音、滚动劫持、鼠标跟随效果都不是必需。不要让光标追踪和金融数值变化使用同一种动效语言。

## 7. 视觉系统与性能预算

建立一套跨首页/个股/记录页共用的字号、间距、色彩、表单、状态、图表标注和触控规范。正文以清晰中文无衬线为主，衬线只用于品牌大标题；数值使用对齐数字，字重与颜色不替代语义。

分析区使用中性浅灰或近黑，涨红跌绿为A股默认并有符号/文字；未来时间带使用低饱和蓝紫及不同线型，避免和涨跌混淆。品牌深海绿可以留在首页装饰，不能成为绿色K线的同色背景。

移动端以16px输入字号、约44px触控目标、明确焦点与200%放大检查作为产品目标；这不是宣称当前已满足全部无障碍标准。不要将桌面布局等比缩小成手机页面。

**VERIFIED（本轮源码/文件）：**海水页已有poster、媒体回退、延迟水下视频、隐藏页暂停与动态质量降级；桌面海面视频约3.99MB、移动约1.96MB；整个回退素材目录约36.50MB不等于一次访问下载量。仍需测实际请求、解码内存、低性能设备滚动与耗电，再决定删减。Google Fonts依赖需在大陆实测并准备合适的字体回退/授权自托管。

采用真实用户p75的LCP≤2.5s、INP≤200ms、CLS≤0.1作为Web性能目标；另外单独记录页面可操作、行情可见、缓存可见、排队和模型计算时间。实验室合成环境与真实大陆用户成绩分开。[Google Web Vitals](https://web.dev/articles/vitals)

建议第一轮先把首屏HTML/CSS/交互与poster控制在明确预算内，并延后非必要媒体；具体KB预算在真实请求清单后冻结，避免先拍数字再牺牲可读性。媒体不进入数据接口的成功依赖。

## 8. 是否更换前端

**NOT_ESTABLISHED（建议）：现在不整体重写。** 原生多页HTML/JS已经具备可复用的数据适配、会话、视图和媒体模块。先抽出统一的搜索、资产身份、结果状态、时间窗口轨道、版本记录和图表组件，按现有契约逐页整理。

页面改造继续遵守`frontend/AGENTS.md`：业务数据由适配层读取，前端不重算模型；失败/开发状态不显示成功数值。该文件和实际API契约已有漂移，需要先在专门工程变更中统一，不能让新设计绕过数据和证据边界。

未来出现跨页账户/关注列表、通知中心、多资产联动与复杂持久状态时，再比较组件框架迁移。迁移采用新产品壳逐页接管、保留旧URL/查询参数和数据适配，不把“换React”当成提高预测能力或自动变快的措施。具体框架和库版本另行评估，本轮不安装新依赖。

### 源码可见、尚未复现的两项风险

1. `frontend/stock.html`的`renderDip`等待环境数据后写共享面板，中间缺少当前资产/渲染代次校验；切股后可能被前一资产迟到结果覆盖。应单列回归，不能宣称本轮已发生或已修复。
2. `stock-session.js`将部分未识别任务状态归为running，而Worker有`dispatch_unknown`；界面可能显示“计算中”，实际尚未确认派发。需明确状态映射。

**VERIFIED（文档漂移）：**`docs/frontend_contract.md`仍写不提供API，但当前适配层存在Worker API接线；首页“21窗/三个尺度”与其他页面的六尺度表达也需要按版本核对。当前不修改旧模型值，仅登记契约修订任务。

## 10. 执行次序与验收

1. 完成顶部协议与结果状态契约，确保视觉不会把未验证输出包装成成功预测。
2. 用同一份模拟状态制作海洋观测台与时间地形的桌面/390px原型，测试查股、理解尺度与识别过期数据；本轮对话中的三方案仅为视觉概念，不是可用生产网站。
3. 选择一套后先改首页入口和个股核心区域，再统一记录页；保持现有API与兼容路径。
4. 真实环境验收后才启用前瞻记录和受控试用；公开部署仍需用户明确授权。

- [ ] 首屏直接查股；手机不因隐藏导航失去入口。
- [ ] 用户能说明“短期高点”和“阶段性高点”的区别，并知道当前是否已建立识别能力。
- [ ] 顶部区间不附带下跌10%或保证跌幅的暗示。
- [ ] 首次区间与修订并存；没有事后改期冒充提前命中。
- [ ] 桌面/390px/200%缩放下无主要操作遮挡或横向溢出。
- [ ] 没有结果时页面仍有清晰状态、日期和可用行情。
- [ ] 图表、任务与媒体失败互不阻断；迟到结果不串股。
- [ ] 动效可关闭，静态回退完整；关键性能在真实网络单独记录。
- [ ] 付费模板/媒体/字体等使用权核对，未购买资源不冒称已授权。

所有设计方向均为**NOT_ESTABLISHED（待用户任务测试）**。本轮的公开页面观察和源码审查不能替代生产功能、预测能力或大陆访问质量验收。
