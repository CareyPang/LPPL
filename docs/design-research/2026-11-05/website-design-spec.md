## 1. 产品定位与不可越过的边界

**设计建议：** 产品定位为“研究金融结构、检查情景、审阅证据的观察工作站”。主页建立品牌，工作站支持分析，证据页解释能力边界；三者使用同一语言和数据定义。

用户应在每个主要页面迅速回答四个问题：正在看什么资产；数据截至哪天；图中哪些是观测、哪些是模型情景；当前结论经过什么检验。

时间层呈现拟合临界时间、情景分布、历史回放、稳定性和已完成验证；价格层呈现实际价格、已实现回撤、历史条件分位、估值参照和规则状态。两层只有在独立验证与预先定义的数据契约支持时才能联合呈现概率。前端不得自行把它们乘成一个“逃顶成功率”或“抄底胜率”。

H1/H2/H3、Q2、MPL、Ising、Q-DD2、PPE 等研究结果以对应封存结论为准。设计不能把失败、未检验、描述性统计、模型内参数稳定性升级成预测能力。技术故障与统计检验失败必须是两类不同状态。

## 3. 信息架构与路由

### 3.1 一级入口

**设计建议：** 一级导航固定为“概览 / 工作站 / 市场 / 历史回放 / 研究与证据”，全站保留资产搜索。个股是工作站支持的资产类型，并有稳定的直接访问URL；不另建一套独立产品逻辑。

| 页面 | 用户主要问题 | 必须呈现 | 不应承载 |
|---|---|---|---|
| 概览 | 这是做什么的，我从哪里开始？ | 品牌说明、可分析资产、最新数据日期、进入工作站、方法与证据入口 | 全套参数控制、冗长统计表、未经证实的命中案例营销 |
| 工作站 | 此资产当前有哪些可观察结构？ | 资产头部、行情图、时间层、价格层、证据摘要、数据状态 | 与当前资产无关的装饰视频、混合成单一胜率 |
| 市场 | 外部市场环境是什么？ | 资金、融资、估值、来源及更新时间，明确描述性 | 默认把资金流或估值并入LPPL模型分数 |
| 历史回放 | 当时实际可见什么，后来发生什么？ | as-of选择、观测/后续分界、历史情景、事后标签、版本 | 将事后标签冒充当时预测、从单案例推断总体胜率 |
| 研究与证据 | 哪些方法成立，哪些没通过？ | 方法卡、开发/校准/测试分段、通过/失败/未检验、样本和版本、报告链接 | 只陈列成功个案、不显示失败路线 |
| 指南 | 如何理解术语和操作？ | 指标解释、尺度定义、图例、数据状态解释 | 与正式数据契约不一致的另一套解释 |

## 4. 墨绿品牌与行情绿色的分离

### 4.1 核心规则

**设计建议：** 墨绿是界面身份，不是行情或模型结论。墨绿稳定用于导航底、品牌面和浅色主题主按钮；深色主题主按钮采用低饱和浅绿配深色字，以保持可读性。品牌操作色与行情涨跌色使用独立token。图表绘图区使用中性白或近黑，不铺绿色渐变、绿色玻璃面板或海洋视频。

中国资产默认保持现有红涨绿跌习惯，图例明确“红：上涨；绿：下跌”。本次原型同时提供绿涨红跌和蓝涨橙跌，由用户显式选择；正式产品应持久保存选择，不因市场切换而悄悄颠倒含义。各色序的图例和涨跌符号必须同步；蓝橙选项不等于已经完成全部色觉与可访问性验收。

涨跌数据同时带 `+/-`、方向符号和OHLC数值；任何重要状态不能仅凭颜色区别。命中/未命中、通过/失败、当前/过期使用文字及形状，不借用行情绿表示“好”。成功加载是技术状态，不是投资成功或预测通过。

**设计建议：** 中文界面用一套易读无衬线；数字与参数用等宽数字。衬线只用于主页标题和研究文章标题，不用于行情表或表单。正文16px起，桌面密集表格可14px；关键证据与错误说明不得缩成10px脚注。标题层级使用32/24/20/16px附近的少量档位，间距基于4px。浅深主题的字号、控件位置、图表语义不变。

## 5. 工作站布局：时间、价格、证据三层

### 5.1 桌面1440px

**设计建议：** 页面左右24px留白，内容最大1360px。顶部64px为品牌、主导航、资产搜索和主题开关；资产摘要约72–96px。分析区采用可伸缩主图加约320px说明栏，列间24px。图表高度以520–640px为起点，不强迫全站固定高度。图下为时间/价格/证据详情标签页，研究表格保持局部滚动。

资产头部固定显示名称、类别/交易所、代码、价格口径、数据as-of、生成时间、模型版本入口、数据状态。时点选择改变全页上下文，不允许只改图而保留另一日期的摘要。

说明栏先给“可以观察到什么”，再给“不能推出什么”，最后给原始字段和方法。无合格拟合时不补一个安慰性看多/看空结论。

### 5.2 1024px

**设计建议：** 顶部保留品牌、资产搜索及折叠菜单；主图全宽。说明栏移至图下两列，长表格独立展开。重要证据标签不因收缩隐藏。避免出现同时包含页面横向滚动、表格横向滚动和图表拖动的三层嵌套。

### 5.3 390px

**设计建议：** 左右16px留白，所有主要内容单列。顶部56px，显示品牌、菜单和主题；下一行全宽资产搜索。摘要先显示身份与as-of，再价格与技术状态。主图高度约320–380px，提供全屏分析按钮。常用控件目标至少44×44px；图例允许自然换行，不截断颜色含义。

时间/价格/证据用三个可点击标签切换详情，但顶部共同的as-of和证据状态始终可见。长方法说明用可访问的折叠块；关键限制、错误、样本不足不藏在默认关闭的折叠块。六尺度表在移动端改为尺度行卡片，优先显示尺度、合格/总窗数、证据和区间，不要求用户横滑五列表才能看到证据。

导航采用可访问菜单或固定底部“工作站/市场/历史/研究”四项；必须包含首页/概览返回路径。底部导航不得遮挡最后一行和系统安全区。

### 5.4 320px

**设计建议：** 左右12px；身份分两行；搜索按钮保持可点；不依赖同一行放置代码、名称、价格、日期和版本。图高280–340px，减少轴刻度数量，保留数据本身。长代码、报告路径、错误信息可换行。不得通过把字体缩至难读尺寸来解决布局溢出。

### 5.5 断点不是设备判断

以上是验收视口，不是只支持四个宽度。320–1440之间连续拖动不得出现中间断点溢出。纵向和横向、200%缩放、系统大字体均需检查；当前源码有响应式规则不代表这些测试已经完成。

| 层 | 绘法 | 必须同时说明 |
|---|---|---|
| 实际历史价格 | K线或收盘线，红绿仅表涨跌 | 价格口径、日期、OHLC缺失情况 |
| as-of分界 | 中性竖线及明确日期标签 | 此前为当时可观测；之后只在回放模式显示 |
| 后续实际走势 | 蓝色线/区域标识，明显写“事后实际” | 不是当时已知输入，不是模型路径 |
| 时间情景 | 时间紫轮廓+低透明填色；簇可分行 | 过滤集、聚合方法、q20/q80或其他定义、未校准状态 |
| 价格参考 | 价格金虚线/纹理带，默认可关闭 | 历史条件分位、样本数、确认可用日；不是目标价 |
| 事后确认事件 | 蓝色三角/菱形，附标签定义 | 确认所需未来观察长度；不是预测发布时间 |
| 证据/质量标记 | 图旁文字徽章与符号 | 数据过期、缺失、边界拟合、检验未通过等具体原因 |

一个图默认不超过一组主时间情景与一组价格参照，其他簇通过列表选中。避免同时叠加六尺度、全部历史簇、拟合曲线和多个价格带导致“越密越可信”的错觉。

### 6.2 时间层定义必须可见

**设计建议：** 明确“拟合过去跨度”和“临界点距as-of的距离”是两列信息。6–12月尺度表示用过去约127–252个bar拟合，不是承诺未来6–12个月见顶。`t_c`不能自动标为顶部日。

当前后端有box pooled分位、KMeans簇分位、STANDARD直方图等不同集合；界面须显示来源，不把它们画成同一概率分布。`share`标“合格拟合中该簇占比”，不能标“崩盘概率”。过去、当日、未来tc分开标识；没有跨as-of稳定性字段时，禁止画“连续确认”徽章。

窄区间不得通过UI强化成高置信预测。展示分位宽度时同时展示拟合数量、窗口重叠提醒及校准状态；没有覆盖率验证就不称“95%预测置信区间”。

### 6.3 价格层定义必须可见

**设计建议：** “已实现回撤”是观测事实；“历史同类事件分位”是描述统计；“估值参照”是条件换算；“规则确认”是滞后状态；“预测目标价”只有经过对应验证且后端明确支持时才出现。不同层不能复用同一种实线和同一个“目标”标签。

样本数不足时展示具体n和不足原因，不画空心假区间；无法比较的估值口径展示不适用，不补零。若只有收盘价，使用收盘线；不得把open/high/low全部等于close的回退值渲染成看似真实的完整K线。

### 6.4 图表交互

**设计建议：** 鼠标拖动/滚轮或按钮缩放；键盘方向键移动，+/-缩放，复位按钮有可见标签。十字线提示包含日期、价格口径、as-of关系、当时情景和事后标签，不能混在同一未标注列表。

触屏默认允许页面纵向滚动；需要图内平移时进入显式“图表交互/全屏”模式，提供退出。点击点可锁定提示，再次点击空白解除。不要求用户只能通过悬停查看关键解释。Canvas旁提供可访问的摘要及小型数值表/下载入口（数据确实可导出时），不能只靠像素图传递信息。

## 7. 查询状态、空态、失败和旧数据

### 7.1 状态模型

**设计建议：** 状态分三个独立维度，避免用一个颜色灯混写。

| 维度 | 允许状态示例 | 用户可见表述 |
|---|---|---|
| 数据 | 无记录、已缓存、最新可用、滞后、部分缺失、来源失败 | “截至11月3日；晚于最近已闭市日2个交易日” |
| 任务 | 未请求、已提交、处理中、当前就绪、历史处理中、完成、失败、超时 | “当前观察已就绪，历史回放仍在生成” |
| 研究证据 | 描述性、研究候选、开发段、校准/测试通过、未通过、未检验 | “个股研究候选；尚未建立样本外预测能力” |

任务完成不代表研究通过；无合格拟合不等于没有风险；未计算不等于零；缺文件不等于模型认为安全。

### 7.2 明确状态与操作

| 情境 | 展示 | 操作 |
|---|---|---|
| 首次进入无资产 | 搜索说明和支持范围 | 输入名称/代码，示例不暗示已计算 |
| 输入歧义 | 候选资产类别/交易所/名称 | 用户明确选择 |
| 读取已有结果 | 骨架仅用于布局，显示缓存读取状态 | 不重复提交任务 |
| 已有旧结果 | 固定资产身份、as-of、旧数据标识 | 明确“刷新结果”操作 |
| 当前生成中 | 已提交时间、当前阶段（仅真实可得）、可继续浏览旧结果 | 不显示虚假百分比；可停止前端等待，不声称取消了后端任务 |
| 当前就绪/历史处理中 | 当前卡正常使用，历史区域独立占位 | 不让历史阻塞当前观察 |
| 历史失败 | 历史失败原因摘要、当前仍可见 | 仅重试历史；不清空已成功当前结果 |
| 无合格拟合 | “本次在所选规则/尺度下无合格拟合” | 查看尺度/方法，不渲染为看多或看空 |
| 数据不足 | 实际bar数、所需跨度、不可计算字段 | 其他可用观测仍显示 |
| 来源失败但有缓存 | 故障提示+缓存日期 | 再试，明确当前是旧数据 |
| 证据未通过 | 接近数值的“未通过/仅描述”说明 | 查看对应研究结果，不提供预测操作按钮 |

切换股票时，新输入和旧图不得看似属于同一资产。可选择立即替换为骨架，或保留旧卡并突出“仍显示上一资产”；无论哪种，旧卡名称/代码必须不可被新输入覆盖。所有迟到响应按请求身份忽略，不能污染当前资产。

### 7.3 缓存新鲜度

**设计建议：** 同时保留 `asof`（价格截止日）、`generated_at`（产物生成时刻）、数据版本、模型版本，不能用生成时间替代行情新鲜度。停牌/长期无交易不简单标为API故障。缓存是否可用由后端的闭市交易日、数据覆盖和版本定义决定；前端负责呈现，不自己推断上市状态或编造新数据。

## 8. 前后端边界与契约

**当前事实 VERIFIED：** `app/lppl-data.js`从静态JSON读取数据，也有Worker查询、状态、结果接口。[S05]、[S08]。它的旧注释“只读静态JSON”不完整，设计文档应区分读取既有结果与显式提交计算任务。

**设计建议：** 后端负责取数、复权、PIT截断、拟合、过滤、聚类、bootstrap、统计检验、证据等级和缓存版本；前端只负责选择、路由、状态呈现、图表交互、单位格式和可访问性。禁止前端补算金融模型、填造未返回的概率、以视觉调参改变模型结果。

规划中的契约字段如下；**这些是建议，不代表当前均已实现**：

| 对象 | 最低所需字段 |
|---|---|
| 资产 | asset_id、asset_type、exchange、symbol、display_name、currency、price_basis |
| 版本/日期 | asof、generated_at、data_version、fit_code_version、model_version、schema_version |
| 数据质量 | freshness、last_closed_trading_day、missing_fields、source_status、n_bars、stale_reason |
| 时间情景 | filter_set、aggregation、scale、lookback_range、ahead_unit、tc_relation、quantiles、n_qualified、n_windows、evidence |
| 价格参考 | reference_type、conditioning_bucket、confirmed_asof、n_events、quantiles、units、evidence |
| 任务 | request_id、asset_id、submitted_at、phase、current_result_ready、history_ready、error_code、retryable |
| 研究 | evidence_label、evaluation_scope、sample_split、sample_size、method_version、report_url、limitations |

缺字段按 `not_available`呈现。新增字段需明确schema兼容；既有结果不因新前端发布变成空白页。导出失败、404、HTTP成功但schema错误应是不同技术错误。

## 9. 性能与可访问性

### 9.1 性能预算（设计验收目标，未测）

- 工作站不请求首页的海洋图片帧/视频/音频。
- 首页静态文本、搜索/CTA和poster先可用；动画加载失败不影响主任务。
- 减少运动模式、节省流量模式或不支持媒体时可使用静态封面；不自动播放声音。
- 明确拆分网络取数、计算排队、拟合、产物发布和浏览器渲染耗时，不能把后端分钟级延迟藏成无限spinner。
- 已有缓存的页面只需读取和渲染，不因为切换主题、缩放图或展开证据触发金融模型计算。
- 图表按可视范围和像素密度降采样显示，但保留原数据供精确查询；不得因降采样改变事件、区间或统计。
- 字体控制在一套界面字体和数字字体所需字重；标题衬线可渐进加载；失败有可靠系统回退。
- 用户交互后前端目标为及时反馈、图表拖动不中断。具体毫秒与Web Vitals预算应在确定设备/网络测试配置后冻结，不能用无测量数字宣称达标。

### 9.2 可访问性

设计以WCAG 2.2 AA相关要求为基线：普通文字目标≥4.5:1，大文字≥3:1；辨识控件/状态及重要图形的必要部分≥3:1。官方要求存在适用条件与例外，验收应看实际组合，不能仅检查配色表。[W1]、[W2]

本项目主动采用主要触控目标44×44px作为设计目标；这不是声称WCAG 2.2 AA普遍要求44px。AA目标最小尺寸条款为24×24 CSS px并含间距等例外。[W3]

键盘可访问全部导航、主题、资产选择、标签、折叠项和图表替代控制；焦点可见且不被固定栏遮挡。状态变化使用适度 `aria-live`，每10秒轮询不应不断重复整段内容。错误摘要能关联输入框；表格有表头；Canvas有文字替代。主题、字号与运动偏好持久化，但用户随时可恢复默认。
