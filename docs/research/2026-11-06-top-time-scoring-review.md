# 顶部时间评分审阅：手工真值表与三项语义修正

日期：2026-11-06。状态：**DRAFT / 待用户确认 / 未实现评价器 / 未运行模型**。

本文件将[顶部时间区间协议草案](2026-11-06-top-time-interval-validation-protocol.md)转成可逐例审阅的评分合同，并公开三项仍需修正的定义。本文只使用虚构交易日和明确给定的事件真值，没有读取新行情、生成真实事件标签、运行拟合或回测，也没有修改原协议。

用户已确认的方向保持不变：重点提醒1–6个月上涨阶段的高点，短期局部高点也需要；至少提前5个交易日，时间窗最好不超过10个交易日；不以随后跌10%或任何其他回撤幅度定义成功。**本文件中的手工通过不构成模型通过，也不授权提前实现新评价器。**

## 1. 本轮推荐确认的评分合同

1. **阶段高点优先。** 以阶段事件的“首条原始区间、实际可行动提前、时间宽度、层级”联合召回作为主指标；短期成绩独立列出。
2. **区间含两端。** `[T100,T109]`宽10日；`[T100,T110]`宽11日。实际可行动日为T95、峰日为T100，提前5日；可行动日为T96则只提前4日。
3. **首警不可事后修好。** 首次错窗、太宽或层级错误，后续修订另列；取消、换episode或重发不抹去原结果。
4. **把层级向量与页面最高层级分开。** 在当前嵌套定义下，“阶段”自然也有短期标签；它不是`stage=true,short=false`。
5. **同一条“兼属两层”主张只指一个事件家族。** 阶段为锚、短期为同家族标签；不能让两个层分别命中不同高点，再说是同一次两层命中。
6. **允许拒判，完整计分。** 尺度待判不是阶段成功；无信号与运行失败都不能从阶段事件召回分母消失。尚未成熟则待定，不提前变成命中或误报。

除用户的5日/10日目标外，`L/R/G/H`、上涨段范围、匹配与通知单位均为**待冻结研究方案**。表中沿用`short=10/10`、`stage=63/21`、`G=5`、`H=63`，只为让例子有确定答案，不表示已经选定最优参数。

[顶部标签例集](2026-11-06-top-time-label-casebook.md)新增阶段右42日的语义对照：上证2024-03-18在原右21日下纳入、在右42日下因5月20日更高而排除。42日仍待用户确认，不是性能最优结论。本评分表的成熟日期继续按原右21日计算；若选择右42日，峰及无事件账本的成熟日期必须相应重填，不能沿用T126等日期。孤立T100峰在右42日加G5下最早需到T147闭合。

## 2. 争议一：当前定义下不应出现自然的stage_only类

### 2.1 确切关系

在同一价格口径、相同交易日日历、数据完整、两层均可判定时：

```text
[i-10,i+10] 是 [i-63,i+21] 的子区间。
若 p_i 是阶段邻域的最大值，则 p_i 必为短期邻域的最大值。
因此 stage_candidate(i) => short_candidate(i)。
```

这是集合包含关系，不是经验上的“通常成立”。原协议第3.5节“阶段候选通常也满足短期候选”应在下一次经确认的修订中改为严格包含，并附前提。阶段增加上涨段条件只会进一步筛选阶段集合，不会破坏其对短期候选的包含。

两层平顶分组可能有不同代表日或一对多关联，但原始阶段候选点仍须出现在某个短期候选分组中。必须沿候选集合交集建立家族关系；不能因为两个分组的代表日不同就制造`stage_only`自然类。跨层分组歧义需要保留，不在本文假设其自动一对一。

### 2.2 推荐表示

| 事实或页面值 | 正确含义 |
|---|---|
| 真值向量`{short:true,stage:false}` | 只有短期层事件，且阶段层已经成熟、可判定 |
| 真值向量`{short:true,stage:true}` | 阶段事件同时具有短期层标签 |
| 页面最高层级`stage` | 重点提示阶段层；不否定短期标签 |
| 页面最高层级`short` | 目前只提出短期层主张；未成功识别阶段层 |
| `scale_uncertain` | 有时间候选但未提出可靠层级主张；不得记阶段真阳性 |
| `short=true,stage=unknown` | 短期标签成熟、阶段尚待确认；不是short_only |
| `short=false,stage=true` | 当前嵌套规则、完整同口径输入下为一致性错误，先审查标签、缺失与映射；不能当第四种自然顶部 |

原协议混淆表中的自然真值行`stage_only`建议删除，改为“标签/跨层映射异常”审计项。自然最高层级真值使用`short / stage / 无事件 / 未成熟或不可判定`；原始标签向量另存。预测`both`可作为页面`stage`附带同家族短期标签的兼容写法，不另算一个更高级别。

## 3. 争议二：峰日已成熟谷点会遗漏21–25日上涨段

### 3.1 原规则的真实代价

原协议要求`STAGE-RISE`的谷点在峰日收盘数据可用时已成熟。对孤立低点`a`，采用低点`R=21`和闭合等待`G=5`时，最早需要到`a+26`确认。若峰为T100：

| 谷点末日a | 谷峰间隔 | 低点最早成熟日 | 原峰日成熟条件 |
|---|---:|---|---|
| T74 | 26日 | T100 | 可以通过（仍需其他条件） |
| T75 | 25日 | T101 | 被排除 |
| T79 | 21日 | T105 | 被排除 |

因此虽然文本写21–126日，原规则的孤立谷实际最低为26日；长平底或数据迟到可能再延迟。它把“用于事后定义上涨段的谷”与“峰日已经能知道的谷”混在一起，可能不符合用户关注约一个月上涨阶段的语义。这是规则偏差，不是模型效果。

### 3.2 推荐修正候选：事后固定区间选谷

**推荐供用户确认，不直接覆盖原协议：**保留21–126日谷峰跨度候选，但移除“低点必须在峰日已成熟”的额外条件。上涨段只作为事后标签，不能作为峰前实时特征。

具体冻结规则应为：

1. 对阶段峰代表日`u`，事先定义允许谷点末日范围`[u-126,u-21]`；不能随最终评价日期向后滚动这个范围。
2. 用固定低点标签版本（候选`L=21,R=21,G=5`）确定该范围内的低点事件。选择末日`a`最晚的合格低点；相同末日按稳定事件ID打破并列。这里的“合格”只按冻结的低点、完整性及时间规则判断，不看LPPL分数或命中结果。
3. 再检查`p_u>p_a`，以及`(a,u]`没有低于`p_a`的价格；任意正向价差均可，不设最低涨幅或突出度。不因随后回撤小就删除峰。
4. 等峰、候选低点分组及“范围内不存在更晚合格谷”的检查全部闭合，才确定`STAGE-RISE`真值。保存实际依赖区段、排除的候选及原因；未闭合时保持待定。
5. `rise_label_support`固定为该条标签实际使用的完整依赖集合；`rise_label_available_at`取这些依赖最晚可得时间。整体峰标签可用时间为峰与上涨段依赖可用时间的较晚者。原始行情修订另开版本，不能在同版本已冻结标签中随复盘日期换谷。
6. 长平底、边界分组或缺失可能使支持范围延长，因此不能不检查就把所有低点成熟时间写成`a+26`，或把所有上涨标签写成固定`u+26`。如果无法列出有限且闭合的依赖，保留`PENDING/NOT_ESTABLISHED`，不强行选谷。

在表中孤立谷/峰例子下，T79谷到T100峰的21日上涨段可以在谷T105成熟、阶段峰T126成熟后于T126确认；它在T100当时仍不是已知标签。训练在T126之前不能读取这个最终上涨标签。

### 3.3 不隐藏的选择

| 方案 | 获得什么 | 付出什么 |
|---|---|---|
| A 保留峰日成熟条件 | 谷在峰日已可识别 | 必须承认21–25日段系统性被排除；可用跨度应如实标注为受成熟约束，不能仍宣传覆盖完整21–126日 |
| B 采用事后固定区间，**推荐** | 更贴近用21–126日结构定义上涨段的目标 | 标签确认更晚；全部未来依赖必须隔离，不能用于实时提示 |

两种方案先在合成例集上核对含义，由用户确认，再写入协议版本。不得在真实模型评分后挑更容易命中的方案。

## 4. 争议三：both必须绑定同一事件家族

若行动日为T75，下一短期高点为T85，下一阶段高点为T100，原协议逐层取“下一事件”的规则会使同一个`both`记录指向两个家族。其区间若是`[T100,T109]`，只能覆盖阶段峰；不能称“两层同一次命中”。

推荐在发出时固定`claim_scope`，而不是评分时临时选择：

| 主张范围 | 匹配规则 | 同家族与计数 |
|---|---|---|
| `NEXT_STAGE_FAMILY` | 匹配行动后H日内下一阶段事件，区间不参与挑事件 | 阶段主张及兼属短期只关联这个家族；独立较早短期事件仍可能漏报 |
| `NEXT_SHORT_FAMILY` | 匹配行动后H日内下一短期事件 | 如该家族后来有阶段真值，则阶段属于漏识别；短期时间项仍可通过 |
| `SCALE_UNCERTAIN` | 仅做预登记的时间诊断，不获得阶段层级命中 | 保留输出/拒判分母；不能事后改成有利层级 |

`both`建议映射为`NEXT_STAGE_FAMILY`，表示“所预测的同一个阶段事件也具有短期结构标签”。它不是两个不同事件的独立预测。如果产品希望同时提示较早短期峰和较晚阶段峰，应发出两个有独立ID、区间及目标范围的claim，并计入对应提醒负担。

同家族不自动保证两个时间项都成功：若短期代表日为T99、阶段代表日为T100，而区间从T100开始，则阶段时间项可以命中，短期原始代表日没有命中。每层按自己的代表日计分，家族联合成功最多计一次；不能为获得短期命中而偷偷把T99改成T100。

跨层一对多或缺乏明确候选交集时，标记`FAMILY_LINK_AMBIGUOUS`。主阶段成绩可以按明确阶段目标单列，但不宣称已通过同家族两层联合识别。跨层关系必须先于最终评分生成并保留版本。

## 5. 手工真值表的共同假设

以下每一行是**独立虚构世界**，不是同一条真实价格路径的多个预测，不应合并算“模型准确率”。`Tn`是交易所交易日编号，无周末换算；“发出”以实际可见时刻为准。

除另有说明外：有一个孤立阶段高点家族F100，峰日与两层代表日都是T100，真值向量为`{short:true,stage:true}`；阶段标签在T126闭合，评价在T200完成；数据完整、可行动性已给定、没有其他会改变“下一目标”的事件。T200也覆盖表中无事件期限及其闭合检查。所有窗口均来自首条原始记录，所有记录在当时完整处于未来，`H=63`。

`A`为实际可行动交易日，`W=r-l+1`，`Lead=100-A`。严格主命中还要求`l>=A+5`、区间包含目标、`W<=10`及正确阶段主张。首次可见一般为`A-1`收盘后；特殊迟到例明确覆盖此假设。

计数符号：`E`为成熟阶段事件数，`P`为已成熟、明确提出阶段或both主张的episode首条数，`TP`为一对一严格阶段成功数，`FN=E-TP`。严格阶段精确率为`TP/P`，`P=0`时为NA；宽窗、错窗、迟到和重复阶段主张仍留在P中。尺度待判与只报短期不进入P，但保留在全部输出/拒判分母和阶段漏报中。

| S20 单日窗与5日提前 | F100；A=T95；stage；`[T100,T100]` | W=1不是0；Lead=5；满足未来合同 | 严格阶段成功；不因窄窗宣称零不确定性 | `1/1/1/0` |
| S21 事件提前够、窗起点太近 | F100；A=T95；stage；`[T99,T108]` | W=10；Lead=5；包含T100，但l=A+4 | 若采纳“整个区间至少提前5日”合同则主失败；若只要求实际事件提前，则会通过，须先选定合同 | 推荐严格合同下`1/1/0/1` |

S14/S15的零只表示尚未进入**成熟评价账本**，不表示真实没有事件或没有提醒。应产出账本、原始预测和待定数量仍保留。S12已假定事件价格可判定；若行情本身缺失使事件未知，不能按同一规则编造一个已知漏报，而应另报未知区段。

S08“过度升级”是独立诊断：严格阶段匹配因期限内没有阶段事件而失败；另在时间相合且已成熟的短期事件上标过度升级。不得为了得到这个诊断，将短期事件塞入阶段召回分母。

S13中第二次episode即使按最终重启规则属于不合法重启，只要确实向用户发出了新的通知，也须保留通知负担与错误记录。正常同episode的后台更新不增加P；是否通知及episode重启/冷却规则仍待冻结。

## 6. 真值表之外还需公开的两个选择

### 6.1 5日要求约束事件，还是整个显示窗口

用户确认至少提前5日，原草案进一步建议`l>=A+5`。这比“实际峰日至少在A+5以后”更严格，S21展示两者不同答案。**推荐保留整个显示窗口条件**，使用户看到的最早可能日期也有5日准备时间；但这是需确认的产品合同，不应伪装为用户已明确选择的细节。

### 6.2 结构阶段峰还是上涨段阶段峰

手工评分表将事件真值作为已给条件，只验证如何计分。它不替用户确认`STAGE-STRUCTURE`已完整表达1–6个月上涨阶段。标签例集应另外展示两种定义的纳入/排除差异；推荐先解决第3节谷点成熟偏差，再确定阶段主标签。不能先以结构峰取得成绩，展示时再改称完整上涨阶段结束。

## 7. 实现前必须确认的最小清单

- [ ] 阶段主标签采用哪种操作性定义；21–126交易日是否作为待冻结的1–6个月近似。
- [ ] 对上涨段选择第3节方案A或B；推荐B，未来依赖全部用于事后标签。
- [ ] 接受嵌套标签向量与页面最高层级分开；删除自然stage_only类。
- [ ] both指同一事件家族；采用阶段锚，独立短期目标另建claim。
- [ ] 确认首条原始区间不可由修订补成成功；同一事件只得一次主成功。
- [ ] 确认含端点宽度和真实可行动时间；确认S21采用哪一种5日合同。
- [ ] 冻结episode/通知单位、重启规则和提醒负担的计数口径。
- [ ] 将上述手工案例与标签例集交叉核对，确认后才授权实现新评价器。

最低召回、最低精确率、提醒预算和统计精度等性能通过门槛，应在独立性能评价前冻结；它们不是实现标签与评分评价器前必须先猜出的准确率目标。评价器应先忠实复现已确认的标签、时间与计数合同。

本轮完成标准是形成这些可以逐条接受或修改的真值，不是让旧报告重新过关。后续协议修订应引用本文件并保留版本差异；在用户确认前，旧协议与本文建议并列为草案，不悄悄替换。
