# 逐日历史重放 v1：记录已建立，阶段顶部联合目标未达到

日期：2026-11-06。协议冻结提交：`e06aceb3e3cd685d665878c933d2277577aa5e44`。证据版本：`top_time_saved_interval_replay_v1`。

**结果：本轮九组LPPL时间区间策略，在相同91个成熟、可判定阶段事件上，只有0–3次满足首条区间包含峰日、理论行动提前至少5日、含端点宽度不超过10日及整窗提前条件；阶段漏报88–91个。没有证明达到用户的阶段提醒目标，也不能把3次成功的thin策略宣布为赢家。**

**交付：**已建立423,360行逐日重放账本、18,292条假想预测/修订、120组独立目标探针评价，以及原始输入和执行源码前后哈希。真实发布账本保持空表，未向其中塞入任何历史重放。

## 1. 这轮究竟执行了什么

本轮按[冻结协议](2026-11-06-top-time-replay-protocol.md)，读取旧开发段六指数的已保存聚合结果和行情，构建新标签并调用新评价器。没有运行优化器、重新拟合、下载行情、切换生产策略或发布网站。

| 范围 | 实际数量/口径 |
|---|---|
| 标的 | 上证、上证50、沪深300、中证500、深证成指、创业板六指数；不是个股验证 |
| 旧拟合 | 569,270行，4,214个实际有拟合的标的日期 |
| 原计划扫描 | 4,236个标的日期；22个早期日期无原拟合 |
| 原频率 | 每5个观测日一次，截止2018-12-26 |
| 重放账本日期 | 各标的首次旧计划扫描日至2018-12-31，共21,168个标的观测日 |
| 每日账本组合 | 九策略及一个固定时间参照，各有stage/short两个独立探针；共423,360行 |
| 假想预测记录 | 18,292条，其中旧九策略两探针9,820条，固定参照两探针8,472条；含修订 |
| 真正历史发布记录 | **0条**，未建立原scope、发布时间或真实行动证据 |
| 标签观测截止 | 读取价格至2019-12-31，仅用于事后成熟；不产生2019年新预测 |

**逐日记录不等于每日拟合。** 338,640行是`NOT_SCHEDULED`，明确注明该截点没有缓存拟合；62,612行是计划截点下的假想无信号，3,420行是输入不可评价，396行是没有原拟合。它们没有被改写为每日新模型结果或原系统真实运行失败。

每个策略的所有原区间先被统一声明为假想stage定位探针；相同区间另作独立short对照。这用于检验时间定位，**不是声称模型当年已分类出短期或阶段顶部**，也不是已经实现“先局部、后阶段”的真实升级服务。

## 2. 记录怎么追溯，哪些时间是假想的

逐日记录有稳定ID、输入截止日期、`source_id`、协议哈希、规则版本、实际本轮`replay_generated_at`、源扫描状态、episode及新预测/修订身份。源hash与路径共用[输入映射](evidence/top-time-replay-20261106/v1/input_map.json)，不在每行重复整个配置。

`original_published_at`始终为空。用于诊断评分的历史17:00发布时间和下一观测日行动时点，分别写作`hypothetical_published_at`与`hypothetical_action_*`；身份统一为`HYPOTHETICAL_REPLAY_CLAIM_NOT_ORIGINAL`。评价使用`mode=diagnostic`、`actionability=theoretical`，不能称为真实可交易提前命中。

第一次报警的episode到期日固定，后续报警只追加修订；无信号或非扫描日不重置首条。到期之后才允许新的episode；新episode也不能修复同一事件的更早错误首警。全部假想通知计入成本，不只保留最后改对的那一次。

复权数据是既有固定快照。完整公司行动/PIT正确性、历史数据实际可得时刻、交易所日历完整性与实际交易可行性均未建立。本报告中的日数按观测索引计算，仍不是严格交易所可行动时钟的实证结论。

## 3. 共同分母与阶段结果

新标签采用当前研究默认：收盘价、短期10/10、阶段63/42、精确同价合并间隔5、阶段附带21–126观测日的事后上涨段，未来期限H=63。它们是研究默认，尚未升级为产品最终参数。

评价范围从首次旧计划扫描日后63个观测日开始，到2018-12-31结束。每个标的、每个目标的所有策略使用完全相同LabelBook和事件范围；[12项分母检查](evidence/top-time-replay-20261106/v1/denominator_checks.csv)全部一致。

主部署范围的已知阶段事件E=91；固定lookback共同子集E=86。该子集检查峰前`[峰-H,峰)`内所有计划截点的九策略输入可用性，然后从原逐事件成绩中取子集，**没有删标签后重选下一个高点**。

此固定lookback是冻结的输入可用性诊断，并非穷尽所有可行动机会：下一观测日行动使精确的最大前视候选截点范围变为`[峰-H-1,峰-2]`，实际提前至少5日又要求不晚于`峰-6`。因此不能把共同子集写成“全部合格行动机会已经完整覆盖”。

## 5. 连续10bar不等于含端点10日

## 6. 短期结果与阶段结果分开

短期已知事件E=552，共同子集E=520。九LPPL策略短期严格TP依次为`4,1,5,5,6,6,8,10,0`（顺序同上表）；固定日历参照为120/552，但有4,236次假想通知，不能忽略负担后只比较召回。

stage漏报中，同家族在独立short探针中严格成功的数量：or4_full为2，or4_thin、cluster_any_full、cluster_cross_full、cluster_cross_thin各1，其余LPPL策略为0。固定参照为13。这些只说明两个独立定位探针的目标差异，**不是当时真的先提醒局部、随后完成阶段升级**；没有原始scope或升级发布时间能证明该行为。

3月18日局部高点应提醒、5月20日阶段重点提醒的最新产品语义不变。这轮旧预测期止于2018年，不能拿本结果声称预测了2024年两个例子；下一轮需要按独立claim首次时钟构建真正可追溯的双层提醒过程。

## 7. 未知与失败没有从分母消失

所有策略主范围均有3个阶段锚点仍不可判定：沪深300的2005-09-19、中证500的2007-05-29、创业板的2010-12-17。没有把它们当已知无事件，也没有编造三个FN。E=91是已知事件分母，不能宣传为全范围真实事件总数已完整建立。

九LPPL探针的已发主张没有待定评分；固定参照有20条阶段、4条短期待定。已发主张精确率账本可闭合与全范围召回分母完整是不同状态，原始Evaluation同时记录二者。

输入历史不足、稳定确认不足及缓存缺失保留在逐日账本与计划运行分母中。这里的`FAILED`只是评价适配器表示“此计划输入不可评价”，不是核实当年生产任务失败。旧21,168标的观测日没有被擅自扩展成后来每天实盘运行。

## 9. 验证与下一步

本轮相关测试79项通过，Ruff检查通过；机械校验核对20个输出文件哈希、原输入/执行源码前后一致、423,360行唯一ID、18,292条预测与每日账本对应、episode不重置、120组评分算术、12项同分母检查，以及每个TP的含端点宽度和理论提前条件。它们证明实现/账本一致，不证明真实预测能力。

重放约18.8秒完成；这是读取已保存聚合结果和评价的时间，不含新拟合，也不代表线上计算或逐日扫描成本。源码快照一并保存在v1，旧研究与输入没有覆盖。

下一步按可归因顺序推进：

1. **先审查首警为什么错位。** 用已输出事件账本固定抽取错首窗、11/12日边界、无claim、迟报和成功例；不按事后结果替换首条，不把大跌筛入成功定义。
2. **明确连续区间到日期的输出合同。** 若尝试新聚类约束，应在新的原始算法中直接满足含端点日期宽度，不能事后裁掉现有区间；仅改变这一项做独立消融。
3. **真实每日拟合另作增量实验。** 当前每5日缓存不能回答每天重拟合是否更早。需单列日期×窗口×预算、计算成本和假想/真实发布通道，逐日重拟合与本轮成绩分开，不能把它当已完成。
4. **建立真正前瞻发布与双层claim。** 先固定应产出、封存与实际可见时间；局部和阶段各自首次时钟，升级另计通知。只有新记录才可能建立真实提前证据。
5. **再设计预算匹配的简单时间对照。** 当前固定日历参照未匹配报警成本，不能用于宣布LPPL已有独立增量。新对照需在执行前确定，已消费的这段历史继续标开发资料。

目前应保留研究身份，不升级为已验证阶段识别或逃顶能力。是否减少漏报、是否有足够提前量和窄窗，仍需在正确记录与新证据上继续检验。
