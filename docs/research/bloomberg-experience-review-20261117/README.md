# Bloomberg 官网实测：优势、限制与 LPPL 可落地的借鉴方案

日期：2026-11-17，Asia/Singapore。方式：Windows Chrome，通过 computer-use 实际点击、搜索、切换、滚动与返回；另核对 Bloomberg Media 官方产品说明。对象是 Bloomberg.com 公开网站，不是 Bloomberg Terminal。

## 结论

**彭博最值得借鉴的是信息组织：把重要变化、支持它的图表、相关资产和背景报道放在一个阅读路径里。** 它帮助用户先建立市场背景，再决定深入研究哪个问题。对 LPPL，这套方法最适合“今日市场”和“日终复盘”；个股工作站仍应让 K 线、成交量、候选顶部区间和修订记录居于中心。

这是基于本次有限体验的设计判断，不是产品全面排名。此次没有证据证明彭博官网的图表分析优于 TradingView，也没有测试 Terminal。资讯组织得好，不等于可以提高 LPPL 预测准确率。

证据标签：

- **VERIFIED/UI**：本次桌面界面实际观察或操作成功。
- **VERIFIED/DOC**：官方文档明确描述；历史说明注明年份，不自动视为当前功能实测。
- **PROPOSED**：针对 LPPL 的建议，没有据此声称实现或验收完成。
- **NOT_INSPECTED**：未实测或受权限限制无法完成。
- **NOT_ESTABLISHED**：现有证据不能确定原因或效果。

操作路径和失败边界见 [BROWSER_LOG.md](BROWSER_LOG.md)。本报告没有把当前网站新闻或报价当作经过独立核验的金融事实，也未复制付费正文。

## 2. 优势具体在哪里

### 2.1 先确定阅读顺序，再增加内容量

**VERIFIED/UI：** 首页主新闻面积、标题字号和配图明显大于相关短讯；右侧 Latest 用更紧凑的列表承载时间顺序。它没有把所有信息压成同等权重的卡片。

**设计判断：** 用户可以先回答“今天值得关注什么”，再回答“刚刚发生什么”。重要性与新鲜度是不同维度，应分开设计。

**PROPOSED：** LPPL 市场页顶端显示 3–5 条有来源的重点变化，旁边提供“最新”“我的自选”。若重点由规则生成，说明排序依据；若为编辑选择，标记为编辑摘要。不要将新闻条数或热度转成泡沫概率。

### 2.2 图表负责解释当前问题

**VERIFIED/UI：** 首页市场主新闻旁有两条指数曲线的比较图，相关报道与多媒体入口围绕同一市场主题组织。图表处在阅读路径中，不必先离开新闻去寻找背景行情。

**设计判断：** 这种布局降低理解一个主题所需的跳转。相邻呈现只能建立内容关联，不能证明新闻导致了行情变化。

**PROPOSED：** 复盘卡采用“发生了什么 → 相关资产 → 一张支持图 → 原始来源 → 打开工作站”。股价比较必须显示周期、单位、复权和归一化口径；不能把不同量纲的曲线画在一起而省略解释。

### 2.3 导航分层，而且区分了内容类型

**VERIFIED/UI：** 顶部主要栏目包含 Markets、Finance、Economics、Industries、Tech、Politics 等；Markets 页面再细分 Deals、Fixed Income、ETFs、FX Center、Markets Wrap 等。More 成功展开为 News、Work & Life、Media、Explore、Tools、Sponsored Content 六组。

**设计判断：** 一级导航决定关注领域，栏目内部导航决定研究方向；More 再处理低频入口、媒体形式和工具。赞助内容单独分组有助于避免与编辑内容混淆。该站仍有一些混合分类，例如主题和媒体品牌并列，LPPL 不必照搬所有栏目。

**PROPOSED：** LPPL 一级保持“市场 / 工作站 / 复盘 / 研究”。市场二级是“A 股 / 全球 / 宏观 / 资讯”；工作站二级围绕“图表与区间 / 资讯事件 / 公司资料 / 资金结构 / 历史评估”。帮助与方法说明放到低频入口，AI 随当前资产和日期作为侧栏出现。

### 2.4 搜索同时识别资产与研究意图

**VERIFIED/UI：** 输入 AAPL 后，一列显示 AAPL:US、AAPL:SW、AAPL:AV 等证券结果，另一列显示相关搜索建议。点击 AAPL:US 到达 Apple 报价页。

**设计判断：** 用户可能想“打开这只股票”，也可能想“查它的新闻”。把两者分开比混在一个无类型列表里更清楚。本次没有测试搜索召回率、拼写容错或所有市场覆盖。

**PROPOSED：** LPPL 搜索结果分成资产、事件、研究三类。资产显示名称、代码、交易所、资产类别；例如“贵州茅台 / 600519 / 上交所”。选择资产打开行情和已有分析，选择事件打开证据卡，选择研究打开方法说明，不默认触发历史回测。

### 2.5 行情条是轻量背景，不占据主工作区

**VERIFIED/UI：** 行情条可由主要证券切换成利率与债券，内容在原位置更新。分类和项目放在同一水平区域。

**设计判断：** 用户能在继续阅读的同时更换市场背景。没有核验行情是否实时、每项延迟多久或分类能否跨设备保存。

**PROPOSED：** LPPL 顶部提供“A 股指数 / 全球资产 / 利率汇率 / 我的自选”，每项包含名称、数值、涨跌、数据时间。微型走势可按需加载；分类切换不触发拟合。缓存过期显示日期和原因，不用绿色指示灯代替新鲜度说明。

### 2.6 视觉强度来自排版和秩序

**VERIFIED/UI：** 本次首页和市场页主要使用黑白对比、明确的标题层级、对齐的列、细分隔线和有限强调色。行情涨跌、媒体图片和主标题承担不同的视觉任务。没有观察到必须完成装饰性开场才能使用网站的流程。

**设计判断：** 专业感来自读者知道先看哪里、哪里能点击、哪里是数据。这与“没有动效”不同；动效可以服务切换和定位。

**PROPOSED：** LPPL 使用浅色底、深色文字、低饱和辅助色；品牌色不与 A 股红涨绿跌争夺语义。正式区间、观察区间和修订同时用文字、线型和图例区分。可以测试 120–180ms 控件反馈、180–240ms 抽屉和定位过渡；这是设计候选值，不是彭博实测参数。禁止刷新时整屏闪烁或高亮每一个报价。

### 2.7 深度内容允许独立视觉，但仍有来源身份

**VERIFIED/UI：** Graphics 列表进入 SpaceX 图解专题后，白底列表切换为深色专题首屏；大幅主体照片、栏目类型、作者、日期和图片来源均可见。完整图解与滚动交互未能在订阅墙后完成，因此不能声称已测试其互动图表或滚动叙事。

**PROPOSED：** LPPL 可把“这次区间为什么修订”“多个时间尺度为什么分歧”等研究做成独立图解页面。大图、滚动聚焦和注释用于解释证据；模型版本、预测首次可见时间、样本截止日、是否历史重放应始终容易找到。

## 3. 本次实际遇到的不足

1. **VERIFIED/UI：广告占据明显首屏面积。** 此次多个栏目顶部约有 380px 高的广告占位，正文被推低。该尺寸来自桌面截图估计，未做 CSS 测量。LPPL 首屏应直接出现可用内容。
2. **VERIFIED/UI：订阅墙中断研究路径。** Apple 报价页、Markets Wrap 及图解专题受限。不能在这些页面上声称完成图表、指标、回测、全文或个人化功能验收。
3. **VERIFIED/UI，原因 NOT_ESTABLISHED：一次样式加载异常。** Markets Wrap 初次出现巨大蓝色标识与未正常排版的链接；刷新并等待后恢复。没有网络瀑布或资源错误日志，不能归因为大陆网络、脚本错误或站点长期不稳定。
4. **NOT_ESTABLISHED：Markets 箭头展开行为。** 本次多次尝试没有看到预期下拉，但点击 Markets 文本可以进入栏目；More 菜单实际展开成功。因此不能把整个导航概括为失效。
5. **NOT_INSPECTED：移动端与量化性能。** 本次为桌面 Chrome，没有完成 390px、Safari、真实手机、键盘全路径、读屏、对比度测量或 LCP/INP/CLS 测量。
6. 桌面外部通知和浏览器翻译弹窗不属于彭博界面；截图中的鼠标蓝色光晕也不是网站动效。本报告不把这些计入网站评价。

## 4. 与 TradingView 的借鉴分工

下表是面向 LPPL 的设计取舍，结合此前 TradingView 体验；不是完整产品能力排名，未重新验收 TradingView 全站。

| 用户任务 | 优先借鉴方向 | LPPL 自己必须提供的内容 |
|---|---|---|
| 先知道今天市场发生了什么 | 彭博的编辑层级、主题聚合、简报 | 数据截止日、来源、重点排序依据 |
| 研究一只股票 | TradingView 的图表中心工作流 | K 线与量、候选顶部区间、多尺度拟合摘要 |
| 理解事件与价格的对应关系 | 彭博的内容关联 + 图表定位 | 当时已知的事件时间轴，禁止补造历史 |
| 判断模型结果是否值得参考 | LPPL 自有证据账本 | 首次可见、观察/正式/修订/新提醒、历史评估 |
| 学习一个复杂概念 | 彭博 Graphics 的独立图解入口 | 自有图解、模型口径、局限及真实案例 |

## 5. 建议的页面骨架与连续操作

以下均为 **PROPOSED**，未修改业务代码。

```text
全局：品牌 | 市场 | 工作站 | 复盘 | 研究 | 资产/事件搜索 | 自选
背景：A股指数 / 全球资产 / 利率汇率 / 我的自选；来源与时点

市场页：
  左侧约 2/3：今日重点 → 支持图表 → 市场宽度/题材/资金
  右侧约 1/3：我的资产发生了什么 → 最新事件 → 即将发布

点击相关资产：
  行情先显示 → 呈现已有分析及截止日 → 当前分析异步刷新
  主区：K线、成交量、候选区间
  侧栏：摘要 / 事件证据 / 模型解释
  下方：区间修订及首次可见记录

点击历史事件：
  保留资产、周期与复盘日期 → 定位图表 → 当时可见证据
  返回时恢复原列表位置和筛选，不重新运行全历史计算
```

移动端采用同一任务顺序，行情条横向浏览、简报单列、事件侧栏变成底部抽屉；先显示资产与图表，再显示扩展资料。390px 下是否成立需要另行实测，不写为已经通过。

## 6. Devin 可执行的三项优先交付

### P0-A 今日市场摘要

- 基于已获使用权限的数据输出 3–5 条重点变化；区分“重要 / 最新 / 我的自选”。没有可靠排序时使用透明的规则排序，不能用模型随意生成确定性因果。
- 卡片字段：`headline`、`summary`、`related_asset_ids`、`source_url`、`published_at`、`fetched_at`、`asof`、`status`、`stale_reason`、`evidence_type`。保留来源修订及内容 hash。
- 先呈现缓存，再独立刷新；摘要加载失败不阻塞行情。
- 验收：来源可打开；不同时间概念不混淆；失败有重试；没有资料时明确为空；新闻热度不进入 LPPL 拟合或被称为顶部概率。

### P0-B 搜索、行情条、新闻卡统一资产入口

- 统一规范化 `asset_id` 与交易所映射；搜索中的证券、事件、研究分组。
- 路由保留资产、图表周期、复盘日期与返回上下文；行情卡、资讯卡和自选使用同一路径。
- 当前行情、当前拟合、历史回放为独立资源和任务；阅读新闻、切换行情分类不创建拟合任务。
- 验收：缓存命中先显示；后台刷新不清空 K 线；失败可恢复；打开同一资产不重复排队；用户必须主动请求历史回放。

### P1-C 事件与模型并排回放

- 分别保存 `event_time`、`published_at`、`fetched_at`、`first_visible_at` 与修订版本；它们可能不同。
- 历史重建按可获得的原始发布时间与当时数据版本筛选；真实产品回放按系统首次可见时间筛选。两者分开标识，不能把后来导入的新闻冒充当时网站已提供。
- 未来已公布的日历事件可显示为“计划”，不能把尚未发布的结果带入过去。发布时间未知的内容进入“可得性未知/事后补充”，不能默认视为当时已知。
- 事件和模型区间并排，选中事件只定位图表；不改写已封存的拟合、提醒或修订账本。
- 验收：回放日期改变时，未来信息不可见；来源修订可追溯；0–4 个交易日提前量的候选仍可查看，提前 5 日属于评估维度，不作为隐藏结果的硬门槛；结构强度、tc 区间和实际预警表现分开展示。
