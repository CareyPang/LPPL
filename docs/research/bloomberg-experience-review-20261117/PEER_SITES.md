# 其他值得借鉴的网站：按 LPPL 用户任务选择

核验日期：2026-11-17。本文件使用官方产品页、帮助页和更新记录；**VERIFIED/DOC 表示官方资料支持其功能描述，不表示已经登录或通过 computer-use 完整验收**。具体改造建议均为 **PROPOSED**。

这里推荐的是进一步体验与设计研究对象，不是购买建议。官网可浏览、个人订阅可使用、API 可访问、数据可保存和可向第三方展示是不同权限；本轮没有将其中任何一项推定为另一项。大陆直连、A 股具体覆盖、免费配额与完整账户流程均未实测。

## 优先级与分工

| 顺序 | 网站 | 最值得借鉴的部分 | LPPL 对应交付 |
|---|---|---|---|
| 1 | Koyfin | 自选列表、可复用列视图、可组合面板 | 普通投资者每天打开的个人市场桌面 |
| 2 | Fiscal.ai（原 FinChat） | 公司研究、财务结构、AI 与来源材料连接 | 有证据的个股 AI 问答，而非独立聊天框 |
| 3 | FINVIZ | 热力图、筛选器与指标视图 | A 股行业/概念/地域浏览与筛选 |
| 4 | Trading Economics | 经济日历、指标历史与修订口径 | 宏观事件日历与状态卡 |
| 5 | Quartr | 公司事件、录音/逐字稿/材料的关联研究 | 公告、业绩说明会、原文证据回放 |
| 6 | 金十数据 | 中文快讯、日期/国家/重要性筛选 | 面向大陆用户的快讯与宏观阅读习惯 |

顺序依据当前 LPPL 的工作站、AI、市场背景和事件回放需求，不是综合质量排名。若下一轮只实测两个，优先 Koyfin 与 Fiscal.ai；图表操作已经有 TradingView 对照，不必再寻找多个相似图表站。

## 1. Koyfin：把自选股做成可复用的研究入口

**VERIFIED/DOC：** 官方功能页描述市场面板、自选列表、筛选与自定义面板；自选帮助说明可配置列、分组、汇总行和视图，视图可用于面板中的列表组件。

**建议实际体验路径：** 建立自选 → 设置列和分组 → 在面板中复用视图 → 从某个资产打开图表和相关资讯 → 返回列表。重点检查上下文是否保留、密集数据是否易读，而非只看漂亮截图。

**PROPOSED：** LPPL 首先提供三种固定模板：“我的自选”“今日复盘”“宏观背景”。自选列包含报价截止日、候选顶部区间、结构强度、上次分析、数据状态；用户可隐藏列和排序。先给出好用的默认值，后续再做任意拖拽，避免第一版的配置负担。

**边界：** 官方页面不能证明我们的 A 股资产覆盖或数据时效；没有测试同步、提醒送达或跨设备保存。可借鉴操作逻辑，不搬用商业数据。

来源：[功能概览](https://www.koyfin.com/features/)、[自选功能](https://www.koyfin.com/features/watchlists/)、[视图帮助](https://www.koyfin.com/help/my-views/)。

## 2. Fiscal.ai：AI 围绕公司与数据工作

**VERIFIED/DOC：** 官方宣布 FinChat 更名为 Fiscal.ai。其产品说明和更新记录支持公司研究、财务、业务分部/KPI、图表、财报日历与 AI 数据服务；官方强调数字可追溯到来源文件。2026-10-30 更新记录介绍 Markets 页面及财报事件抽屉；这是官方发布记录，不是本轮 UI 实测。

**建议实际体验路径：** 选择公司 → 查看财务指标/分部 → 提问某指标变化 → 打开来源材料 → 保持公司上下文返回图表。重点验证引用是否真正支持回答、单位和报告期是否一致。

**PROPOSED：** LPPL AI 侧栏继承 `asset_id`、`asof`、当前区间和模型版本；提供“本次区间为什么变了”“哪个尺度支持它”“有什么相关公告”等入口。回答按事实、模型输出、解释、缺失证据分开，引用必须可点击定位。AI 不替换拟合、不重新计算未经定义的概率，不从新闻情绪直接宣布顶部。

**边界：** 官方准确性与速度宣传不视为独立验证；网站产品与 API/MCP 为不同订阅/访问范围，不能假设网页账号允许后端转供数据。大陆网络和 A 股具体支持仍需查验。

来源：[更名公告](https://fiscal.ai/blog/series-a-announcement/)、[产品首页](https://fiscal.ai/)、[更新记录](https://fiscal.ai/changelog/)、[帮助与访问范围](https://fiscal.ai/help/)、[来源可追溯设计说明](https://fiscal.ai/blog/fiscal-ai-launches-an-mcp-connector-for-microsoft-copilot/)。

## 3. FINVIZ：让市场扫描与筛选共享一套条件

**VERIFIED/DOC：** 官方页面提供 Stock Screener、ETF Screener、Maps、Groups 等入口；官方更新说明支持在筛选器和 Maps 使用不同的表现、估值及财务指标。支持页当前明确提示报价存在延迟，不能把免费展示一律写成实时。

**建议实际体验路径：** 看市场热力图 → 切换颜色指标/周期 → 缩小到某行业 → 在表格中进一步筛选 → 进入个股。需要后续 UI 核验这些状态如何衔接；本轮未宣称全部步骤已完成。

**PROPOSED：** LPPL 的热力图与列表共享筛选状态，行业/概念/地域是分组维度，面积与颜色分别显示明确口径。概念股存在多重归属，汇总时要声明去重与分母；涨跌幅不能与 LPPL 结构强度共用同一个无说明图例。点击股票复用统一资产入口。

**边界：** 主要借鉴市场扫描方式，不能当作完整 A 股数据供应商；动态图表的全部功能、会员差异和实际刷新频率未验收。

来源：[Maps 入口](https://finviz.com/map)、[筛选/热力图指标更新](https://finviz.com/blog/expanded-metrics-in-screener-maps/)、[支持页与延迟提示](https://finviz.com/knowledge-base/support)。

## 4. Trading Economics：把经济数据的不同含义分开

**VERIFIED/DOC：** 官方日历区分实际值、前值、调查共识与其自有预测，并说明修订前值的标记和事件重要性。

**建议实际体验路径：** 日期与国家筛选 → 事件详情 → 历史序列 → 前值修订 → 返回日历。重点检查时区、单位、公布前后状态和日历历史是否能追溯。

**PROPOSED：** LPPL 宏观卡同样分开显示“尚未公布 / 已公布 / 已修订 / 延迟”。共识与模型预测不能合并为一个“预测值”；没有授权的共识数据就保留缺失。历史回放保存首次公布值与后续修订值，不以今天的修订值冒充当时已知数据。

**边界：** 日历可浏览不代表 API、历史留存及网站展示授权已经具备。这里借鉴字段与交互；数据继续按 LPPL 已确认的官方来源和许可逐源接入。

来源：[官方经济日历及方法说明](https://tradingeconomics.com/calendar)。

## 5. Quartr：事件研究的价值在于能回到原文

**VERIFIED/DOC：** 官方功能页描述公司事件日历、电话会、逐字稿检索、材料并排和按需回放；支持从逐字稿位置定位音频。移动产品说明强调 AI 回答与原始材料连接。

**建议实际体验路径：** 公司 → 一次业绩事件 → 搜索某个关键词 → 定位说话人和原文 → 对照幻灯片 → 回看上一期。比“自动生成一大段总结”更应验证的是定位能力与时间一致性。

**PROPOSED：** LPPL 先做公告/报告原文定位和跨期比较。A 股缺少电话会材料时使用已授权的公告与业绩说明会记录，不补造逐字稿。AI 引用保留报告期、发布日期、页码/段落、来源及版本；后续才考虑音频同步，且不自动播放。

**边界：** 不将其全球覆盖数字推定为某只 A 股的完整覆盖；网页、移动、Pro 与 API 范围不同。未体验账户、完整回放或延迟。

来源：[事件与逐字稿功能](https://quartr.com/features/live-calls-and-transcripts)、[功能目录](https://quartr.com/features)、[移动研究产品](https://quartr.com/products/mobile-app)。

## 6. 金十数据：中文快讯与日历的阅读习惯

**VERIFIED/DOC：** 官方介绍页描述分市场快讯，以及按日期、国家、重要程度筛选的财经日历，日历包含前值、预测值与公布值。该介绍页包含历史产品内容，不能由此断言 2026 年所有入口、速度和功能细节仍与描述完全一致。

**建议实际体验路径：** 快讯筛选 → 某事件 → 相关日历 → 数据详情 → 返回原阅读位置。重点查看怎样突出重要信息而不使整屏都变成警报。

**PROPOSED：** LPPL 中文快讯提供“全部 / 自选相关 / 宏观 / A 股”，保留精确时间、来源、修订与阅读位置。新消息用计数提示，不强制把正在读历史内容的用户滚回顶部。来源称“利多/利空”时显示为该来源解释，不自动当作事实或模型结论。

**边界：** 快讯内容与数据再展示需要单独核验，不能默认允许转载；本次没有确认免费 API、实时保证或当前大陆网络性能。未经许可不因存在第三方 skill 就直接采集转供。

来源：[官方产品介绍](https://www.jin10.com/about/introduce.html)、[官方产品入口](https://i.jin10.com/)。

## 下一轮实测的统一比较题

对 Koyfin、Fiscal.ai 优先各做同一条用户路径，避免只比较首页截图：

1. 输入一只明确市场的股票，确认歧义如何处理。
2. 未完成分析时能否先读行情与已有结果。
3. 从自选进入股票，再看事件、数据和来源，返回是否保留位置。
4. 数据过期、付费限制、加载失败、空结果如何说明。
5. 390px 下图表、表格、AI 面板和来源是否仍可操作。
6. 记录实际点击、截图与限制，不把官方宣传写为实测通过。

这组研究的交付是 LPPL 的任务组织、交互与证据规范；不会把所有竞品功能一次性塞进首页，也不改变 LPPL 拟合和评分口径。
