## 1. 需求合同与本文边界

| 项目 | 已确认的含义 | 评价约束 |
|---|---|---|
| 核心预测对象 | 顶部出现的时间区间 | 主成功条件不包含随后下跌多少 |
| 两类顶部 | 几周内的短期局部高点也需要；1–6个月上涨的阶段性高点重点提醒 | 阶段层为主指标，短期层为次指标；同一高点允许两标签 |
| 使用场景 | 普通投资者，通常持有1–6个月 | 持有期、历史拟合长度、标签结构尺度、预测前视期限分别定义 |
| 提前性 | 至少提前5个交易日 | 从真实可行动时点计算，不能从拟合截止日或补算日期计算 |
| 时间精度 | 窗口最好不超过10个交易日 | 同时报告覆盖与拒报；不为达标强制裁窄 |
| 取舍 | 偏少漏报 | 在预先固定的提醒负担下比较事件召回；误报和拒报不能隐藏 |
| LPPL研究起点 | 完整周期数至少1.5的研究基线 | 不是最优门槛结论，也不是已成立的顶部预测能力 |
| 不属于本次成功定义 | 随后跌10%、最低价格、回撤幅度或交易盈利 | 可以另列描述或独立价格层研究，不回流主标签 |

过去“顶后一定期限跌10%”的设想不再是本协议主目标。既有幅度过滤标签、分段终点加一交易日代理及旧研究结果保留原身份，不能更名为本协议真实高点，也不能用旧命中率作为新标签的成绩。

本文提出的是可证伪的**操作性标签候选**，不是宣称市场存在唯一正确的顶部定义。标签语义与数字冻结后才能生成正式评价数据。即使时间标签命中，产品也不保证随后一定下跌、下跌幅度或减仓获利。

## 2. 四个时间尺度不得互相替代

| 时间概念 | 含义 | 草案中的处理 |
|---|---|---|
| 投资者持有期 | 用户通常持有多久 | 已确认1–6个月；不直接成为标签公式 |
| LPPL历史拟合窗 | 模型读取多少过去数据 | 保存实际首末交易日与观测数；旧研究档位可作候选 |
| 高点结构尺度 | 多长邻域内的相对高点 | 短期与阶段两组`L/R`，见第3节 |
| 未来预测期限 | 提醒最多向前覆盖多远 | `H`独立登记，不能由历史窗的月份名称推断 |

供语义审阅的默认候选：短期层`L=10,R=10`，阶段层`L=63,R=21`，两层合并间隔`G=5`，预测最大前视`H=63`，均为交易日。两层暂用相同`H`便于对照；这不表示63日是已证明的最佳前视期限。5日提前目标与10日窄窗目标来自用户，其余数字均为研究建议。

`L=63,R=21`只定义一个特定邻域的结构性高点，**不自动证明前面有完整1–6个月上涨阶段，更不证明该上涨周期永久结束**。持续上涨语义必须另行审阅，见第4节。不得在结果不佳后把阶段层改称“仅大泡沫顶”，或用短期层成绩替代阶段层。

## 3. 幅度无关的双尺度标签候选

### 3.1 价格、日历和输入版本

预设候选为日频、拆股连续化收盘价`p_i`；收盘价与盘中最高价是两个不同目标，不能择优混用。分红按价格口径还是财富收益口径处理，须在冻结表中确定；没有完整、可重建的公司行动口径时标为`PRICE_BASIS_UNRESOLVED`。本草案未核验现有数据是否满足这些要求。

`i`表示预先指定交易所的交易日序号，不把个股停牌日从交易所日历删掉后压缩提前量。价格缺失、停牌、无有效成交和公司行动异常单列。主标签所需区段存在无法解释的缺失时，标记不可判定；不前向填充价格制造平顶。另表给出不可判定区段和涉及的资产交易日。

精确相等使用冻结数据中的规范十进制价格表示或明确的整数报价单位比较。不得以“相差不到1%”“波动率若干倍”或浮点`epsilon`把近价自动并成平顶。只为实现数值编码而采用的精度规则必须与原始报价精度一致并登记，不能成为隐藏幅度门槛。

### 3.2 点候选：固定邻域极大值

对每层`s∈{short,stage}`，预先固定`L_s,R_s`。在完整可判定邻域内定义：

```text
candidate_s(i) = 1  iff  p_i = max{p_j: i-L_s <= j <= i+R_s}.
```

该规则只有时间跨度与价格顺序，不要求之后下跌10%，不要求最小回撤、最小突出度、最小振幅或达到某个波动倍数。上下文中的任意严格更高价格都会否定该点，不因它只高一点就忽略。

此标签必然使用未来`R_s`日，**未来部分只用于事后标注**。`candidate_s(i)`不能在第`i`日被当作已知特征、选股条件或训练标签。把标签事后可识别与模型当时可预测区分开，是整个协议的基本要求。

### 3.3 平顶与重复同价高点：仅按时间合并

为避免连续同价日被算成多次顶部，按以下固定算法处理每层候选：

1. 将候选点按交易日排序。
2. 仅当相邻候选点的价格精确相同、日期间隔不超过`G`，且两者之间没有更高价格时，把它们连接；对连接关系取连续分组。
3. 每组产生一个事件，`plateau_start=u`、`plateau_end=v`；`peak_at=u`取最早候选日，`peak_price=p_u`。`G=5<=min(L_s,R_s)`为本草案候选约束。
4. 不同价格的峰不能用相对幅度容差合并。相同高度但间隔超过`G`的候选保留为不同事件；这种双顶如何计数属于已公开的定义，而非看结果后决定。
5. 分组外的左邻域`[u-L_s,u-1]`与右邻域`[v+1,v+R_s]`各须至少有一个严格较低的有效价格，才形成闭合高点；全平、左端已处于同价平台或没有可见转折的一侧标记未识别/边界状态，不虚构高点。这里仅检查方向，任意小的价差都有效，不设最小幅度。
6. 连续平顶可以超过10日。不能把长平顶裁成10日后宣称预测精确；另外报告平顶长度和长平顶比例。

主命中要求区间包含`u`，提前量也相对`u`计算。这是保守约定，防止模型在平顶中段才报警却按平顶末日获得提前性。区间与`[u,v]`任意相交只能作为明确标记的宽松敏感性结果，不能替代主成绩。

平顶候选分组可能随新数据延长，因此不能在看到第一个同价日时冻结事件。只有分组闭合且全部候选成熟时才发布最终标签；第3.4节给出可审计界限。

### 3.4 成熟、边界和标签可用时间

每个候选点`i`要等`i+R_s`及以前的数据全部可用后才能确定。若当前截点为`T`，只对`i<=T-R_s`计算已成熟候选，再执行分组。一个候选分组`[u,v]`只有在`T>=v+G+R_s`时才关闭：这样所有可能在`v`之后`G`日内接入的新候选都已可判断。

```text
event_label_available_at
  = 该事件及其闭合检查全部依赖数据均已可得的最早时刻.
label_support_end = v + G + R_s.
```

`label_available_at`表示因果上最早可知时间，不早于`label_support_end`的有效行情可用时刻；实际标签计算完成另记`label_computed_at`。真实运行中的训练还须等计算完成；历史回放可在模拟截止时点用当时已可得依赖重建标签，但必须记录实际回放时间，不能冒充当年真的发布过标签或预测。`u-L_s`之前历史不足为左截断；右邻域、合并闭合区或后续行情未到为右截断/未成熟。无法判定不是无事件；未来补齐后追加新版本，保留原状态。

连续极长的同价平台可能长期不能闭合。此时保持`PENDING_PLATEAU`，不能用最后一个已知候选强行结案。报告挂起事件数及最长等待时间；不能只公布较容易成熟的事件成绩。

没有事件的区段也要经过完整右邻域与合并闭合检查，才能形成成熟负例。涉及候选分组链延长时，必须等所有可能影响该区段代表日的分组闭合；不能一律用`区段末日+R+G`自动结案。不能把“目前尚未标出顶”当成“已经确认没有顶”。

### 3.5 两层可以重合，不能强行互斥

在本文默认候选下，阶段极大值的邻域包含短期邻域，阶段候选通常也满足短期候选；经过分别分组后，两个事件的代表日不保证完全一致。因此保存**两套原始事件账本**，不以层级名替换任何一套标签。

跨层关联使用相同规范价格且候选日期集合有交集的关系建立`event_family_id`。如果一个短期分组关联多个阶段分组或相反，保留完整关联表并标记歧义，不自行选最有利配对。没有此关系的邻近事件不因日期接近就自动合并。

输出标签向量可以是`{short:true, stage:true}`；“两者都是”是允许结果。`short_only`表示有短期标签而无阶段标签；“阶段”不是对“短期”的否定。总事件数量按事件家族去重，并同时给出每层原始计数，不能把两层命中数相加制造总成功数。

## 4. “1–6个月上涨阶段”必须额外校验

固定邻域极大值具有可复现性，但不足以完整表达投资者说的“上涨阶段结束”。在冻结前建立不查看LPPL输出的标签例集，覆盖：持续上涨后的横盘、双顶、长平顶、缓慢回落、V形回落、震荡区间、长期上涨中的小高点、除权和停牌。由语义审阅决定下列两个候选哪个可以担当阶段主标签；不能看模型命中率选择。

| 候选 | 定义与用途 | 限制 |
|---|---|---|
| `STAGE-STRUCTURE`，本文默认审阅候选 | 第3节的阶段`L/R`极大值 | 可作为“阶段尺度结构高点”；不能直接叫完整上涨阶段终点 |
| `STAGE-RISE`，备选操作性候选 | 先用相同极值方法生成低点（将max换min，候选`L=R=21`），选在峰前21–126交易日内最近一个已成熟低点分组的末日`a`；要求`p_u>p_a`且`(a,u]`没有低于`p_a`的价格。事件仍须满足阶段极大值 | 只表达有指定时间跨度、净向上的谷峰段；容许中途波动，不证明上涨机制或周期永久结束；可能排除较长牛市中的有用高点 |

`STAGE-RISE`中“已成熟”的判定截点固定为候选峰`u`的收盘行情可用时间：候选低点事件必须满足`label_available_at<=peak_close_available_at(u)`，再从这些低点中选最近一个。保留这一截点、可选低点清单及所选`a`；不得随着最终评价日期向后推移，改选在峰后才成熟的新低点。如果峰日收盘或低点依赖数据的真实可得时间不明，标记`RISE_AVAILABILITY_NOT_ESTABLISHED`，该附加上涨阶段语义不成立，不能假定当时已知。

`STAGE-RISE`中的正向比较只确定方向，不设最小涨幅。必须记录`rise_start=a, rise_duration=u-a`、无候选谷、谷在固定截点尚未成熟、区间缺失等原因。若作为主标签，整个谷识别及匹配算法一并版本化，成熟时间取峰和谷两部分所需数据的较晚者。

**推荐冻结路径：**先以`STAGE-STRUCTURE`生成纯标签审阅样例；同时附`STAGE-RISE`分组用于核对1–6个月上涨语义。若用户语义只能由第二种满足，就在任何模型评分前把它冻结为主目标。未经这一步，阶段高点能力仍为`TARGET_SEMANTICS_NOT_FROZEN`，不能对外承诺已会区分上涨阶段。

定义不会因随后只小幅回落就事后删除事件。后续涨跌及回撤可以分层描述；不得借“有效顶部”“实用顶部”等名称偷偷恢复幅度过滤。

## 5. 预测必须是当时可见、完整处于未来的区间

每次正式输出`I=[l,r]`使用交易日日期映射，宽度包含两端：

```text
width_td = index(r) - index(l) + 1.
```

同一天的区间宽度是1日，不是0日。连续模型参数映射成交易日区间的规则需冻结；候选规则为下端向外取整、上端向外取整，之后再计算含端点宽度。禁止先按连续差值`<=10`入选，再把包含11个交易日的区间叫10日窄窗。

对数据截止时点`d`、实际可见时刻`published_at`和首个可行动交易日`a`：

- LPPL预测任务中的所有临界点必须满足严格未来域`tc>d`；窗口内部或过去的`tc`只属描述性拟合。
- 发布的时间区间应在当时仍然全部未来：`l>a`且`r<=a+H`。主严格提醒额外要求`l>=a+5`，使整个显示区间都符合至少5交易日提前的承诺。
- 如果原始拟合支持跨越过去、太近、太宽、过远或多峰，则输出相应状态及原始诊断。不能删除不方便的成员、移动端点或改用别的簇来制造合格窄窗。
- 允许宽区间或“有关注、暂无合格顶部区间”；它们单独计分，不进入严格窄窗的成功分子。所有拒绝严格输出仍保留在服务与事件覆盖分母。

这里的严格提醒条件是用于评价用户目标的协议候选，不是宣称所有模型输出都必须被强制压成窄窗。用于候选筛选的`tc`前视距离也不能代替真实事件的实际提前量。

## 6. 实际可行动时点与5日提前量

`first_actionable_at`由实际可见时刻、交易时段、停牌和预先规定的交易限制共同确定，不能只取`asof+1`。日线收盘后发布的提醒，最早通常从下一可交易时段起算；迟到发布、次日停牌或相关动作无法执行时要顺延，并保留原因。

默认评价动作是“已有持仓者可以采取减仓动作的最早时点”，不是假设所有人按预测日收盘成交。是否可成交的判断规则、报价可用性和限制条件须在数据合同中明确；不能由实际结果反推当时能否成交。尚无这些数据时，同时报告理论下个交易日与`ACTIONABILITY_NOT_ESTABLISHED`，不能声称真实可行动提前性已通过。

对事件起点`u`：

```text
action_lead_td = index(u) - index(first_actionable_session).
strict_timing_hit = 原始区间包含u
                    AND action_lead_td >= 5
                    AND width_td <= 10
                    AND 预测时已满足未来域、期限、记录与层级条件.
```

这是日期序号差约定：行动日在第1日、事件起点在第6日，提前量为5；可行动后到顶部日之前有第1–5日五个交易日机会。不得一处用日期差、另一处用含端点天数。

`u-a=4`即使`tc-d>=6`也失败。已发生的高点不能作为新提醒命中。盘中高点与收盘高点若使用不同目标时间，需要分别建标签，不能用日内最高价时间为收盘标签补提前量。

## 7. 首次提醒、修订与一对一计分

### 7.1 先冻结用户实际看到的提醒单位

每个正式提醒必须有稳定`episode_id`与不可覆盖的首条预测。每日刷新同一提醒、改时间窗、改层级、取消、重发均追加记录并关联原记录。本文默认：一个资产、同一提醒通道仅有一个活动episode；其主评价到期日取**首条区间结束日**，不得因后续改期不断延长。

新episode的重启条件与冷却时间必须先冻结，不能等看到顶部后再决定哪些记录合并。建议冷却时间作为明示参数；未冻结前不得计算可宣传的“首次提醒成功率”。取消不能删除原始预测或把它从精确率分母移走。

宽泛关注、首次给出时间区间、首次给出合格窄区间分别记录。一个月前说“注意风险”，临顶才给窄区间，不能把前者日期借给后者计算5日提前。主窄窗成绩以第一次正式发布区间的原始快照计分；后续收窄、延期或改等级均不修复首条成绩。

### 7.2 默认匹配语义：下一个目标高点

为了避免从预测窗口中挑最容易命中的高点，本草案建议把每层预测对象写为：**从可行动日之后到`H`日以内，下一个该层级结构高点**。这项语义须与目标标签共同冻结。

对每个episode的首条记录及每个声称预测的层级：

1. 仅依据事件账本和固定期限，在`(a,a+H]`选择该层级最早事件`e`；不读取所报区间来选事件。不存在成熟事件则为`NO_EVENT_IN_HORIZON`；尚不能确认不存在时为`PENDING`。
2. 若多个episode指向同一事件，最早实际可见的那一条为该事件的首警；同时间用稳定`prediction_id`排序。后续episode记重复提醒，不能再获得独立真阳性。
3. 首警必须同时满足区间包含事件`u`、实际提前至少5日、宽度不超过10日及正确层级，才获得主命中。第一次区间错了，后来改对，主成绩仍为未命中；另列“修订后命中”描述。
4. 同一首条预测在同一层最多配一个事件，同一事件在同一层最多配一个主成功。`H`内两个事件不能被一条宽区间算两次。
5. 该层有事件却没有首警为漏报；有首警但太迟、太宽、错窗、错层、不可行动或证据无效分别记原因。原因允许多选，并提供一个冻结的互斥主原因优先序用于汇总。

这种“下一个高点”定义会惩罚预测远处高点但遗漏期间较早同层高点的情况，这是公开的目标选择，不是统计修正。若语义审阅决定要预测指定阶段的最终高点，须另立目标及阶段识别规则，不能在评分时偷偷改成“窗口内任何顶都算对”。

默认精确率的分母含所有已成熟episode首条层级主张，包括重复提醒；只有每事件最早一条可能取得主真阳性。重复提醒因此既不能刷召回，也会增加提醒负担。修订版本另表统计，不重复扩大episode分母。

两层各自计分时，一个预测可在两个层中分别核对；总体用户通知数与总体事件家族数不得相加。比较层级的指标还要在同一事件家族或预先确定的关联表上计算，避免重合标签被当成两个独立成功。

## 8. 双尺度判别成绩单

系统可以输出`short`、`stage`、`both`、`scale_uncertain`，也可以拒绝给出时间区间。两层不是互斥分类，因此不以单一二分类准确率评价。

必须同时公布两种成绩：

- **端到端联合成绩：** 时间、提前量、宽度、层级一起满足才命中；未匹配、拒判、错窗和过度升级都留在分母。
- **条件层级诊断：** 仅在时间已匹配的事件家族中观察等级判断；明确这部分排除了时间失败，不能把它写成全样本区分能力。

| 指标 | 必须说明的分母 |
|---|---|
| 阶段层联合召回，主指标 | 所有范围内、成熟且标签可判定的阶段事件；含未出信号、拒判和运行失败涉及的事件 |
| 短期层联合召回，次指标 | 对应全部短期事件；不替代阶段主指标 |
| 阶段主张精确率 | 所有成熟episode中带`stage`主张的首条记录；重复主张不额外取得真阳性 |
| 过度升级率 | 声称阶段且时间匹配的事件中，真实只有短期标签的比例；另给其占全部阶段主张的比例 |
| 阶段低估率 | 真实阶段事件中只给短期主张的比例；同时分解时间命中与时间未命中 |
| 层级拒判率 | 所有有时间区间的正式episode中`scale_uncertain`的比例；全体应产出项中的拒判率也列 |
| 两层重合率 | 同时有两层标签的事件家族/全部可判定事件家族；报告原始两层计数与关联歧义 |
| 层级混淆表 | 行为真实`short_only/both/stage_only/无事件/未成熟或不可判定`，列为预测`short/stage/both/scale_uncertain/无输出`；不把未知合并成负例 |

“各尺度都支持同一区间”可以是候选特征，不能直接定义真实层级，也不能直接写成顶部概率。高度重叠的历史窗口、多次随机种子和相邻日期不是独立投票。

## 9. 主指标、漏报、拒报与覆盖

主目标建议为：在冻结的提醒数量及警报占用预算内，提高**阶段层严格首警召回**。少漏报不等于无限报警；所有策略要在同样的用户负担下比较，且预算在独立评价前固定。

| 统计量 | 定义/必须保留的边界 |
|---|---|
| 严格首警召回 | 主成功事件数/全部成熟可判定范围内事件数；按阶段、短期分别报告 |
| 漏报率 | 1−严格首警召回；拆为无信号、拒报、错窗、迟报、宽窗、错级、不可行动、数据/运行失败 |
| 严格精确率 | 一对一主成功数/全部已成熟episode主张数；重复提醒留分母，无提醒时为NA而非100% |
| 区间包含率 | 原始区间包含相应目标事件的比例；分别以事件与所有episode为分母，并注明是否附加5日/10日条件 |
| 提前量与宽度 | 全部输出与成功子集分别给分布；不能只报命中样本中位数 |
| 严格输出率/拒报率 | 全体计划应产出的资产×截点中，输出合格区间/主动拒绝的比例；失败另列 |
| 数据覆盖 | 有足够、可判定数据的计划项/全部范围内计划项 |
| 按时运行覆盖 | 按时生成并封存状态的计划项/全部范围内计划项；无信号也是有效状态，漏跑不是 |
| 提醒负担 | 每资产年episode数、每次用户通知数、重复数、活动警报日占比、预测区间覆盖交易日的并集占比 |
| 未成熟率 | 当前不可评分的事件、episode和计划项，分别列数量与等待长度 |

事件召回要给**部署范围口径**及**算法共同可评价口径**两张表。前者保留运行失败造成的漏报；后者仅用于模型配对比较，并公开从前者排除了多少事件及原因。算法自身的可服务范围单列，不能用更窄的自身分母掩盖覆盖损失。

标签无法判定的缺失区间不能假装已知有/无高点。提供观测到的事件召回、未知区段规模及无法完成全范围裁定的状态；不可把无法观察的真实事件计数凭空补成零。缺失达到事前容忍上限时，整体结论为证据不足。

## 10. 提醒后继续上涨怎样评价

首警发出后价格继续上涨，不自动使时间预测失败；顶部本就可能在未来区间。若最终相应高点在原始区间内、满足5日和10日条件，时间项可以成功。但提醒可能让投资者过早减仓，必须独立揭示代价。

对全部有可用价格的episode，使用同一首个可行动价格起算，报告到预测到期及固定期限的上涨机会、最大不利变化、到目标峰的涨幅、等待交易日数。可使用价格收益幅度作这些**结果描述**，不得反过来删除小回落事件或筛选主命中。

至少区分：先上涨后在窗内出现目标顶；先上涨但目标顶在窗外；持续上涨且期限内无目标顶；已处于下降后迟报；平顶中段才报。每类保留原预测与价格路径，不只展示漂亮个例。

“减少损失”“适合减仓”“收益提高”需要另一个冻结的动作、仓位、再进入、费用及未成交协议。时间层过关不能代替动作层过关；本协议不生成买卖收益承诺。

## 11. 简单时间参照与LPPL独立增量

先建立能够输出同样区间、遵守相同未来域及同样提醒预算的参照，才能判断LPPL有没有增量。

| 对照 | 固定规则与作用 |
|---|---|
| `B0-NONE` | 从不报警；揭示高“无事日准确率”没有价值，召回为0 |
| `B1-CALENDAR` | 用固定seed及过去数据预定的日期抽样发窗；窗口宽度、前视分布、episode预算与候选匹配，不能看未来事件抽日 |
| `B2-EMPIRICAL-TIME` | 只用训练截止前成熟事件估计等待时间分布，按冻结映射给未来区间；不得用“距未来真实顶多久”作输入 |
| `B3-SIMPLE` | 有限、预登记的价格顺序/新高年龄/趋势持续时间等简单变量，加同一时间分布与区间映射；参数在训练/校准段确定 |
| `L0-LPPL-1.5` | 严格未来域、规范完整周期>=1.5、冻结窗口/过滤/聚合的LPPL研究基线 |
| `L1-INCREMENT` | 在最强简单时间参照上增加LPPL信息；或以同预算做配对比较，单独识别LPPL增量 |
| `L2-MULTISCALE` | 仅在L0基础上改变跨尺度聚合；短窗、长窗、尺度平衡、跨日稳定分别消融 |

未经校准的拟合支持度不能写成事件概率；`tc`分布不是自动校准的真实峰日分布。拟合更好、SSE更低、优化更快、簇更窄只属于数值/工程性质，不替代真实顶部指标。

一窗一份信息单位；同窗口多seed用于数值稳定性，不重复投票。原始尝试、失败、过滤、合格窗口、尺度来源、主簇和未选簇全部留账。主簇选择不能看未来标签，不可事后选择更接近顶部的第二簇。

完整周期字段按已核对口径使用：`N_cycles = omega/(2*pi)*log((tc-t1)/(tc-t2))`，仅严格未来域适用。1.5是用户选定研究基线，不在新独立样本中重新遍历1.0/1.5/2.0/2.5再只报最佳门槛。历史单位修复和已有拟合研究见第17节。

## 12. 无泄漏、独立评价与统计裁定

1. 先冻结资产资格、历史范围、数据与公司行动版本、可用时间、事件定义、模型候选、预算、主指标及匹配算法。资产资格使用当时可得规则；当前仍上市名单不构成历史资格证明。
2. 建立已消费数据台账。旧开发、旧校准、旧终测及看过的个例都不能因新标签或新标题恢复成独立样本；可用于定义诊断和代码核对，并保留其已消费状态。
3. 标签与模型分开。标签语义审阅不看预测；预测只能读取`data_available_at<=cutoff`的数据。未来`R`窗、平顶闭合、未来低点及真实层级不得进入实时特征。
4. 训练仅接纳`label_available_at<=training_cutoff`的标签；不仅核对`peak_at`。负例与无事件episode同样必须成熟。
5. 时间拆分时按实际信息支持区间清除跨界样本。对每条训练例登记预测特征起止、目标期限、事件右窗和合并闭合范围；只靠固定几天embargo不能替代逐例依赖审计。
6. 开发、校准与独立评价隔离。阈值、宽度、层级映射、重启/冷却、提前期限与预算均在独立评价前固定；独立成绩不回流调参。新增候选需要新版本与新证据。
7. 独立评价主候选原则上只设一组；如果多候选共同参赛，事前控制多重比较。所有尝试与失败登记，并不能单独替代多重比较控制。
8. 先按最小有意义增益与所需精度估算事件量。报告阶段事件数、独立市场时期数、资产数、事件家族数与有效观察长度，不把窗口数量当样本量。
9. 不确定性采用预先冻结的时间块/市场共同冲击重采样或其他能保留相关性的方案。相关股票、重叠窗口和同一市场冲击不能当成相互独立事件。重采样需在完整账本上重新执行匹配，不能仅对筛出的命中样本抽样。
10. 固定评价终止规则。定期看运行质量可行；反复偷看效果、显著即停会改变检验含义。预定成熟截点前只展示积累进度与质量，或另立顺序检验方案。

若没有真正独立历史样本，则结果只能作为开发性证据；冻结后转入真实前瞻记录，不能给旧历史重算结果补写“当时已预测”。本协议不假定现有数据足以支持独立测试。

## 13. 前瞻运行必须先有“应产出”分母

前瞻开始前封存资产×交易日截点清单、时区、数据截止时间、最迟发布时间、模型版本和正式预测通道。按需查询/临时试算使用不同记录类型，不得挑结果好的查询加入正式成绩。

每个计划项必须恰有一个最终运行状态，并可关联多条追加式状态更新：

`ON_TIME_INTERVAL / ON_TIME_NO_SIGNAL / ON_TIME_ABSTAIN / HISTORY_INSUFFICIENT / DATA_LATE / DATA_INVALID / COMPUTE_FAILED / TIMED_OUT / MISSED_RUN / LATE_RESULT / OUT_OF_SCOPE`。

`OUT_OF_SCOPE`必须由事先资格规则判定；不能事后因效果差把范围内资产改成范围外。全部范围内应产出项是服务分母；失败、漏跑、迟到与补算都留账。正式范围之外的用户查询另表统计，不挤进模型成功分母。

分别记录数据截止、计算完成、服务接收封存、实际可见和可行动时间。内容哈希、源码/配置/输入身份及追加日志可帮助复核，但本地文件mtime或自行填写时间不能独立证明预测提前存在。运行前确定封存接收与独立复核机制；未实现时证据状态为`PUBLICATION_TIME_NOT_VERIFIED`。

标签后来成熟时追加评估记录并指向原预测，不能覆盖原区间。失败后补算只能标`LATE_RESULT`，不得补成按时提醒。数据修订需要保留旧快照与重评版本，并同时报告当时数据下的成绩与修订影响。

## 15. 执行阶段、验收与失败裁定

| 阶段 | 交付物 | 允许进入下一步的条件 |
|---|---|---|
| A 语义冻结 | 双尺度定义、无幅度阈值审计、标签例集、阶段上涨语义选择、数字表 | 标签不看模型效果选定；默认值与最终值明确分开 |
| B 评价器验收 | 黄金边界样例、成熟/首警/匹配/分母核对、数据使用台账 | 两名复核角色对逐条结果一致；未知状态不误当负例 |
| C 有限开发对照 | 简单时间参照、LPPL1.5、单因素消融、完整错误表 | 有继续消耗独立证据的理由；无增量就停留研究层 |
| D 独立确认 | 冻结候选、独立预测、成熟结果、相关性不确定性 | 达到事前数值门槛及精度要求；不靠换指标或换标签过关 |
| E 前瞻确认 | 应产出账本、封存预测、运行质量、成熟事件与机会成本 | 时序证据可信、现场表现与离线定义一致；样本不足则继续等待 |

本草案尚不指定“准确率80%”等无依据产品门槛。冻结时必须填写：最低阶段召回、最低精确率、最大每资产年提醒数、最大警报占用、可接受拒报及运行缺失、相对最强简单基线的最小增益、置信区间标准、最少独立事件/时期与最终判定日期。缺一项不能宣称通过。

可接受裁定只有：`PASS / FAIL / INCONCLUSIVE / INVALID_EVIDENCE`，分别表示达标、未达标、样本/精度不足、协议或时序证据失效。CI/程序测试通过仅表示实现检查通过；不是预测通过。

如果短期层通过、阶段层失败，产品只能按短期证据表述。时间通过、层级失败，则只能显示层级不明。简单参照通过而LPPL无增量，不继续把LPPL作为已证明的核心优势。宽窗可覆盖而窄窗失败，保留宽情景并说明限制，不裁窗制造成功。

### 评价器必须覆盖的黄金案例（仅为后续验收清单，本轮未运行）

- 单日峰；精确连续平顶；间隔`G`内的同价双顶；间隔`G+1`的双顶；长平顶尚未闭合；近价但不相等的双顶。
- 左邻域缺失；右邻域未成熟；边界日出现更高值；合并闭合最后一天出现可接入候选；停牌或除权异常。
- 宽度1、10、11交易日；周末节假日；连续参数外向取整后超宽。
- 收盘后发出；延迟可见；下一交易日不可行动；`u-a=4/5`；模型`tc`在未来但真实峰已过去。
- 首警错窗后改中；首警宽窗后缩窄；取消重发；多个episode指向同一事件；一窗包含两个事件；期限内无事件但尚未成熟。
- 同一事件两层标签；短期被升级成阶段；阶段只报短期；时间对但拒判层级；两个层级关联歧义。
- 提醒后先上涨而在窗内见顶；小幅回落仍成标签；之后跌很深但时间错；整段无提醒；运行全失败。
- 在同一数据上作严格单调价格变换后，极值/平顶顺序标签应保持一致（报价编码和公司行动处理不变）；这一检查用于发现隐藏的幅度门槛。
