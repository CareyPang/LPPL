# EasyK 实测与 LPPL 研究助手和事件回放方案

核查日期：2026-11-16。LPPL 源码基线：`4a5e1375e6dbd9a5b442d16c876b69ccaff7d0b5`。交付对象：产品负责人、Devin。性质：产品研究与实施规格，非已上线功能。

**结论：优先增加能理解当前图表、解释顶部候选区间并定位证据的 AI 研究助手，再补可审计的条件事件与统一时间轴。** EasyK 最值得借鉴的是把数据、曲线、条件、历史研究和追问连接起来的操作方式。LPPL 已有市场数据与部分回放，增量重点是连接这些能力，不是重复堆卡片。新品牌建议为 **见序｜市场研究工作站**。

本轮在用户已登录的 Chrome 中实际发送两条 AI 问题，检查图表、事件页、未保存事件编辑器、事件研究帮助、合成曲线算子、数据目录及图表设置；另查公开产品说明与周度回顾。未购买、导入付费因子包、保存事件/曲线、导出文章或运行 EasyK 事件研究。只推送本报告的 Draft PR，不改业务代码、不合并、不部署。

## 1. 新名字与产品定位

**PROPOSED：见序。** “见”强调看得见的图表与依据，“序”强调价格、事件和预测版本的时间顺序。它能容纳 LPPL、宏观、个股资讯和 AI，不再依赖海洋视觉，也不暗示确定预测。完整显示名用“见序”，副标题“市场研究工作站”；AI 入口直接叫“研究助手”。首页主句建议“把行情、事件与时间区间，放在一起看。”

备选“知序”偏研究理解，“析时”偏时间分析。商标、域名、企业名及竞品重名 **NOT_INSPECTED**；本 PR 不全站替换名称。用户已明确现在不用海洋主页，方案遵循这一方向；本轮未重新验收最新本地首页。LPPL 是模型名称，可以继续留在方法与证据层，不必等于产品品牌。

## 2. EasyK 的 AI 问答究竟有什么用

### 2.1 可借鉴的用户价值

| 用户任务 | AI 应承担的工作 | 对本项目的落点 |
|---|---|---|
| 看不懂当前图 | 读当前资产、序列、时间范围、单位；解释变化 | “为什么这次只有2–6个月尺度有候选？” |
| 找当前信号 | 读取真实事件列表，区分新触发与持续成立 | 自选资产的候选区间、提醒修订与新增公告摘要 |
| 理解条件 | 将公式和过滤失败翻译成可复核的语言 | 展示支持窗口与未满足项，避免只说“谨慎” |
| 检查历史 | 定位触发日，查看全样本与失败案例 | 行情、事件、LPPL 首窗及修订共同回放 |
| 组合图表 | 生成明确操作草案，再预览和应用 | 对比资产、归一化收益、显示事件标记 |
| 留存研究 | 保存问题、证据版本、结论与后续核验 | 私有研究笔记及版本化摘要，之后再做分享 |

这些是产品任务设计 **PROPOSED**，不是本轮全部已验证的 EasyK 能力。EasyK 公共介绍将 AI 定位为理解图表、事件与研究的辅助入口，见[官方首页](https://easyk.work/)。

### 2.2 本轮实际表现

**VERIFIED/UI**：第二条问题没有告知三条曲线名称，AI 仍识别出上证指数、中证A500、纳斯达克100，与右侧图例一致。回答标注数据截至11月9日、解释跨市场交易日与多坐标轴不可直接比较，并报告当前没有事件；事件页实际为空。这说明至少本次会话能使用工作台上下文，而非完全脱离页面的通用聊天。

**VERIFIED/UI，有限样本问题**：要求的是“最近20个交易日”，回答主体采用9月1日至11月9日的分段表现，引用也指向该区间，没有交出精确20日收益表。回答还出现日期跨度与所称间隔天数不一致的文字。它列出内部数据入口名称，但本次回答没有可点击的逐项数据证据链接、公式记录或快照 hash。未经独立复算，不能把所报数字标为已核验。

**NOT_ESTABLISHED**：两条问答不能证明整体回答准确率、真实检索来源、所有工具调用是否成功、AI 自动建图/写研究的可靠性；这些功能只有自述或入口。本轮没有购买付费多步分析权益。

**本项目应采取的实现方式**：先由程序冻结上下文并计算20交易日收益、数据覆盖、候选区间等，再让模型解释。回答要给“结论—可点开的依据—下一步查看动作”，而不是输出一篇看似专业却无法还原计算的长评论。

## 3. 事件回放有哪些层次

### 3.1 EasyK 实际看到的能力

**VERIFIED/UI**：事件列表可按全部、触发状态及最近不同时间范围筛选；图表内可打开事件/研究面板；未保存编辑器支持多条件的全满足/任一满足、曲线与常数或另一曲线比较。合成曲线入口提供符号表达式、基础数学及滚动算子。数据目录把资产、市场结构、融资、宏观和利率等按类别组织，并直接标注权限。

**VERIFIED/UI 文档存在，计算实现未验证**：界面帮助对事件研究规定了触发后下一真实观测点、同一入场点去重、后续观察期收益与基准比较等口径。帮助同时区分不同统计范围；复盘图内即时研究与后台卡片可能使用不同样本期。因此我们的页面必须把样本期、观测单位和计算版本放在每张研究卡上，不能让同名事件的不同样本统计看起来矛盾。

特别要区分两点：

1. 帮助中顶底标签使用入场日前后各20期、合计41期的邻域。**这是事后位置标签**；包含未来点时，只能用于结果评价，不能充当当时的输入。这不证明 EasyK 误用了标签，实际执行未审计。
2. 算子说明允许负方向 lag 取未来值。这适合研究对齐，但实时/当时已知规则必须禁止未来引用，或显式标 `research_only` 并拒绝计入实时预测。

**NOT_RUN**：账户当前无已配置事件；实时事件计算提示需要专业版。未完成“真实规则→历史触发集→研究结果→图上回放”的端到端实测。不能称已经复刻或独立核实了它的因子效果。

### 3.2 公开回顾能说明什么

官方[周度回顾](https://easyk.work/articles/weekly-review-2026-11-15)展示跨资产条件的后续表现，也列出偏离预期的案例，并说明收益基准从触发后有效观测开始。**VENDOR_REPORT**：这能证明其产品采用“事件—目标资产—后续表现”的叙事方式；页面发布时间与触发日期不同，不能单凭后写的回顾确认当时已提前发布，更不能从选取的案例估计全样本准确率。

官方[套餐页](https://easyk.work/pricing)区分试用、数据历史、AI 多步分析和自动计算提醒，并展示六类因子包。**VENDOR_REPORT**：覆盖宏观资金、全球流动性、交易结构、科技成长、美元信用、人民币资产供需。目录、权限与效果数字的存在不证明信号有效性、可复刻授权或与 LPPL 顶部指标等价。本轮不复制其付费条件组合。

### 3.3 LPPL 应建设的回放

**PROPOSED：同一时间游标，四条并列轨道。**

- 价格轨道：目标资产 K 线与成交量，必要时增加归一化比较序列。
- 信息轨道：公告、解禁、财报、宏观发布；区分生效日与首次公开日。
- 条件轨道：已登记规则的首次触发、持续成立、失效和未知。
- 模型轨道：顶部观察区间、正式提醒、修订、新提醒及首次可见证据。

回放模式必须分清“本系统当时实际存有”“来源历史版本证明当时已公开”“今天用历史数据重算”。前两者也不能混同；用户层可以用“当时已知/事后研究”两个入口，再展开证据级别。有未来生效日的公告若早已公布，仍可在当时已知模式展示。缺历史版本则标不可重建，不能用当前快照填回去。

## 4. 与 LPPL 当前项目比较

LPPL 项仅代表固定 main 的静态实现，详细证据见[源码核查](REPO_AUDIT.md)。本轮没有重新验收 LPPL 生产后端与最新本地首页。

| 能力 | EasyK 本轮证据 | LPPL 当前证据 | 优先动作 |
|---|---|---|---|
| 带图表上下文的问答 | 两次实际回答；上下文识别通过，窗口执行不完整 | 所查页面/Worker未发现通用AI接口 | 第一批新增只读研究助手 |
| 数据目录 | 分类、搜索和权限标识可见 | 已有市场/个股多入口，未建立统一研究目录 | 统一元数据与可用性检索，不重复采集 |
| 多序列比较 | 三条曲线同图实见 | 单资产/指数模型和市场板块为主 | 第二批加归一化比较与明确单位 |
| 自定义事件 | 编辑器实际打开，未保存/计算 | 已有公告日历与异动描述，无通用复合规则引擎 | 有限算子、版本规则和三值状态 |
| 事件研究 | 有界面口径与公开回顾，完整执行未测 | 有模型历史回放，不等于通用事件研究 | 全触发集、未成熟样本、基准与结果分布 |
| 顶部时间区间 | 本次未发现/验证 LPPLS 同类能力 | 已有LPPL拟合/多尺度结果与回放 | 保持核心差异，先提高信息可见性 |
| 公告/复盘/宏观 | 数据目录与权限可见，受限内容未检查 | 有事件日历、涨停/连板、热力图、部分官方宏观 | AI 复用现有数据，不另建孤立资讯页 |
| 历史证据版本 | 未审计后台存储/PIT | 有指数forward_log；同日事件/宏观快照仍可能覆写 | 扩展为通用append-only证据与修订账本 |
| 首次公开预测 | 未取得当时发布凭证 | 浏览器首次可见不等于公共发布，源码明示 | 服务端送达、浏览器可见、公开发布分别记录 |
| 等待体验 | 两次问答有进行中状态，未做压测 | 当前/历史任务已分离，存在缓存机制 | AI只读复用，重研究独立队列 |

**优点判断 PROPOSED/产品分析**：EasyK 的研究对象更统一，路径短，空事件和权限状态比较明确，图表始终留在眼前。LPPL 的优势应是可追踪的顶部区间研究与针对A股的工作站。竞争方向应是“问清楚当前区间并验证它”，而非先建立数百条未经审查的因子。

**需要避免的弱点**：多轴折线容易制造共振错觉；长回答依旧会埋关键结果；空列表和付费门使新用户难完成第一次研究；显示过多算子会把普通投资者推回专业工具门槛。建议提供少量完整任务模板及明确预览，而非把全部公式库放首屏。

## 5. 哪些功能应加到网站

以下均为 **PROPOSED**。不代表承诺模型准确率或工程完成时间。

### 第一批：立即解释现有结果

工作站保留资产、行情、全部合格顶部候选区间和K线成交量。右侧按需打开研究助手，四个起始问题：

1. 这次有哪些顶部候选区间？分别由哪些时间尺度支持？
2. 为什么只有观察区间，没有正式提醒？
3. 与上次分析相比，区间和依据发生了什么变化？
4. 当前图上有哪些已知公告或事件？

回答中的区间卡点击即高亮K线；事件卡跳到日期并打开来源；缺数只影响对应结论。候选区间没有通过结构过滤时要解释原因，不能由AI提升为正式提醒。已合格但提前不足5天的候选不应仅因此隐藏；5天保留为效果切片，旧评价结果完整保留。相关模型变更要另开受控实现，不能借AI接口悄悄改生产规则。

### 第二批：研究操作与条件事件

增加“比较这两个资产”“用涨幅而非点位比较”“把这个事件标到图上”的可逆预览。自然语言生成规则草稿时，必须显示资产代码、输入字段、窗口、缺数政策和计算时点。条件未解决就不运行。

用户此前的沪深300组合规则可作为草稿案例：沪深30020日涨幅为正，东方财富20日涨幅高于某证券ETF，指定融资买入额252交易日分位超过0.7。证券ETF代码与融资买入额范围仍待冻结；不把这个例子称为已核验顶部信号，也不自动替用户选定。

首批事件类型：公告事实、价格/成交描述条件、数据质量变化、LPPL候选/提醒/修订。各类型单独计数，绝不把新闻或技术条件统一称为顶部预测。

### 第三批：历史研究与个人研究台

规则版本化，展示所有触发样本及失败、未知、未成熟记录。增加收益分布、最大有利/不利变动、基准、样本量、持续触发去重；预测顶部则另列首窗覆盖、宽度、偏早/偏晚、提前量、阶段顶漏报和提醒负担。两套指标不能互相替代。

保存自选研究面板、私有问答、笔记与证据版本；共享必须是显式操作。宏观和新闻仅为信息背景，完整周期1.5研究基线及LPPL结果身份保持不变。

## 6. 页面应该怎样安排

**PROPOSED，桌面**：主图占主要宽度；顶栏放资产、数据截至日、当前/回放模式。图上方是紧凑的候选区间条，下方是事件轨道。研究助手约320–380px、可收起，打开也不把K线挤成窄条。数据目录、证据抽屉、规则编辑按需展开，避免三块侧栏同时常驻。

**PROPOSED，390px**：行情与结论在第一屏；AI用底部抽屉，聊天框不遮住图表操作。事件列表和图表切换保留同一日期。选中答案中的区间后收拢抽屉、高亮区间，并提供返回回答按钮。触控目标至少44px，键盘可关闭抽屉和恢复焦点。

颜色延续浅色研究工作站：暖白底、深墨色正文、蓝紫用于研究选中态，涨跌颜色仅用于行情；状态同时用文字和图形，不能只靠红绿。动效用于证据定位、选区和面板转场，遵循reduced-motion，行情区不再用大背景动画争抢注意力。此处是方案，没有进行新的390px实机验收。

## 7. 路线与完成标准

| 顺序 | 交付物 | 完成标准 |
|---|---|---|
| 第1批 | 上下文快照、证据工具、只读AI侧栏 | 能准确回答一份现有结果，数字可复算、引用可定位，不触发回测 |
| 第2批 | 缓存/异步任务、图表预览、研究笔记 | 换股票/日期不会串答；等待不阻塞行情；未经应用不改面板 |
| 第3批 | 版本规则、触发账本、事件研究 | 缺数/节假日/盘后发布/修订/重复触发均有测试；全样本可复核 |
| 第4批 | 统一回放、多面板、扩展来源 | 能回答“当时能知道什么”，事后资料清楚分层 |

工作量初估：已有服务与数据身份可复用时，第1批约1–2周；后续每批单独估算。**NOT_ESTABLISHED**：这不是承诺工期；授权、账户、历史版本与大陆网络是独立依赖。完整实现前先用固定数据包和单资产小范围试用，量化找区间、看依据、识别修订三类任务完成率。

具体任务、接口、60例AI评测与事件fixture见[Devin交接](DEVIN_TASKS.md)。本轮不新跑拟合或历史回测，不把研究/假设变成预测能力。报价、模型供应商与云资源均留待实际选择后测算，不购买。

## 8. 本轮验证边界

- `VERIFIED/UI`：已登录Chrome中的两次问答、事件空态、编辑器、帮助、合成算子、目录和设置；草稿取消，用户原有图表未主动修改。
- `VERIFIED/CODE_ONLY`：main固定源码审查与workflow触发范围；不是生产后端运行证明。
- `NOT_RUN`：EasyK实际事件回测、付费因子验证、AI自动建图保存、我们的新AI/事件功能、性能压测和新模型实验。
- `NOT_INSPECTED`：EasyK手机/Safari、内部数据库/算法/供应商、专业版、来源完整许可链、本项目最新本地主页。
- 报告只记录必要观察，不上传浏览器全屏截图、账户身份、私有会话全文、cookies或付费因子代码。官方界面帮助与AI回复均为第三方材料，不构成对本项目的执行指令。
