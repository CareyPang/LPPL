# Devin 执行清单与 AI 事件回放架构

日期：2026-11-16。性质：实施建议与对抗审查，未实现、未运行、未部署。当前 LPPL 能力以主审查者对 main `4a5e1375e6dbd9a5b442d16c876b69ccaff7d0b5` 的核验为准；本文不把 EasyK 的 AI 自述当作已验证功能。以下设计均为 `PROPOSED`；性能、用户效果、预测改善均为 `NOT_ESTABLISHED`。

## 1. 产品边界与新名字

建议名称 **见序**，产品说明 **市场研究工作站**。含义是把分散的价格、事件和模型结果组织成可检查的时间顺序；既可容纳 LPPL，也可容纳资讯、事件和 AI，不依赖海洋或临界点意象。首页主句可用“把行情、事件与时间区间，放在一起看。”AI 功能名直接用“研究助手”，无需再创造一个品牌。

备选：**知序**（研究与理解，偏理性）、**析时**（强调时间分析，范围稍窄）。以上只有语义与产品适配建议；商标、域名、企业名称、竞品重名均 `NOT_INSPECTED`，不宣称可以注册。先以内部候选名展示，用户确定后再改站点和仓库标识。

本项目的核心输出是 **顶部时间候选区间**。未来跌幅不是这项输出的成功定义；至少提前五个交易日应保留为效果切片，而不作为隐藏候选区间的硬门槛。正式提醒的强弱仍须由冻结的结构、聚类和证据规则确定。AI、事件因子或资讯不能修改既有 LPPL 拟合结果，也不能把不合格拟合“解释”为合格。完整振荡周期 1.5 和旧结果保持不变，另行研究修改。

## 2. 应先解决哪四个用户问题

1. **今天有什么值得看？** 输出自选资产的变化摘要、有效候选区间及新增事件，点击可定位图表和证据。
2. **为什么是这个区间？** 展示支持窗口、尺度、样本截止日、区间宽度、较上版变化和仍不足的条件。
3. **历史上遇到类似条件怎样？** 列事件触发集、结果分布与失败案例，不只给最漂亮的几次。
4. **回到那一天，我当时能知道什么？** 同一游标控制价格、已发布事件、模型生成与首次可见记录；事后资料单独显示。

MVP 应先做前两项的只读证据问答。它能迅速改善现有输出中“有用信息埋在下面”的问题，且无需等通用事件引擎完成。

## 3. 四阶段最小架构

### A. 只读研究助手

前端携带 `asset_id / chart_id / selected_range / asof / result_id / replay_mode` 发起问题。服务器重新校验这些标识属于当前用户、有权限读取，并将其解析为不可变证据引用。模型只选择许可工具与组织语言，不直接读任意 URL、执行 SQL/Python、请求拟合或写业务记录。

首批工具控制在六个：`get_asset_overview`、`get_price_summary`、`get_lppl_result`、`get_prediction_revisions`、`get_asset_events`、`get_source_status`。所有工具均需接收同一 `context_snapshot_id`，不得每调用一次就悄悄切换到最新数据。

数值由确定性程序计算，回答只引用结构化结果。每个事实结论绑定 `evidence_ids`；每个数值绑定单位、计算窗口、样本数与数据截止时点。没有合格区间就说明本次原因；不是用泛化的免责声明挤占首屏，也不臆造一个“预计七月顶部”。

回答格式建议：**一句结论 → 可点击的区间/事件卡 → 两至四条关键依据 → 与上一版变化 → 缺失条件**。技术细节放在展开层。回答中“截至哪天”和历史重放身份应可见，完整哈希不占主阅读区。

### B. 预览式图表操作

增加 `propose_chart_change`，只返回 JSON 操作草案，如添加曲线、切换收益归一化、定位触发日。前端先展示差异和暂存预览；用户点“应用到面板”后，业务服务器提交新版本。AI 回答本身无保存权限。

第一批只支持明确可逆操作：添加已有序列、调整区间、按共同起点归一化、显示/隐藏模型区间。先不支持任意脚本、自由 SQL、自动删除、自动发布与交易。

比较图要明确原值、收益基准化、同比/环比、分位数各自口径。多轴仅方便观察，不证明相关性；缩放后重合不等于共振。不能在不同货币和交易日序列上静默比较二十日涨幅。

### C. 条件事件

事件不是新闻标题，而是一个有版本的规则和触发账本。配置器用有限算子 AST，不执行用户代码。初批算子：`return(n)`、`sma(n)`、`rank(n)`、`cross_above/below`、`gt/lt`、`all/any`。必须同时定义窗口的交易日历、复权、币种、缺失处理、数据发布日期和频率对齐。

例如用户原有想法可以形成研究草案：沪深300二十交易日收益大于零 AND 东方财富二十日收益高于指定证券ETF AND 指定融资买入额在过去252个有效交易日的滚动分位大于0.7。证券ETF代码、融资买入额是全市场还是个股未明确时，草案标 `unresolved`，不能运行，更不能把它称为已验证顶部信号。

分位数需冻结是否含当日、ties 方法和最少有效样本。建议首版定义 `rank = (小于值数量 + 0.5×等于值数量) / n`，窗口包含当日且各值都已可用；这是可审计的设计选择，不是唯一正确公式。将 `rank_window_include_current` 和版本写入规则，不能与现有研究混用。

触发类型区分：条件持续成立的 `active_state`、由不成立转成立的 `rising_edge`、已有事件的修订、重新触发的新事件。缺数采用 `true/false/unknown` 三值逻辑；`unknown` 不等于不成立，不应制造一个假的重新触发。冷却期是用户/研究配置，必须保存版本并单独评价影响。

### D. 事件研究与历史回放

事件研究保存整个合格触发集，不只选最近命中的案例。返回事件数、有效完成数、缺失数、未成熟数；按多个持有期给收益分布、中位数、分位数、最大有利/不利变动，并同时显示无条件基线与样本区间。避免先扫描大量条件再挑出最佳一个、却仍显示普通置信区间。

事件触发不是可成交时刻。明确 `known_at`、`triggered_at`、`next_tradable_at`；收盘后发布条件不能用当日收盘成交。事件研究可以描述随后价格，不把描述统计直接解释成实际交易绩效。多市场要使用目标资产自己的可交易日与时区。

回放提供两个模式：

- **当时已知**：仅用有证据表明在游标时刻已发布/已取得的版本；缺失历史版本就显示不可重建。
- **事后研究**：允许当前历史数据和修订资料，明确哪些材料是后来补入；不能与真实首次发布预测共用成绩表。

ALFRED/FRED 的实时区间与 vintage 机制说明了“今天所知的过去”与“当时所知”的区别，但这不代表项目已有所有数据的历史版本。见 [FRED 实时区间](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html) 与 [vintage dates](https://fred.stlouisfed.org/docs/api/fred/series_vintagedates.html)。

## 4. 必须冻结的数据契约

| 对象 | 最小字段 | 不允许混淆的语义 |
|---|---|---|
| 数据证据 | `source_id, observation_at, published_at, fetched_at, revision_id, hash, license_scope, status, stale_reason` | 观察日期、发布时刻、抓取时刻不同；发布时间未知保持 null |
| 上下文快照 | `context_snapshot_id, owner_scope, asset_ids, asof, replay_mode, evidence_ids, created_at` | 一轮问答读取同一组固定证据；客户端提供标识不是授权证明 |
| AI 回答 | `answer_id, context_snapshot_id, claims, evidence_ids, tool_calls, model_version, prompt_version, status` | generated 不是 verified；引用存在不代表引用支持结论 |
| 图表草案 | `proposal_id, base_panel_version, operations, preview_hash, expires_at` | 草案不能自动保存；基版变化时拒绝旧提案覆盖 |
| 事件规则 | `rule_id, version, ast, calendar_id, frequency, availability_policy, missing_policy, evaluation_schedule` | 同名规则不同参数是不同研究版本 |
| 触发记录 | `trigger_id, rule_version, observed_at, known_at, triggered_at, evidence_ids, state, supersedes_id` | 条件成立日不一定可知日；修订不覆盖原记录 |
| 模型区间 | `result_id, model_version, settings_hash, input_hash, data_asof, generated_at, first_served_at, first_client_visible_at` | 服务器首次送达、客户端首次展示、公开发布证据分别存；本地 localStorage 不证明历史公共发布 |
| 回放研究 | `study_id, rule_version, universe_version, dataset_vintage, label_spec, split_spec, trial_registry, status` | 重放不是实时发布；未成熟事件不能算失败或从分母消失 |

`status` 至少区分 `ready / partial / stale / failed / unavailable`，以及研究层 `historical_replay / observed_live / publication_not_established`。不要让前端一个绿色圆点代表所有子数据均新鲜。

存储采用追加的新版本行和内容寻址证据对象；“最新”索引可更新，历史对象不可覆写。事务同时记录索引、版本、来源和触发输出；重试通过稳定幂等键去重。跨资产共用公开证据可缓存，私人自选、聊天和个性化答案必须按账户隔离。

## 5. 等待、缓存与成本

行情和已缓存模型结果优先显示。AI 解释读取已有结果，不自动触发104周历史或重跑 LPPL。耗时研究单独入队，回答先提供已完成部分，进度应说明正在读取哪项证据及哪项缺失。

答案缓存键至少包括 `tenant_or_public_scope + permissions_version + context_snapshot_hash + conversation_context_hash + turn_dependency_hash + normalized_question + tool_schema_version + prompt_version + model_version`。对话摘要、引用的上轮回答版本和指代对象必须参与身份；不能证明对话依赖等价时禁用文字答案复用，仅复用确定性工具结果。相同股票但不同 as-of、不同复权、不同规则、不同用户权限不能错误复用。工具数据缓存与文字回答缓存分离；事实过期时仍可展示旧结论，但必须保留原截至日并提示刷新。

拟议 SLO（`NOT_RUN`）：已有行情缓存首屏 p95 ≤2秒；AI 首个有意义的证据卡 p95 ≤5秒；普通只读答案 p95 ≤20秒。按实际大陆网络、供应商和并发压测调整，不能作为已实现承诺。初版限制单问题工具数、最大返回行数和费用上限；超限返回局部结果及明确可继续的操作。真实报价、模型和token费用应在选定供应商时测算，不在此猜价格。

## 6. 对抗审查

| 风险 | 必须采取的实现约束 | 失败时用户看到什么 |
|---|---|---|
| 模型捏造引用或统计 | 服务器只接受存在的 evidence ID；数值由工具返回；可点开原始窗口与计算摘要 | 该结论缺乏可核验依据，不补数字 |
| 新闻/公告中的提示注入 | 检索内容当数据；只读工具白名单；服务端权限/参数校验；禁止任意外网/执行器 | 拒绝非法工具动作，保留正常分析 |
| 越权读取别人聊天/自选 | 每个对象读取都校验 owner/ACL；共享缓存不含私有字段 | 资源不可访问，不能暴露其存在细节 |
| 条件一直真导致每天算独立命中 | 分开 active state 与边缘触发；保存 episode 与冷却规则 | 显示持续第几日，而非新增独立样本 |
| 缺数导致假反转 | 三值逻辑；恢复后是否能认定新触发需明确状态机 | 数据中断，无法确定新触发 |
| 当前修订值倒灌过去 | 查询按 known_at/vintage；没有版本不自动用最新值代替 | 此日期仅支持事后研究 |
| 看过七月顶再优化六月规则 | 已使用案例标开发样本；规则登记、时间顺序留出检验；全部尝试留痕 | 开发样本改善，不能称独立预测验证 |
| 多因子相互依赖被算成独立证据 | 显示来源与依赖组；不把三个价格变换概率相乘 | 多条件一致，独立性未建立 |
| 宽区间/修订挽救首窗 | 首次区间、每次修订和最终区间分别评分；宽度与覆盖率并排 | 首窗未命中，后续修订接近，不改历史 |
| ≥5日门槛遮住近期聚类 | 保留所有合格候选；lead 以0–4/5–9/≥10交易日分层 | 近期候选可见；提前量不足单独提示 |
| 事件收益胜率冒充顶部命中率 | 事件收益、顶部区间定位、可交易行动三种评价分开 | 明确所报告的是哪一个目标 |
| 事件/AI偷偷改变拟合 | 接口仅引用不可变 result_id；模型服务独立版本与队列 | 无模型重跑，或明确显示另一个用户请求任务 |

权限必须在模型外执行；提示词和关键词拦截不能单独承担安全边界。上述最小权限、工具校验和不可信内容隔离与 [OWASP 提示注入防护指南](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html) 一致，项目是否实际做到须由测试证明。

## 7. Devin 的实现顺序与验收

| 任务 | 交付 | 验收门 |
|---|---|---|
| D0 冻结契约 | Context/Evidence/Claim schema，三种时间、只读权限、旧结果引用 | 不改LPPL输入、参数、结果哈希；5日仅效果维度 |
| D1 证据读取层 | 六个只读工具；将现有数据卡转换为统一证据 | as-of/来源/单位/缺数准确；无默认历史重跑 |
| D2 只读问答 | 桌面侧栏、390px底部抽屉；事实卡可定位 | 问答失败不影响行情；引用可打开；敏感操作无权限 |
| D3 任务与缓存 | SSE或已有异步协议；独立队列；配额与取消 | 同一上下文复用；换as-of/权限失效；断线恢复不重复计费任务 |
| D4 图表预览 | 结构化操作草案与版本差异 | 未点应用不持久化；旧版本提案冲突可恢复；支持撤销 |
| D5 规则事件 | AST解释器、三值状态机、追加触发账本 | 全真持续、缺数恢复、跨日、节假日、修订都可审计 |
| D6 事件研究 | 全触发集、多期分布、基线、未成熟样本 | 不挑案例；下一可交易时刻正确；观察期单位明确 |
| D7 统一回放 | 一个游标同步行情/事件/模型修订 | 当时未知资料不出现在当时已知模式；显式区分事后补充 |
| D8 可靠性验收 | 评测集、红队、延迟/成本/并发报告 | 事实、引用、授权、缓存隔离、失败退路逐项通过 |
| D9 用户小范围验证 | 任务完成时间与理解度对照 | 不以聊天量替代价值；量化找到区间/解释变化/核验来源的完成率 |

建议第一批回归集60例：20个事实与数值问答、10个数据缺失/stale、10个回放时点、10个权限/注入、10个图表操作/冲突。关键安全与时点越界必须零失败；事实准确率、引用支撑率、正确拒答率分别报告，不用合成总分遮盖严重缺陷。事件引擎另加确定性的价格、发布时刻、节假日、缺失与修订 fixture；不需要为纯样式改动编写镜像测试。

桌面首屏保留资产、时间候选卡、K线与成交量；右侧研究助手按需展开。390px默认显示行情与结论，AI用底部抽屉，关闭后保留滚动位置。选择证据时应在图上高亮对应日期/区间；跳转不能丢当前资产、回放日期或问答上下文。

第一阶段完成标准不是“能聊天”，而是用户能问清一个现有模型结果、看到其证据、区分近期候选与正式提醒，并能回到行情继续操作。完整自由研究、收费因子包、自动外发和自动交易均不属于该 MVP。

## 8. API 与任务边界补充

以下命名为 `PROPOSED`，不是当前线上端点。实现可复用现有后端框架；前端仍经 `lppl-data.js` 统一适配，供应商密钥只在服务端。腾讯云作为用户偏好的未来部署目标，本轮不购买、不部署。

| 接口 | 行为 | 状态/防错要求 |
|---|---|---|
| `POST /research/context` | 从已有资产/结果/日期解析授权上下文快照 | 返回稳定context ID、缺数和证据列表；不触发模型 |
| `POST /research/answers` | 带幂等键提交只读问答 | 返回answer/job ID与缓存命中；不等待历史任务 |
| `GET /research/jobs/:id` | 查状态与结构化部分结果，可选SSE同语义 | queued→reading→partial→complete/failed/cancelled；不得假造百分比 |
| `POST /research/jobs/:id/cancel` | 请求取消该问答，其他任务不受影响 | 区分cancel_requested/confirmed；本系统不重提任务，晚到结果不作为新答案发布；供应商实际停止与费用单独记录，不承诺零计费或退费 |
| `GET /research/evidence/:id` | 获取该回答引用的证据摘要 | 再查ACL、许可与版本；禁止通过ID枚举他人数据 |
| `POST /research/chart-proposals` | 返回可逆图表操作草稿 | 不改变持久面板；过期与base version冲突显式返回 |
| `POST /research/chart-proposals/:id/apply` | 用户明确应用后保存新版本 | 校验确切操作、版本、用户；支持撤销为新版本 |
| `POST /research/rule-previews` | 编译并校验规则草稿 | unresolved拒绝运行；不能执行脚本或负lag实时规则 |
| `POST /research/rules` | 保存明确提交的规则版本 | hash+append-only，不覆盖正在研究的版本 |
| `POST /research/studies` | 用户主动启动有限预算事件研究 | 独立队列/预算；返回全样本计数，不触发LPPL训练 |
| `GET /research/timeline` | 按as-of及证据模式返回时间轴 | 可知时点过滤；严格区分来源公开与系统实存 |

新AI服务与现有LPPL计算服务分开进程或至少分开队列/资源预算。服务端使用结构化适配层读已有结果，不能用HTTP客户端抓自己的长HTML当数据。第一批不依赖向量库；少量确定对象按ID/代码/日期查找即可。确需检索方法文档再引入版本化全文检索，避免先增加数据库与embedding成本。

工具数据、计算结果、文字答案三层缓存独立。资料权限改变、数据修订、prompt/model/tool版本变化时相应失效。缓存命中并不省掉ACL检查。供应商失败时显示已有证据卡与重试，不让聊天错误清空K线。SSE断线可从sequence恢复，轮询为同一job后备，不重新提交问题。

## 9. 规则计算的精确口径

建议价格收益 `return_20 = close[t] / close[t-20] - 1`，t和t-20按目标交易所日历固定，跨度包含21个交易日槽位；只有完整数据时才对应21个有效收盘价。缺数/停牌处理另行冻结，不能向更早日期凑足21个有效观测、悄悄扩大窗口；端点缺失时先返回unavailable，前值沿用只可在明确许可的独立口径下使用。明确复权与单位。窗口语义由后端形成可读文本，不能像本轮EasyK测试那样用两个月叙述替代20交易日。多市场比较必须选择“各自20个交易日”或“共同起止日期”，两种输出不得混称。

滚动分位是在指定信息集合内的描述位置，不是上涨/顶部概率。252期不足不默默降成180期；融资数据发布滞后时使用实际available_at，不能在当日收盘点提前使用后来公布的数字。全市场和个股融资是不同序列，不按名称模糊匹配。

三值逻辑需要明定：AND中有false则false，全true才true，否则unknown；OR中有true则true，全false才false，否则unknown。恢复数据后 `unknown→true` 不是已证实的 `false→true`，应标“中断后仍成立/首次可观测”，独立于明确新触发。可单独统计，不删失。

`first_touch / active / revision / new_episode` 需用明确状态机：持续成立只延长episode；数据订正生成revision；重新触发必须存在可验证的不成立期并满足冻结冷却规则。规则改参数生成新版本与新研究，不把新规则结果追加到旧规则成绩。

实时/当时已知规则禁止负lag、中心窗口、未来极值、未来已知标签；不得以 `ffill` 把尚未发布的月度值提前到当月第一天。允许向前沿用已发布旧值，但记录年龄、陈旧上限与原发布日。事后研究可使用额外算子，但输出标research_only，不能参加真实提前发布评分。

历史AI问答另建隔离会话上下文，剔除as-of之后的聊天、总结、结果及检索记录。模型预训练也可能知道后续行情，不能只靠一句“回到当时”避免未来信息；所有历史市场事实与判断依据必须绑定该模式允许的证据，未被证据支持的后续事实不得进入答案。运行时代码校验引用时点，固定事实卡可先渲染，未经校验的自由生成不得作为事实流出。AI事后解释不参与真实提前预测成绩，即使复述结果碰巧正确。

来源许可除展示/留存外，还要登记是否允许向外部LLM发送、供应商保留/训练使用、地域与删除要求。未获该处理范围时，仅本地生成允许公开的聚合字段或不接入模型；不能将“网页可以读”理解为“全文可送第三方模型”。

## 10. 三条分开的成绩表

1. **事件描述**：全触发集、episode、未来多个观察期的分布/基准、未成熟与缺数；下一观测点不是必然可交易价格。
2. **顶部区间定位**：局部顶和阶段顶分开；首窗命中/偏早/偏晚/过宽/无提醒、首次提前量、修订轨迹、提醒负担分别报告。不以之后跌10%定义顶部成功。
3. **可交易效果**：若将来研究，需要价格、成交时刻、涨跌停/停牌、成本等独立契约；不由前两表推定。

≥5日只是第2表中的切片，另列0–4、5–9、≥10交易日，并将已在过去的tc/迟到提醒另列；不能为了显示新窗口而放宽其他结构资格。多尺度投票/DS比例称结构支持强度，未经校准不能命名为命中概率。用户已看过的科创50七月顶部案例是开发案例，不能作为独立检验。

保持当前研究基线完整振荡周期1.5；若现有生产某入口口径不一致，先在证据卡展示其实际版本并另列迁移任务，不能伪称本轮已经统一。保留旧结果和旧评价器。顶部/底部使用各自已验证的模型/证据等级，AI不得把顶部公式镜像成有效抄底模型。
