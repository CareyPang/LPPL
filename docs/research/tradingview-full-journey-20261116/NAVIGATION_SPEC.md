# TradingView 导航拆解与 LPPL 可实施导航规格

核查日：2026-11-16。本文只核验官方网页/教程，并提出 LPPL 设计；没有控制用户Chrome，不能代替主报告的逐页实操。截图菜单来自用户提供的参考图，单列为USER_SCREENSHOT。没有修改业务代码、推送、购买或部署。

状态：**VERIFIED/DOC** 官方当前文档可核；**USER_SCREENSHOT** 用户截图中可见；**PROPOSED** 独立设计方案；**NOT_ESTABLISHED** 官网内部实现、账户权限或效果未证明；**NOT_RUN** 未实施和验收。

## 1. 顶部五类导航的分工

**VERIFIED/DOC** TradingView公共页导航入口为Products、Community、Markets、Brokers、More；官方页面与帮助可核验其目的地。以下是信息架构解读，实际展开内容、排序与点击路径以主任务本轮UI记录为准。[官网](https://www.tradingview.com/)

| 顶部入口 | 用户实际要解决的问题 | 官方目的地/内容体系 | 给LPPL的借鉴 |
|---|---|---|---|
| Products | 我用什么工具完成任务？ | Supercharts、筛选器、热图、日历、新闻等产品类别可在官方站点目录核验 | 按工具/任务组织工作站入口，不按内部后端模块命名 |
| Community | 别人怎么看、有哪些可学习的研究？ | 观点、教育内容、脚本等；观点与针对标的的讨论并非同一形式 | 暂以研究案例与方法文档承接；不为模仿而先建社区发帖体系 |
| Markets | 我想研究哪个市场、哪类资产？ | 市场概览、指数、股票及其他资产入口 | 按对象组织发现路径，点击资产后进入统一工作站 |
| Brokers | 我通过谁执行交易？ | 经纪商列表、可交易资产与评价信息 | 当前LPPL是研究工具，这项不应为了导航齐全而复制 |
| More | 我需要帮助、产品说明或公司信息？ | Help Center为顶栏链接目的地之一，站点还提供功能、订阅与公司入口 | 放使用指南、数据来源、模型方法、更新记录；少用无含义的杂项收纳 |

市场目录与经纪商目录均可在官方独立页面核验；后者属于交易接入生态，不等于图表能力或策略预测能力。[Markets](https://www.tradingview.com/markets/)、[Brokers](https://www.tradingview.com/brokers/)、[Help Center](https://www.tradingview.com/support/)

**设计解读 / PROPOSED：** 这五类分别回答“工具、他人研究、资产对象、执行渠道、帮助”。这是一组不同目的的入口，并不是股票页面的五个重复页签。LPPL应该明确区分全站导航、市场内导航、单资产内导航和图表工具条，避免每层都叫“分析/回测/图表”。

## 2. 截图里的三列菜单为何好用

**USER_SCREENSHOT** 用户截图中，Markets展开为三列：左列列出国家/新闻及资产类型；中列是所选类型的目的地；右列是若干指数行情卡。截图本身的右列主要是名称、数值、涨跌；不能仅据这张截图断言每一行都有可交互走势图。小走势图/悬停详情的实际行为由主任务另行观察。

**PROPOSED / 设计解释：** 左列负责选择研究对象，中列选择查看方式，右列帮助用户预览并直接进入某个标的。用户不必先跳到新页面才能确认“这里有没有我要看的指数”。这可称为带行情预览的多列导航面板，而非普通下拉列表。

它的价值在于减少无效跳转：

1. 左列“指数”代表资产类别，不是最终页面。
2. 中列“主要指数/地区指数”等代表有意义的列表或概览。
3. 右列“上证/沪深300”等资产卡是可直接打开的实体。
4. 顶部Markets仍保持选中，让用户知道自己正在浏览哪一层。

**NOT_ESTABLISHED** 不能从视觉反推TradingView内部使用了哪套组件、什么数据协议，或认为该菜单就是官方widget原样嵌入。我们可实现相似的任务结构，不需要复制其私有实现。

**PROPOSED** LPPL主导航更适合复用已有、允许展示的行情缓存，自绘小型SVG图。官方widget可以作为独立全球行情展示的备选，但不要读取其内部数据后喂入LPPL，也不能把不同来源/复权时点的widget图与本系统模型当作完全一致的数据。

## 4. LPPL一级导航的完整建议

状态：**PROPOSED / NOT_RUN**。以下是统一逻辑方案，实施前与现有路由做映射，保留旧链接，不要求重写框架。

桌面顶栏建议：**品牌 → 市场 → 工作站 → 复盘 → 研究 → 全站搜索 → 自选 → 帮助/账户**。品牌链接进入首页；搜索在视觉上持续可见。

| 一级 | 二级分组及目的地 | 右侧预览 | 默认点击/恢复行为 |
|---|---|---|---|
| 市场 | A股：概览/主要指数/行业概念地域/涨停复盘；全球：主要指数/利率汇率/商品/经济日历 | 与类别对应的4–6张行情卡，带迷你图及asof | 打开市场概览；预览卡打开该资产工作站 |
| 工作站 | 继续最近分析/搜索资产/我的自选/最近分析/图表布局 | 最近标的、上次分析日期和状态 | 有最近状态则恢复，否则资产搜索；不能自动重跑历史 |
| 复盘 | 当日市场复盘/历史市场快照/单资产历史回放/提醒与修订记录 | 最近已封存日期、当前快照状态 | 默认最近完整交易日；不存在历史就明确缺失 |
| 研究 | 顶部时间研究/底部研究/事件规则/模型与优化器对照/研究报告 | 最近研究结果与证据级别，不展示虚假的准确率 | 进入研究目录；高级任务需明确参数与运行操作 |
| 帮助 | 3分钟入门/图表操作/区间怎么读/回放和回测区别/数据与stale/方法与更新 | 对当前页面推荐一篇短指南 | 侧栏帮助优先，必要时打开独立文档页 |

第一版不增加Brokers、下单、社交排行榜、脚本市场或付费试用入口。它们没有解决用户当前“读顶部时间窗和复盘”的主要任务。尚未接通的宏观或概率来源不能在导航中伪装成可用数据；可放研究规划或明确未启用说明。

菜单每列上限建议6–8个主项，更多进入目录页；右列卡片固定尺寸，数据加载不改变菜单宽度。两级已经够用时不要强行做第三列。

## 5. 单只股票页面的二级导航

以贵州茅台为操作示例，统一实体为`SSE:600519`；其映射至既有后端代码由适配层负责，不能把交易所省略。

**PROPOSED** 股票页保留稳定资产头：名称、代码/交易所、最新报价及时点、分析截止日、数据状态、加入自选。其下为：

| 页签 | 主内容 | 和其他页签的连接动作 |
|---|---|---|
| 图表与区间（默认） | K线/成交量、候选顶部区间、六尺度支持、修订记录摘要 | 点事件打开资讯证据；点候选打开研究详情；点日期进入回放 |
| 资讯与事件 | 公告/新闻/财报事件/解禁等，筛选类型、发布日期与已知时点 | “图上查看”保留资产并定位日期；来源原文单独打开 |
| 公司与财务 | 已接通且授权的数据，报告期/公告日/修订状态明确 | 选财务指标可查看历史图；该功能不修改LPPL拟合输入 |
| 资金与结构 | 龙虎榜、融资、资金历史、股东等已获准数据 | 保存描述性事件规则或定位日期；不默认命名为顶部信号 |
| 历史与评估 | 历史回放、首次提醒/修订、阶段顶与局部顶评价 | 从某一失败案例回到当时图表；保留当时已知版本 |

**AI作为上下文侧栏**，不是与财务或新闻重复的一张长页。点击“解释当前区间/为什么没有正式提醒/比较两个候选”时带当前资产、as-of、结果版本和选中候选。回答中的动作直接定位图表。没有底层证据时解释缺口，不能临时编出行情。

一级导航决定任务场景；股票二级导航决定当前资产的研究维度；图表工具条决定表示方式。三层状态互不混用。切“财务”不能丢失当前资产，切“周线”不能改变模型的日线采样，切“市场”也不能悄悄抹掉工作站最近视野。

## 6. 迷你走势图如何实现

以下是**PROPOSED**工程规格，不是TradingView私有实现分析。小型走势图不需要完整K线引擎或重型WebGL。

### 6.1 数据契约

| 字段组 | 必需字段 |
|---|---|
| 身份 | symbol_id、exchange、asset_type、display_name、currency、timezone |
| 报价 | value、previous_close、change、change_pct、quote_asof、session、delay_minutes |
| 迷你图 | period、sampling、adjustment、calendar_version、points:[time,value或null]、series_asof、period_return |
| 证据 | source、fetched_at、status、stale_reason、snapshot_hash、display_permission_status |
| 跳转 | route_kind、symbol_id；历史入口另带mode/asof，不能依靠显示名拼URL |

报价和小图时点允许不同，但必须分别展示或说明；只有日线历史时不要画出假分时。菜单卡显示“近60交易日”就真的用对应日历与日线样本；不要把最近60个非缺失点误当60交易日。

### 6.2 SVG绘制与视觉规则

1. 卡片固定一块约96×32或120×40的绘图区，保留边缘内距；这是建议尺寸。
2. x按真实时间或明确交易日序号映射，y按当前序列范围归一化；缺失点断开，不跨缺口造出连续价格。
3. 全部值相同则画居中水平线；少于2个有效点则显示“历史不足”。不要出现除零、NaN或任意噪声。
4. 默认用折线加很浅的面积。比较涨跌时有明确基准；1日涨跌与60日走势图方向可能不同，分别命名，不拿同一颜色暗示同一个期间。
5. 显示当前值、期间、来源/时点，提供文本替代；图本身不是唯一信息。
6. 选中/悬停时突出边界，不改写历史曲线，不通过装饰动画制造上涨趋势。

### 6.3 请求与缓存

- 菜单先打开静态结构，缓存卡片立即显示；异步刷新不阻塞导航。
- 只请求当前类别4–6个标的，按批获取；每张卡不要独立建立轮询或长连接。
- 同symbol/source/adjustment/calendar/period的行情序列跨首页、菜单、自选复用。private自选列表身份与可共享行情缓存分开。
- 关闭菜单停止无必要订阅；后台页面降频。来源限频、休市与stale逻辑统一，不凭设计稿固定一个“每秒刷新”。
- 快速划过菜单只预加载少量行情；不触发LPPL拟合、不调用104周历史、不启动外部AI。
- 通过请求序号/取消信号避免先选指数后选股票时，迟到响应把预览写回错误类别。

## 7. 桌面悬停、键盘和390px

### 桌面交互状态机（PROPOSED）

`closed → open(category) → preview(item) → navigate`，并允许`open → close`。切换类别只替换中列/预览，不让外框抖动。

- 顶级项目采用真实链接与独立展开按钮，或明确的展开按钮+“查看概览”链接；同一点击不能既跳页又展开导致随机体验。
- hover作为便利，click同样可打开。建议短延迟约120–180ms防止误开，关闭延迟约180–250ms，具体需实测；不是TradingView测得参数。
- 从左列斜向右列移动时保留菜单，不能鼠标经过空隙即关闭。
- Tab按视觉顺序遍历，Enter/Space展开，Escape关闭并回到触发点。普通导航优先`nav`、链接和disclosure语义，不乱加只能方向键访问的复杂ARIA menu。
- 指示`aria-expanded/aria-controls`，当前页面使用`aria-current`；焦点样式和hover同等明显。
- 非模态桌面导航不锁死焦点；点击外部关闭。放大200%和窄桌面时退化为较窄面板，不切掉右列内容。

### 390px替代（PROPOSED）

不把三列压成三条窄缝。顶部保留品牌、搜索、菜单；菜单打开为可返回的单列层级页。点击市场→指数后看到指数列表与迷你图，点击标的进入工作站。最近分析和自选放在第一层。

触控目标至少44px；完整名称可读，报价与涨跌右对齐。没有hover，详情用明确展开/进入。底部抽屉有可见关闭按钮、焦点恢复，键盘弹出不挡唯一返回动作。菜单横向滑动不抢页面纵向滚动。

官方说明正在持续改善widget无障碍，不能因此认为嵌入后的整页已自动通过键盘、读屏和手机验收。[官方无障碍声明](https://www.tradingview.com/widget-docs/accessibility/)

## 8. 路由与跨页面联系

**PROPOSED** 引入一个共享ResearchContext，但不要求把现有静态站重写SPA。先以统一适配器读写URL与当前状态：

`symbol_id / mode(current|replay) / asof / display_resolution / visible_range / selected_cluster / selected_event / result_version`。

路线示例是设计，不是现有已上线接口：

- 市场→上证指数：`workstation?symbol=SSE%3A000001&mode=current`。
- 事件→茅台公告图上查看：同symbol，加event_id及focus_date；普通资讯时间定位不自动切成历史预测模式。
- 研究失败案例→当时回放：显式`mode=replay&asof=YYYY-MM-DD&result_id=...`，先检查当时记录是否存在。
- 菜单→最近分析：恢复原分析版本和视野；若旧数据则显示旧日期，刷新作为独立动作。

全局唯一symbol_id保证卡片、K线、资料和AI一致。敏感会话内容、token和私有笔记不进入URL。浏览器后退恢复原页签、列表筛选、滚动和视野。新资产加载时旧答标旧上下文，不能只换标题仍显示旧内容。

源数据缓存、行情视图缓存、模型结果缓存、生成文案缓存分别按身份与版本管理。图表看过去与模型回到过去不是同一个动作：拖动视野只改变visible_range；真正回放需要asof和历史可知性约束。

## 9. 站内教程如何制作

**PROPOSED** 做任务型指南，每篇用“目标→3至6步→预期画面→失败情况→下一步”，并从对应界面直接打开。不要只有一份几十页大说明书。

| 教程 | 用户应完成的动作 | 成功标准 |
|---|---|---|
| 3分钟看懂一只股票 | 搜索→确认交易所→看行情时点→看候选→定位图上 | 用户能说清研究资产、数据截止日和候选日期 |
| 顶部区间怎么读 | 切候选/尺度→看支持与分歧→看状态 | 不把结构强度理解为顶部概率；近端候选可见 |
| 当前分析与历史回放 | 显式选asof→单步→看当时已知→退出 | 不把后来新闻或修订结果当原预测 |
| 回放、模型评分与交易回测 | 比较三种任务及费用/执行假设 | 不把顶部覆盖率当收益率，不把K线回放当策略回测 |
| 资讯如何影响理解 | 点事件→来源→首次公布→图上定位 | 能区分公告事实、研究解释和模型结果 |
| 为什么没有结果 | queued/current_ready/history_running/stale/失败/无合格拟合 | 能采取重试/看旧结果/查看原因，不以无信号等于安全 |
| 自选与最近分析 | 加入/删除→恢复最近版本→保存视野 | 操作可撤销，重复打开不强制全量重算 |

教程可采用可跳过的局部提示和固定演示样本；不要一次弹七个气泡挡住图表。高级用户关闭后记住偏好。示例数据清楚标注，不与真实预测账本混在一起。

官方参考阅读顺序：先[标的搜索](https://www.tradingview.com/support/solutions/43000746682-symbol-search-find-any-symbol-on-tradingview/)，再[自选列表](https://www.tradingview.com/support/solutions/43000745825-mastering-the-tradingview-watchlists/)，有嵌入需求再读[widget教程](https://www.tradingview.com/widget-docs/tutorials/)。这说明可获得真实操作指南，但LPPL仍需围绕自己的证据状态写教程。

## 10. 最小交付顺序与验收

1. 导航schema与路由映射：旧链接兼容，所有入口指向同一资产身份；先做静态菜单和无数据状态。
2. 市场菜单预览：使用已有行情缓存、时点与stale；迷你图与报价期间清楚，开菜单不启动模型。
3. 股票页二级导航与共享上下文：图表/事件/研究跳转不丢symbol/asof/result。
4. 自选与最近分析恢复：读已有状态，保存视野，防迟到响应串标的。
5. 教程与无障碍：键盘、390px、200%缩放、低带宽和失败状态全部覆盖。

验收至少包括：逐一级/二级项目进入并返回；无鼠标完整导航；屏幕触控无hover仍能完成；菜单快速切换不串数据；节假日日期正确；股票/指数同名不误选；价格和走势图时点不同可辨；两次恢复同版本不重新拟合；旧结果不能伪装实时；未接通来源无假数据；展示页动画不会阻断搜索。
