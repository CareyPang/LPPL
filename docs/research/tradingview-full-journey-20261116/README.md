## 1. 结论

**设计判断：最值得学的是连续的研究路径。** 入口允许按资产找内容、按任务找工具；进入股票后保留身份和报价；图表、新闻、财务与策略报告围绕同一资产连接；报告明细还能把人带回对应K线。这比复制菜单数量、黑白配色或宣传动画更能改善LPPL。

LPPL下一版应让普通用户在同一工作区完成：**找到资产 → 立即看行情 → 看已有顶部候选区间 → 点区间看支持与分歧 → 点事件看来源 → 回到当时复盘**。复杂研究参数和交易模拟逐步展开，不占据第一屏。顶部时间研究继续以完整周期1.5为基线；至少提前5交易日作为评估切片，不能再被误用成隐藏所有0–4日候选的显示门槛。

## 4. 用户截图中的指数和右侧小图

**VERIFIED/UI**：本轮Markets→Indices右列看到的是指数名称、报价、涨跌和延迟标识，没有逐行迷你图。所检查的S&P500卡D提示为延迟10分钟；不能外推全部资产，也不能把D误认日线。

**VERIFIED/DOC**：官方确有[Mini Chart](https://www.tradingview.com/widget-docs/widgets/charts/mini-chart/)、[Ticker系列](https://www.tradingview.com/widget-docs/widgets/tickers/)、[动态标的教程](https://www.tradingview.com/widget-docs/tutorials/iframe/build-page/dynamic-symbols/)和[导航教程](https://www.tradingview.com/widget-docs/tutorials/iframe/build-page/navigation/)。Legacy iframe导航用`largeChartUrl`连接自有页面，选中标的通过`tvwidgetsymbol`传递；新Web Component应使用其对应[链接配置](https://www.tradingview.com/widget-docs/tutorials/web-components/custom-links/)，不能混用参数。

**NOT_ESTABLISHED**：这些公开组件不证明官网mega-menu内部就采用它们。

**推荐实现**：LPPL菜单以已有获准行情缓存生成SVG sparkline，右列4–6张固定尺寸卡，字段含名称/交易所/价格/涨跌/quote_asof/series_asof/source/stale。小图写“近60交易日”，只取该日历范围内真实数据；缺点断线、平盘画水平线、历史不足显示空态。报价与小图不同期间分别命名。开菜单只读缓存、按类别批量刷新，不启动模型，也不为每张卡创建一条连接。

官方widget适合快速做独立展示，但并非可取走的行情API；个人订阅不会自动授予嵌入数据，widget也不接受我们的自有数据。[官方数据FAQ](https://www.tradingview.com/widget-docs/faq/data/)。当前LPPL原生Canvas主图不必为了迷你图整体迁移。

## 5. AAPL策略回测真正走过的步骤

**VERIFIED/UI**：搜索AAPL时先确认NASDAQ，同名/不同市场结果并存；结果行提供Launch chart和See overview。进入1D标准K线，打开Indicators，选择BUILT-IN Technicals的RSI strategy。底部自动打开Strategy Report。

查看Inputs为14/30/70；Properties为初始100,000USD、100% equity仓位、commission0%、slippage0、long/short leverage1x等。Style与Visibility分别控制标记和适用显示周期；没有修改参数。默认报告实际产生214笔已平仓交易，盈利22笔；界面显示净损益−99,969.95USD（−99.97%）及174次margin calls。

这些数值仅用于证明实际跑过该默认模拟。它包含做空、资金与执行假设，且数据调整方式没有独立复算，不能据此判断RSI无效、TradingView不准或LPPL更准。尤其不能把交易盈利率当顶部日期预测准确率。

切到List of trades，找到#214 Short：2017-01-13入场、01-18出场。点击行内出现的定位图标，主图跳到2016–2017附近，出现策略和margin call标记。**这一条“摘要→明细→图上证据”的路径，应该优先用于我们的提醒账本。**

**给LPPL的对应设计**：

| TradingView对象 | LPPL对应对象 | 点击后的行为 |
|---|---|---|
| 策略Metrics | 阶段顶漏报、区间宽度、提前量、首窗偏差 | 进入同一版本的案例集合 |
| List of trades | 逐日预测与提醒／修订账本 | 选中prediction_id与revision_id |
| 定位成交 | 定位原始顶部候选 | 回到当次asof、显示当时区间和证据 |
| Inputs/Properties | 模型设置/评分设置/可选交易模拟设置 | 分开版本，不改草稿就偷换报告 |
| 交易成本与订单模拟 | 后置可选策略模块 | 先定义入退场、仓位、费用、A股约束才有收益曲线 |

官方新版名称为Strategy Report；旧教程常用Strategy Tester。策略添加和报告入口以当前UI为准。[官方操作指南](https://www.tradingview.com/support/solutions/43000764138-tradingview-strategy-report-how-to-start/)、[逐笔定位指南](https://www.tradingview.com/support/solutions/43000681737-list-of-trades-tab/)。

## 6. 单资产页面的组织逻辑

从图表右侧公司链接打开股票概览，仍是NASDAQ:AAPL；全站一级导航不变，单资产二级导航切换研究维度。第三层只在相关模块出现，例如Financials内的Overview/Statements/Statistics/Estimates/Dividends/Earnings/Segments。**导航有层级，但每层只回答一个问题。**

本轮已观察到：

- 财务Statements：图表在上、报表在下；年/季切换同时改变图和表，URL保留`statements-period=FQ`。旧年数据Locked明确呈现，不填0。向下滚动，资产头压成小行情条并保留See on Supercharts。
- Filings：按年度组织财报/公司事件卡；Earnings筛选会实际去掉产品发布等非财报卡；文件类型8-K/10-K等作为可识别入口。
- News：Key facts与Latest news分开；摘要有来源，新闻列表按时点、标题、来源排列，并有财报/分红/回购/并购/内部人/分析师分类。
- Community：围绕这只股票的图表观点卡和Minds，不等于官方事实或信号。
- Technicals：日线切周线，三个分组的汇总指针与计数随之变化；这是所选周期的指标判断，不是下一次顶部时间预测。
- Forecasts：过去价格与1年分析师目标以视觉边界分开，Max/Avg/Min及分析师数量清楚。这里的价格目标范围不是LPPL tc区间，也不是校准的置信区间。
- Seasonals：不同年份曲线和月度热表可互切；数据展示模式在URL留痕。历史规律不自动成为未来预测。
- Options：Call/Put分两侧、行权价在中间；到期筛选同时给具体日期与DTE。缺失Bid/Ask用空值，不当0价。本轮仅查看，没有构建或交易组合。
- ETFs：不是全市场ETF目录，而是“持有这只股票的基金”；从概览切Fund flows后，列变为1M/3M/1Y/3Y/YTD，保持同一组关联对象。
- Bonds：同一发行人的债券，按收益率、票息、到期日、金额和评级组织；本轮点击到期列表头未观察到重排，不计排序成功。

其余页签访问结果见实操日志，不把点击后尚未加载的旧页面误认成新页面内容。

## 8. 交互、色彩、留白与动效

以下为**独立设计提案**，不是从截图精确测出的TradingView CSS。

| 项目 | 可落地规格 | 为什么 |
|---|---|---|
| 页面底色 | 暖浅灰`#F7F8FA`，内容面`#FFFFFF`，正文`#182230`，次要正文`#536176` | 降低沉闷感，保留行情对比度；具体对比度实施时测 |
| 操作色 | 蓝`#315CF5`用于选中/链接/主动作；不承担涨跌含义 | 操作与市场状态互不混淆 |
| A股涨跌 | 默认红涨绿跌，可切习惯；同时保留正负号与文字 | 颜色不是唯一信号；国际截图的绿涨红跌不能照搬 |
| 模型时间带 | 主候选蓝紫浅填充，次候选虚线；选中高亮边界 | 不以绿色表示“安全”或红色保证“卖出” |
| 状态 | stale琥珀、失败暗红、待算中性、已完成蓝色文字标签 | 有结果不等于预测已验证；不滥用绿色对勾 |
| 字体 | 正文14–16px、数字tabular-nums、分层标题18/24/32px | 报价跳动不改列宽，研究阅读和表格扫描兼顾 |
| 留白 | 4/8/12/16/24/32节奏；图表页压缩头部，首页扩大呼吸空间 | 营销页与工作区密度分开 |
| 微交互 | 按钮120–160ms；面板160–220ms；图表定位短平移并可减弱 | 动效表达选中、进入、定位和更新 |
| 图表交互 | 十字线与量能同日；拖动/缩放保留日期；事件点开证据；候选卡↔时间带双向联动 | 每次操作都有可解释反馈 |
| 首页动效 | 一个轻量主视觉围绕“聚合→时间带→图表”展开；搜索和案例一开始可用 | 保留惊艳感，但不再滚过长段空白才能进入功能 |

首页可做抽象曲线逐步收束成顶部候选时间带，最终变成真实工作站预览；动画只是示意，清楚标演示。仅在进入视口时播放，reduced-motion替换为静态状态。工作站不用持续移动背景、自动轮播研究对象或声音。当前首页动画逐帧性能没有在本轮重新测量，不据此宣称已达奖项标准。

## 9. 易被忽略的连续性要求

**PROPOSED**：统一ResearchContext保存symbol/exchange、mode、asof、result_id、selected_cluster/event、显示周期和视野。URL仅保存可公开恢复的状态，私有对话与token不能进入URL。

1. 切股票页签不丢资产；返回市场保留原筛选；浏览器后退恢复位置。
2. 事件“图上查看”只定位日期；“回到当时”才进入历史证据模式。图表滚到过去不等于当时可知回放。
3. 当前报价、分析截止、首次用户可见时间分别显示。网站切到历史图但右栏仍是今日行情时，应明确标记或折叠今日栏。
4. 1M/6M是可见范围，日/周是显示聚合，LPPL窗口是拟合样本，评估asof是证据时点，四者不得共享一个含混“周期”开关。
5. 导航和信息页只读缓存；历史任务按需；当前计算不中断行情；历史失败不清空当前结果。快速A→B切换时拒绝旧响应覆盖新资产。
6. 价格图未来只能扩展时间槽，不能生成假K线；未来候选跨节假日必须依交易所日历和原始tc单位映射。
7. 候选强度、tc区间、历史实际效果分开显示。统计支持占比不是顶部概率；分析师目标价、技术评分和资讯不能悄悄喂进LPPL。

## 10. 教程和实施次序

教程直接放在任务旁：每篇3–6步、预期画面、常见失败及返回原位置；首次引导可跳过。“一分钟看一个候选”“公告如何定位”“如何区分观察/正式提醒”“回放与回测”“为什么暂无结果”优先。先给上证和茅台固定示例，包含一个失败/修订案例，不只展示命中。

实施按三个交付包推进，详细任务、依赖及反例见DEVIN_PLAN：

1. **核心正确性与一只股票闭环**：身份/时间/日历、行情与计算异步、主K线的候选区间、提醒账本联动；保持旧入口兼容。
2. **统一导航与信息联系**：一级菜单、市场预览、股票页签、公告与资金页、历史模式、上下文AI；自选和最近分析恢复。
3. **视觉与教程综合复验**：首页主视觉、390px、键盘/低带宽/stale/错误、按用例记录真实耗时与截图；后置可选交易模拟。390px和键盘按D10随每个组件同步验收，本包再做完整路径复验，不推迟到最后才考虑手机。

设计包可并行，正确性契约先于上线。当前main源码已有部分异步状态、自选、市场卡、指数区间图层等，任务应做差异整合，不把所有能力都重新实现。源码对照详情见同PR上一份[图表引擎核查](../tradingview-experience-review-20261116/chart-engine-notes.md)。本轮没有把Devin未合并分支当成已上线。

## 10.1 专业评价：可借鉴的优点与不宜照搬的地方

| 维度 | 优点（基于本轮观察的设计判断） | 局限与LPPL应对 |
|---|---|---|
| 导航 | 工具与资产两条发现路径，搜索可直达图表，股票内再按研究维度划分 | 入口多、11个单股页签对普通用户负担大；LPPL收敛至5个业务页签，单资产页默认图表与区间，回访可恢复最近工作站 |
| 信息层级 | 大标题确认对象，滚动后紧凑行情条保留身份；三级选项局部出现 | 本次部分页面重复显示大头部和右侧报价，占较多空间；LPPL工作区压缩资产头 |
| 图表与结果 | 指标/策略/属性分层，报告明细定位历史K线形成证据路径 | 只读总收益很容易忽略仓位、空头和保证金假设；LPPL模型评分优先且保留配置摘要 |
| 状态 | 盘前、Limited data、延迟D、历史Locked、缺失报价都可见 | 图表历史视野与右侧今日行情能同时存在；LPPL显式历史模式及双时点 |
| 表格 | 年/季、图/表、ETF列组切换，保持资产和比较对象不变 | 高密度小字与横宽表在手机会有成本；390px以摘要与展开明细替代全表压缩 |
| 视觉 | 白底、黑标题、细分隔、克制强调；研究数据承担主要视觉重量 | 买卖仪表盘容易使普通人把汇总看成确定结论；LPPL用支持/分歧条、日期带、证据标签 |
| 动效 | 已观察到的有效反馈集中在菜单展开、选中、加载、数据视图切换 | 光标蓝光不是网站效果；本轮无帧率测量。LPPL不以背景动效挤占研究空间 |
| 响应与可用性 | 模块有局部加载、自选和上下文保持 | 本会话多次路由已变化但旧内容短暂保留或白屏；不归因整体性能，但LPPL应以加载骨架/旧版标识防误读 |
| 生态 | 单股关联新闻、文件、脚本、ETF、债券，扩展研究路线 | 完整生态带来维护、许可和账户成本；不能仅复制UI宣称具有同等数据深度 |

本轮不是TradingView全产品无障碍审计或性能测试，因此不给伪精确的95分/获奖等级。评价重点是能复现的用户任务、相应设计收益和已观察到的限制。

## 11. 完成定义

不是“页面像TradingView”，而是用户从市场菜单选择上证/搜索茅台后，能立即使用行情，看到有明确日期和状态的候选，定位证据与修订，回到当时且不混未来信息；重新打开可恢复、失败可解释。全程无需先读论文，也不必等待104周历史计算。

每条验收记录入口、操作、预期/实际上下文、数据版本与PASS/FAIL/NOT_RUN。任何串标的、串时点、节假日映射错误、旧成绩冒充新参数、近端候选被硬隐藏，都应阻断交付。好看的动画不能抵消这些错误。
