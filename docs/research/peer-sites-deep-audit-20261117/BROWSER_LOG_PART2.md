## 需要保留的证据边界

1. **发布日不等于经济所属期。** 日历中“今天发布”不能被写成“今天的失业率”。Reference 指向经济统计覆盖期；发布时间与观察期必须分列。
2. **Actual、Previous、Consensus、TE Forecast 是不同对象。** 本次确认界面做了区分，尚未建立其来源、调查样本、修订历史与时间戳的完整可追溯性。不能把产品预测替代缺失的市场共识。
3. **历史与预测的视觉分界不证明预测准确。** 灰色未来柱、蓝色历史柱有助阅读，只是表达设计；预测有效性需要另行验证。
4. **ONS 名称是本轮看到的来源标注。** 本轮没有完成官网原始发布、时间戳和版本的逐项对照。
5. **公开访问与网站再展示授权是两件事。** 此日志没有确认抓取、保存、派生统计或商业展示许可。

## 对 LPPL 的具体设计增量（PROPOSED / NOT_RUN）

### 1. 把宏观日历做成研究路径的一环

建议路径：`市场概览 → 今日事件 → 指标详情 → 来源／历史发布 → 返回原日历位置`。点击宏观事件时保留原筛选、日期、时区与滚动位置；不用打开一张丢失上下文的孤立卡片。

第一版保留“今日、最近、本周”与按国家／重要性筛选。未授权或未封存的历史范围明确不可用；不能用最新资料拼接历史事件。

### 2. 统一指标详情结构，不混入 LPPL 计算输入

指标详情可采用 `概览 / 历史发布 / 图表 / 来源` 四个面向普通用户的入口；统计、共识和外部预测按真实数据覆盖逐步开放。不要为模仿竞品而复制七个空页签。

宏观卡片与新闻属于信息背景。引用它们解释行情时要指出来源和时点，不自动改变 LPPL 拟合数据或候选区间。

### 3. 明确“一个数值属于哪一期、何时发布、何时被看到”

每次发布至少关联：

- 指标与定义版本；
- 观察期／Reference；
- 原始发布时间及其时区；
- 当次 Actual、当时已知 Previous；
- Consensus 与外部预测的独立来源、形成时间；
- 本次发布／修订版本；
- 系统抓取和首次可见时间。

如果显示前值修订，明确分开“当时公布的前值”和“后来修订的前值”。切换历史回放时不能用最新修订值覆盖当时所见。

### 4. 颜色承担明确语义

历史观察与未来预测使用不同填充、虚实线或背景区，并附图例；不能仅依赖颜色。LPPL 候选顶部区间也需要可见的未来区域边界、区间日期和结果状态，不应与历史实际高点标记混为一体。

报价红绿只用于价格方向；预测与观测的区分、stale 与失败状态用独立标记。

### 5. 逐行展示日期，避免“全页统一最新”的错觉

市场矩阵中逐行 Date 值的做法值得保留。LPPL 市场卡片若来自不同收盘时间或不同数据源，应逐项展示实际 as-of；页面刷新时间不能冒充每项行情的数据时点。

### 6. 错误状态只影响对应模块

本次 News 超时提醒我们：新闻请求失败时，行情、日历与当前拟合结果仍应可用。失败模块给重试和上次成功时间；不因一个来源失败阻塞整个工作站，也不把“无数据”写成“无事件”。

### 对 LPPL 的可用借鉴（PROPOSED / NOT_RUN）

1. **一个事件，多个资料入口。** 同一财报／公告事件下组织概览、原文、演示材料和相关图表，保留共同的 `event_id`、报告期和发布时间。不要让相同事件在“新闻、公告、AI、复盘”里变成四份无法互相追溯的内容。
2. **AI 与原文并排，并能精确定位。** 先实现“问题与答案 → 引用片段 → 原文页码／段落或表格单元格”的验证路径。引用一个相关标题或整篇链接不足以支持具体金额、同比或日期判断；应显示所用版本与报告期。
3. **记录材料缺失，而不是制造完整感。** 只有公告时显示公告；没有电话会、幻灯片或授权全文时，不造空的可用页签，更不能让 AI 根据标题补写正文。
4. **聚焦事件资料，不复制全套终端。** 音频与逐字稿同步、自定义查询、全市场内容订阅可后置。LPPL 先把已有行情、模型区间、公告及宏观发布关联到同一时间轴。
5. **品牌页与研究区各有重点。** 官网可以采用清晰留白、单个产品主视觉和少量主要入口；实际工作站需要稳定布局、明确状态及低干扰反馈。Quartr 的公开展示图不能作为其终端交互已验证的依据。

### 对 LPPL 的具体借鉴（PROPOSED / NOT_RUN）

1. **每天先给一份有结构的摘要。** 首页或市场概览可以按“市场表现、今日事件、自选相关、模型区间变化”排列摘要，各项能跳回资产、事件或原始结果；摘要不是未经支持的因果解释。
2. **快讯与研究上下文关联。** 从 A 股／行业／自选分类进入资讯，保留资产和日期上下文；在工作站中选择事件时，同步定位 K 线时间，而非将全文无限堆在图表下方。
3. **新消息不抢走阅读位置。** 用户正在阅读旧消息或展开事件时，新到消息只更新“新增 N 条”提示。由用户主动插入或返回最新；不能自动滚到顶部、移动正在点击的行或清空筛选。
4. **示意与真实数据明确分区。** 示例卡使用统一的“示例／非当前数据”角标和视觉容器，真实卡必须显示 as-of、来源和状态。仅在卡片角落写“参考示意图”不足以避免与实时数字混淆；LPPL 不应在同一结果列表中混排未标清的模拟区间与真实预测。
5. **不同金融字段使用独立定义。** 融资余额、融资买入额、融资净买入不是同一量；ETF 持仓、份额变化、净申购和二级市场资金流也不能混用。每张卡关联指标 ID、单位、计算窗口、来源与版本，AI 解释复用相同定义。
6. **许可与功能展示分开。** 看到公开卡片或开源接口不代表取得再展示和 AI 使用授权。J10 的声明应作为逐源核验的线索，不能据本轮观察直接接入生产抓取或把资讯送入 AI；最终以对应数据源的完整条款或实际授权为准。
7. **减少跨站点式跳转成本。** 金十多个主入口另开标签，能保留原页但也增加管理成本。LPPL 内部主功能优先在统一应用壳内切换，外部来源才明确另开；用户返回时仍保留筛选与所选区间。
