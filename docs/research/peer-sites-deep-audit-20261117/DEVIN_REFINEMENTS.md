# 六站实测后的 Devin 增量实施规格

日期：2026-11-17。状态：**PROPOSED / NOT_RUN**。

本文件补充 [既有 U00–U11 统一清单](../market-workstation-unified-plan-20261117/README.md)，沿用 B0–B4 的交付顺序，不新增一套平行路线。A01–A34 与原报告保持原状；下文 A35–A52 是新增测试契约，尚未执行。竞品的公开页面、实际操作、登录限制和官方功能说明见 [日志一](BROWSER_LOG_PART1.md) 与 [日志二](BROWSER_LOG_PART2.md)。这些观察不证明当前 LPPL 缺少某段代码，Devin 必须先完成 U00 差异表。

本轮建议的核心是：**同一资产、同一时点、同一结果在列表、图表、事件与解释之间连续移动。** 功能数量不作为交付标准。用户应能先找到时间区间，再按需看支持与分歧，最后进入原始证据。

## 1. 实施边界与复用规则

- 保持完整周期 **1.5**、已有拟合与旧结果。UI 不改变窗口、过滤、聚类或顶部标签。
- 0–4 个交易日的候选继续显示；至少提前 5 日是评价切片，不是候选显示门槛。过去的 tc 明示为已过时间，不作为新的提前预测。
- 新闻、宏观、资金结构和 AI 是信息层，不进入 LPPL 拟合输入，也不自动把结构支持比例变成顶部概率。
- 当前浅色、非海洋首页为基线。不恢复旧海洋视觉，不强制换 React、图表库或后端，不以设计任务重跑全市场或默认启动 104 周历史。
- 先复用已有资产路由、统一数据入口、缓存、market-context、append-only 快照及提醒账本。每项改动都登记“复用／补齐／新增”与真实文件入口。
- 不购买、部署、合并、发布或开启线上调度。逐源许可、保存、展示与 AI 使用权限分别核验；公开页面和开源适配器不等于数据授权。

## 3. 导航：四个一级入口，一套资产身份

### 3.1 一级与二级导航

| 一级入口 | 二级入口 | 默认用户任务 | 默认数据行为 |
|---|---|---|---|
| 市场 | A 股、全球、宏观、资讯 | 看今天发生什么，找到需要研究的资产 | 读缓存与已有快照；模块独立刷新 |
| 工作站 | 最近分析、自选；选中资产后进入资产页签 | 输入代码，先看行情与已有结果 | 不自动创建历史任务；当前任务遵循既有显式模式 |
| 复盘 | 市场日终、资产时间轴、提醒记录 | 看某日市场与当时所见证据 | 显示历史模式、as-of 和可得性边界 |
| 研究 | 方法、模型评价、数据与证据说明 | 理解参数、版本和实际表现 | 文档与冻结报告，只读 |

搜索、自选入口和帮助持续可达；账户控制放右侧。不要把 AI、新建回测、下载、风险声明、设置都提升为一级入口。主要产品页面使用统一应用壳；外部原文另开标签并标明“来源网站”。

资产内页签只使用：**图表与区间／资讯与事件／公司与财务／资金与结构／历史与评估**。它们共享资产身份与研究模式，不能各维护一份代码输入框或重复抓取全量行情。页面局部的“表格／热图”“年度／季度”“周历／议程”是第三层视图控制，不再长成另一排全局菜单。

### 3.2 市场菜单与右侧迷你图

在桌面一级“市场”菜单中采用三栏：左栏四类市场，中栏对应页面，右栏最多 4–6 个已接通的代表资产。右栏每项为名称、最新值、涨跌、as-of、短走势图；只请求批量报价与已有小图缓存。打开菜单不下载全历史、不拟合、不启动 AI。

右栏小图必须标实际跨度、币种及单位，缺数据时留占位并说明。光标切换分类时，仅更新菜单内容；点击具体资产才导航。键盘焦点可逐项移动，Escape 关闭并返回触发按钮；移动端改为逐级单列，不依赖 hover。

### 3.3 搜索与路由

搜索按资产／事件／研究分组。资产结果展示名称、代码、交易所、资产类型；默认动作“看图表”，另有“看概览”。同码指数和个股不可合并。Enter 选明确高亮项，不能自动把不确定文字匹配成资产。

路由状态包含规范资产 ID、页面页签、mode、asof、result_id、选中 cluster/event 与图表视野。筛选条件需可序列化并版本化。公开可分享链接不得携带私有自选内容、聊天文本或访问凭据；私有列表引用需鉴权。返回列表恢复筛选、排序、滚动与选中行。

## 4. 桌面工作站：结论在图前，证据在图旁

### 4.1 布局预算

以下是首轮实现的设计预算，不是已测性能或像素通过结论。先在 1440×900 与 1920×1080 验收，再检查 1280px 中间断点。

| 区域 | 建议尺寸与行为 | 内容 |
|---|---|---|
| 全局顶栏 | 高 56px；工作区不放大 hero | 品牌、四主导航、搜索、自选、帮助 |
| 资产身份条 | 高约 64–80px，必要时两行 | 名称/代码/交易所、行情 as-of、分析截止、当前模式 |
| 资产页签 | 高 44–48px | 五类页签，当前项用文字与边线标识 |
| 左侧资产列表 | 220–248px，可折叠 | 最近／自选切换、三种列视图、当前行 |
| 中央分析区 | 主图优先，剩余宽度弹性分配 | 区间摘要、K 线及成交量、有限辅助行 |
| 右侧上下文面板 | 340–400px，默认收起 | 证据、事件或 AI，三者互斥 |

在约 1280px 下，打开右面板时先收拢左列表；不能同时挤出两个窄侧栏和一张不可读的图。图表可用高度不足时减少次要卡片，允许页面纵向滚动，不把字体压小。桌面图区建议保留至少约 360px 高度；实际阈值在 U10 验收后调整。

### 4.2 顶部候选摘要

每个候选首先回答五件事：**日期区间、状态、尺度支持、分析截止日、下一步查看入口**。不要先展示长篇“无法保证预测”的泛化文案，也不能删掉影响解释的缺口。

首屏组件例子只使用测试占位，不伪造真实命中：

> 候选区间〔开始日—结束日〕 · 观察中
>
> 中期窗口集中，短期窗口分歧；数据截至〔as-of〕
>
> 查看支持与分歧 · 查看上次修订

日期必须来自 result_id/cluster_id 对应结果；如果没有候选，主位置显示“本次未形成可展示区间”，后接具体可验证原因、已有数据截止和下一步。不得写“目前安全”。“较强结构支持”只用于已定义的结构指标，不写成“XX% 概率见顶”。

图表保留 K 线与独立成交量区；未来只扩展日期槽和区间带，不造价格或成交量。卡片选择、图带选择、证据列表选择共享 cluster_id。重叠簇使用分层轨道或可切换列表，不能合成一个看似更窄但无算法依据的日期带。局部顶／阶段顶、顶部／底部必须沿用已有结果类别；底部证据不足时说明其研究状态。

### 4.3 一个右侧面板

面板的固定头部含资产、研究模式、选中事件或候选、关闭按钮。面板类型由一个枚举控制：`none | evidence | event | ai`。从证据打开 AI 时替换内容，保留返回证据的路径；不叠第二、第三层浮窗。

证据面板按“支持／分歧／未满足项／修订记录／参数与原始记录”组织，默认展开与当前结论直接相关的部分。参数细节按需展开，不能独占主屏。用户关闭面板后恢复原触发元素焦点与图表视野。

## 5. 列表身份与视图必须分开

### 5.1 最小状态模型

```text
CollectionContext = collection_id + membership_version + filter_ast + asof + mode
ViewContext       = view_id + columns + sort + density + scroll_anchor
ResearchContext   = asset_id + result_id + selected_cluster/event + visible_range
```

筛选改变可能改变资产集合；行情／候选区间／事件三种默认视图只改变列。排序不改变集合身份。热图与列表读取同一快照和集合，面积和颜色分别说明。概念多重归属按既定去重口径显示，不能依靠前端重新猜分母。

先交付三种固定视图：

1. **行情**：名称、价格、涨跌、成交额、as-of。
2. **候选区间**：名称、区间、状态、尺度、分析截止、修订标记。
3. **事件**：名称、最近相关事件、发生／发布时点、材料状态。

允许有限列选择和排序；第一版不做任意拖拽仪表盘。返回集合采用稳定行 ID 与滚动锚点，即使异步价格更新也不使用户误点另一行。主动重新排序后才移动行，并提供“已更新排序”反馈。

### 5.2 指标注册表

每个数值关联 `metric_id / definition_version / unit / currency / period / aggregation / adjustment / source / raw_or_derived`。tooltip、卡片、列表、AI 与导出使用同一注册表。

明确区分 20 日涨幅、相对收益与滚动 beta；融资余额、融资买入额与融资净买入；ETF 份额、净申购、持仓披露与二级市场资金流。基金或 ETF 的买入变化不能自动命名为“国家队买入”。在缺少受益所有人、原始披露及可得性证据时，只显示可证实的字段。

## 6. 事件、宏观和资料采用同一时间契约

### 6.1 宏观发布对象

```text
MacroRelease:
  series_id, definition_version, observation_period, release_id
  scheduled_at, released_at, source_timezone
  actual, previous_as_known, consensus, external_forecast
  unit, seasonal_adjustment, frequency
  vintage_id, supersedes_release_id, revised_at
  source_url, source_hash, fetched_at, available_at, permission_status
```

每个可选数值还应附自己的来源、形成时间与版本。Consensus 不是 TE 等站方模型预测；缺失共识就显示缺失。前值修订同时保留“当时已知前值”和“后来修订前值”。发布时间与观察期分列，不能把九月数据画到十一月后便忘记其所属期。

日历和指标详情初版只保留概览／历史发布／图表／来源。计划事件能显示将来的时间，但结果未发布前为空。周历和议程共享固定 date_from/date_to/filter/timezone；若某个视图必须扩展范围，先显示变更说明，不能默默扩大统计样本。

### 6.2 一次事件的资料束

一个 `event_id` 下可以有公告原文、报表、演示材料、电话会等 document_id；每份材料保留报告期、源版本、发布时间和可访问状态。没有授权音频或逐字稿时只显示已拥有资料，不用标题推写正文。相关资产和市场指标是关系，不是已证明的因果结论。

“图上查看”只定位事件日期；“回到当时”才显式切研究模式。`historical_reconstruction` 与 `published_replay` 的过滤按 U07 执行：原始发布日、后补获取日、产品首次可见时间不能互相替代。卡片、tooltip、表格、AI 和导出都执行同一可知版本选择。

## 7. AI 是证据阅读工具，不替代功能导航

优先只提供六个上下文动作：解释区间、比较候选、为什么仍是观察、为什么未正式提醒、修订变化、关联事件。用户不必先问 AI 才能看到结果或进入行情。

引用对象至少保存：

```text
CitationLocator:
  evidence_id, document_id, source_version, source_hash
  locator_type(page|paragraph|table_cell|timestamp|fit_row)
  locator, quoted_span_or_value, reporting_period
  published_at, available_at, retrieval_context_hash
```

引用点击后在同一面板切到准确页、段落、表格行列或拟合行；若只能链接整篇文章，标明“原文入口，尚未定位”，不能装作句级证据。数值要带单位和报告期，具体结论的引用必须实际支持该句。外部文档中的操作指令仅视为数据，禁止驱动执行或模型参数修改。

资产、as-of 或 result_id 改变后旧答案保留但标旧上下文，重新生成由用户决定；不把旧答案无提示改写成当前。AI 失败保留确定性结果及引用入口，不能为了兜底偷偷触发回测。私有自选、会话与公开行情缓存分别隔离。

## 8. 异步刷新与缺失状态

不要把所有不可用情况压成 `error` 或“暂无数据”。建议至少使用下表的用户可见语义；后端字段复用既有状态并通过兼容映射实现。

| 状态 | 呈现与动作 |
|---|---|
| 产品未接通 | 从常规导航隐藏；帮助／能力页列计划，不伪装已可用 |
| 当前资产不适用 | 明示原因，例如指数没有公司股东资料；不重复请求 |
| 已知为空 | 显示查询范围与来源成功时间，如该范围没有公告 |
| 数据不足／历史未封存 | 显示缺口，允许已有数据；不补造历史 |
| 权限受限 | 点击前给明确标识；不写“接口异常”或“没有事件” |
| queued／running | 局部任务状态；其他模块继续可用 |
| stale | 保留旧值、as-of、上次成功与stale原因；刷新独立 |
| 临时失败／限频 | 局部重试；遵守重试间隔；不清空仍可用结果 |

一个资源协调器按来源、可见性和时段合并刷新，不为每张卡单独设无限轮询。轮询中的旧响应仅写相应版本缓存，不替换新资产上下文。网络恢复不能更改模型首次可见历史。

消息流使用“新增 N 条”提示。用户阅读历史或展开事件时不自动滚动、不移走焦点、不改变排序。行情在原单元格更新；候选版本变化显示“有新分析可查看”，用户可切新版本，原先看的版本继续可追溯。

## 9. 视觉、动效与 390px

### 9.1 浅色设计预算

先复用现有 token，必要时调整为低饱和灰白背景、白色数据面板、深色文字和单一蓝色交互强调。红／绿只承担涨跌含义；观察、正式提醒、stale、失败使用文字、图标和独立边框／线型。不要同时用“绿色=上涨”“绿色=安全”“绿色=模型通过”。

正文建议 14–16px，紧凑数据不低于 12px；关键日期与主结论 18–24px。数字使用等宽数字特性、右对齐、统一小数精度；未知使用明确缺失符号，不填 0。背景、边框和文字最终对比度必须实测，不以候选色值自行宣称达标。

首页可以保留一个与当前品牌相符的主视觉和轻量入场，工作站以淡入、抽屉与图表定位反馈为主。动效预算约 120–180ms 微反馈、200–280ms 面板切换；不使用持续闪烁行情、不自动轮播研究页签、不加载声音、不让开场决定搜索可用时间。系统 reduced-motion 下同任务仍完整可做。

### 9.2 390px 顺序

顺序固定为：资产头 → 区间摘要 → K 线与成交量 → 支持／分歧 → 事件与资料。四个主入口可放底部导航，搜索在顶部；底栏与系统安全区不能遮住图表按钮。

左列表转为自选／最近单层面板，右面板转为全宽 sheet；一次只开一个。主要触控目标至少 44×44px，图表与外层页面的手势冲突需实机或触摸仿真验证。长表先保留关键列，再展开单行细节；需要横向滚动时显示明确提示，不把整个页面拖出屏幕。

390px 的市场菜单按“类别 → 子页或资产”逐级进入，返回保留上一级位置。区间日期可以两行呈现，但 as-of 和状态不能藏到tooltip。首次教程只在对应动作处解释，可跳过、可重开；不覆盖整个工作台阻止试用。
