# 提醒边界与等次数单项对照：仍未证明阶段顶部提醒有实用价值

日期：2026-11-06。执行前协议提交：`0f3d0d5d21a0568c45235bcc13f6f5a788da7260`。证据：[claim-boundary-20261106/v1](evidence/claim-boundary-20261106/v1)。完整周期下限始终为1.5。

**VERIFIED（已消费开发资料上的条件性算术）：新整数日期宽度可增加满足正式门槛的候选，但在相同资产、同一提醒日期、相同提醒次数下，没有提高本次阶段首条命中。稀疏取窗没有胜出，跨尺度门槛在配对比较中少命中1个事件。每组仍包含同一91个阶段顶。**

**NOT_ESTABLISHED：阶段顶部预测已实用、能稳定提前5交易日、最优时间窗/聚类阈值、真实发布效果。此次结果不能支持把新模型切换到生产。**

## 1. 已落地的四种边界

新增独立研究状态机 `research/eval/top_time/claim_boundary.py`，没有修改旧评价器或生产门槛。

| 含义 | 仅依当前及过去记录的规则 |
|---|---|
| 早期观察 | 当前有拟合区间，但超出行动日起63观测日，或含端点宽度超过10日；保存完整区间与原因 |
| 非正式观察 | 已非未来，或整窗不足5日提前；明确不称为“早期”，也不丢为无信号 |
| 正式区间提醒 | 含端点1–10日，起点距假想下一观测日至少5日，终点不超过行动日后63日 |
| 修订/新提醒 | 首个正式提醒开启episode，原终点固定为有效期；到期前正式输出是修订，到期后才是新提醒。修订不延长旧有效期，观察不占用正式episode |

每次正式输出（含修订）均计一次通知。保留观察数量和观察内容；正式门槛通过只表示区间几何合规，不保证它包含峰日，也不等于已自动区分局部与阶段。

新“首次可见正式主张”评分允许每次已经可见的正式输出参加该事后事件最早主张的选择，包含修订；线上episode及父记录不改，事后target只进入评分。对同一事件，较早错误仍不能被后来正确修复。无事件、未知锚点、超边界处理沿原评分器。

以下输入区间、通知次数和顺序完全相同，只把“episode首条才有资格”改为“每条可见输出都有资格成为事件首条”；尚未过滤正式门槛，也没有改模型。

|---|---:|---:|---:|
| 6–12月参考档 | 1 | 1 | 442 |
| 12–24月参考档 | 0 | 0 | 304 |
| 两档并集 | 0 | 0 | 656 |
| 四档并集 | 0 | 0 | 1,136 |
| 四档稀疏并集 | 3 | 1 | 1,051 |
| 任意尺度密集簇 | 2 | 2 | 770 |
| 跨尺度簇 | 0 | 0 | 258 |
| 稀疏跨尺度簇 | 1 | 1 | 224 |
| 跨尺度连续两次确认 | 0 | 0 | 69 |

VERIFIED：修改首次性语义并未普遍提高TP。此前查到较早合格修订，不代表它在所有更早可见输出中一定最早；更早的错误主张仍可能先占事件。四档稀疏方案反而由3降为1。不能把协议边界问题宣传为“评价器修复后模型很准”。

完整表另列“新状态机+原episode-first”和“新状态机+正式可见-first”，把门槛与episode组织变化和评分变化分开。没有改写上一轮0–3/91成绩。

## 3. 单项模型生成：自然输出的完整代价

四条模型臂均从同一旧拟合重建；连续宽度原臂的4,236个计划资产扫描已逐日核对原可用状态、报警状态、选中簇ID和区间一致。整数日期臂在候选生成时检查 `ceil(hi)-floor(lo)+1≤10`，不事后裁剪旧宽簇；取窗和跨尺度各只改一项。

下表采用新正式门槛与“首次可见正式主张”计分。每臂事件分母91；FP表示未满足本研究联合合同的成熟主张，**不是随后没有下跌、不是交易亏损次数**。P与通知数可能因评价边界不同而略有差别。

| 方案 | 正式通知 | 早期观察 | 非正式观察 | TP / FN | P / FP | 成功事件提前量 |
|---|---:|---:|---:|---:|---:|---|
| 原连续宽度、全窗口、任意尺度 | 305 | 318 | 147 | 2 / 89 | 305 / 303 | 45、63日 |
| 整数日期宽度、全窗口、任意尺度 | 505 | 119 | 142 | 3 / 88 | 501 / 498 | 45、54、63日 |
| 整数日期宽度、固定稀疏窗口 | 251 | 15 | 106 | 2 / 89 | 251 / 249 | 23、49日 |
| 整数日期宽度、全窗口、跨尺度 | 174 | 0 | 73 | 0 / 91 | 174 / 174 | 无 |

VERIFIED：整数日期生成端使200条原本不能正式发布的候选变为正式输出（自然输出305→505），但增加通知后只多命中1个阶段事件；这不是等成本改善。新整数full_any仍有43个阶段事件无首条、30个窗口偏早、15个偏晚、3个命中。跨尺度为62个无首条、22个偏早、7个偏晚、0命中。

原连续、整数full、整数thin、整数cross的正式修订数分别170、352、150、97；事后重复事件主张分别63、140、66、42。关联未来H63内无已知事件的成熟正式记录分别197、313、152、103。错误原因可以重叠，不能横向加总为通知数。

观察也没有隐藏：四臂全部信号输出分别770、766、372、247条。按“某观察有下一条信号，下一条已转为正式”的相邻转换定义，分别为120/460、83/258、45/119、31/70；末尾没有后继的观察分别5、3、2、3条，单列而非作失败。这是状态转换率，不是成功预测率。完整观察单独作区间诊断，其P/FP保存在summary，不能把它们说成正式提醒或丢掉负担。

## 4. 同次数、同日期的三个预定对照

每个截点，仅在两臂当前都可正式发出区间时，各发一条。这个决定不读取未来峰、最终通知总数或未来表现；两边资产、日期与条数严格一致。相同日期再发一个无模型信息的日历区间（行动日后5至14日）作参照。所有比较保留91事件，不缩成“恰好被提醒的峰”。

| 单项变化 | 每臂相同通知次数 | 对照臂 TP / FN | 改动臂 TP / FN | 同日历区间 TP / FN |
|---|---:|---:|---:|---:|
| 连续宽度→整数日期宽度 | 305 | 2 / 89 | 2 / 89 | 6 / 85 |
| 全窗口→固定稀疏窗口 | 246 | 2 / 89 | 2 / 89 | 3 / 88 |
| 任意尺度→至少两尺度 | 169 | 1 / 90 | 0 / 91 | 3 / 88 |

VERIFIED：日期宽度配对丢掉整数full独有的200条提醒，并少覆盖3个事件首条、失去1个自然命中；取窗配对分别舍弃259和5条提醒；跨尺度配对分别舍弃336和5条。跨尺度配对使任意尺度臂少20个事件首条、少2个自然命中；这些成本全部列在 `pairing_inventory.csv` 与 `pairing_event_changes.csv`。

VERIFIED：配对日期宽度两臂成功提前量同为45、63日；配对取窗同为23、49日；配对跨尺度任意尺度臂仅39日一例，跨尺度无成功。样本过少，不作稳定提前量结论。

**NOT_ESTABLISHED：上述配对证明哪种策略在真实业务中更好。**它是“双方同时有正式候选”的条件性诊断，实际部署不能靠竞争策略决定是否推送。它会丢掉独有提醒，必须和自然全量并列。日历参照在相同模型触发日期使用固定区间，借用了共同触发时点，不能解释为日历模型独立具备预测能力；但本结果没有支持LPPL选出的区间优于这条简单参照。

## 5. 建议据此作什么决策

1. **保留1.5周期研究基线与新提醒状态记录，暂不切换生产预测策略。**状态清晰和日志完整是工程改进，不能包装成准确率进步。
2. **整数日期宽度可保留为输出合法性约束**，因为用户目标是≤10日；本轮没有证明它在同通知成本下提升预测，正式提醒变多必须明确展示。
3. **暂不把跨尺度同时确认当作更高概率或主要筛选门槛。**本轮自然漏报更多、同次数也未改善；先追踪被门槛排除的候选和原拟合质量，再拟定下一轮独立协议。
4. **固定稀疏窗口仅是下一步计算成本候选**，本轮没有重拟合，不能用这次聚合时间推断实时提速或不损失准确度。
5. 若继续研究，优先核对“未来H63第一个峰”与产品区间主张的匹配语义，以及非泡沫阶段顶是否超出LPPL适用域；不能通过结果后改标签/配对来使成绩好看。任何新定义须另冻协议，并在未消费时间段验证。
