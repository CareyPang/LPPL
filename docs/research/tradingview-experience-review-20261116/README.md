# TradingView 实际体验与 LPPL 工作站设计复盘

核查日期：2026-11-16。方式：用户已登录的 Windows Chrome 桌面实操、官方产品与开发文档、LPPL 公开页面，以及同日固定 main 源码核查。交付为研究与设计规格，不含前端改造、模型运行或部署。

## 1. 结论与证据边界

**设计结论 / PROPOSED：LPPL 应学习 TradingView 的图表操作体系，结合 EasyK 的研究问答入口，围绕“顶部候选时间窗及其证据”形成自己的工作站。** 最重要的不是多加几十个功能按钮，而是让资产、时间、图表、解释和来源保持同一个上下文。

TradingView 的核心优势是：高频动作位置稳定；大面积主图；图上直接操作；自选与资产详情持续可用；复杂功能按需展开；市场数据、脚本、筛选与社区形成产品网络。它的展示页把图表能力本身作为动态主视觉，进入看盘界面后收敛装饰。

本轮状态约定：

- **VERIFIED/UI**：本轮亲自操作或看到的浏览器行为，仅代表这台电脑、这个账户和这次会话。
- **VERIFIED/DOC**：官方说明已查，不代表当前账户可用或独立效果验证。
- **VERIFIED/CODE_ONLY**：固定提交存在实现；不代表生产链路通过。
- **PROPOSED**：对 LPPL 的设计/实施建议，尚未实现。
- **NOT_ESTABLISHED**：性能、预测能力、根因或完整行为未证明。
- **NOT_INSPECTED / NOT_RUN**：未检查的平台或未执行的测试。

**本轮未完成：** TradingView 真正截断历史后的单步回放、AI Copilot回答、告警送达、付费功能、多设备同步、真实手机390px、Safari、大陆直连性能与精确帧率。打开回放控制条不算回放验收成功。没有购买、创建告警、交易、发布观点或保存用户图表布局。

本轮浏览过的区域：社区观点、Products菜单、Supercharts、资产搜索、周期选择、图表/事件设置、指标目录、回放控制条、登录后的市场概览首页、产品展示页；另外打开 LPPL 当前首页和指数终端。浏览器截图含用户其他标签与账户信息，不上传到公共仓库。光标附近跨网站出现的蓝色光晕不归因于网站设计。

## 2. 实操发现：哪些细节真正改善体验

| 操作 | 实际结果与证据 | 对 LPPL 的意义 |
|---|---|---|
| 进入 Supercharts | **VERIFIED/UI** 顶栏放资产、周期、指标、提醒、回放；左侧绘图；中央主图；右侧自选与资产资料 | 让空间位置形成记忆。新功能进入对应区域，不断加长页面会打断任务 |
| 搜索600519 | **VERIFIED/UI** 可按资产类型筛选；结果带交易所，首项为SSE贵州茅台；All里还出现其他市场相近代码 | A股优先、代码+名称+交易所+资产类型；同名不同市场不可静默选错；键盘也能操作 |
| 选择茅台 | **VERIFIED/UI** K线、成交量和右侧详情跟随变更，自选列表继续保留 | 切资产是一次上下文切换；旧结果不能在新资产卡上闪现或冒充新结果 |
| 十字光标 | **VERIFIED/UI** 日期、价位、OHLC、成交量同步显示 | 用户在同一位置读完整证据；不要迫使其在图下多张卡寻找对应日期 |
| 滚轮缩放、横向拖动 | **VERIFIED/UI** 可见历史和K线密度变化；右侧仍是最新资产资料 | 保留看图位置，提供“返回最新”。历史游标与最新报价有明确不同标签 |
| 点击6M | **VERIFIED/UI** 本次从日线自动改成2小时线，提示为6个月范围、2小时周期；手动改回1日后范围也调整 | 不能直接照搬到日线LPPL：显示范围、显示周期、模型采样、拟合窗口必须分开 |
| 周期菜单 | **VERIFIED/UI** 按秒/分钟/小时/日等分组，各项有收藏入口 | 常用项置顶；复杂选项搜索/收藏，比铺满每种周期更好 |
| 图表设置 | **VERIFIED/UI** 蜡烛实体/边框/影线可分别配色；背景、网格、十字线、坐标字号、留白可配置 | 可读性是可配置产品能力，不能只以某一张宣传截图判断 |
| 指标目录 | **VERIFIED/UI** 搜索、个人脚本、内建、社区来源分区；先出现加载占位再出现条目 | 扩展能力按来源和用途分层；自定义脚本不应默认当作官方验证模型 |
| 事件设置 | **VERIFIED/UI** 股息、拆股、财报、新闻为独立开关；未改这些开关 | 公告/资讯/模型候选各自成层，不把所有图标都叫“顶部信号” |
| Bar Replay | **VERIFIED/UI** 打开了选起点、播放、单步、速度、周期和退出控件；**NOT_ESTABLISHED** 未完成真正历史截断 | 控件可借鉴；历史可知性需要独立后端契约，不能靠一个播放键证明 |
| 未保存离开提醒 | **VERIFIED/UI** 离开试用图表时出现未保存提示；未保存本轮布局更改 | 用户主动编辑需保护；纯浏览动作是否也标dirty应细分，避免烦扰 |

本次也遇到社区缩略图未完整显示、部分弹窗响应迟后与新手提示挡住图表。**VERIFIED/UI** 是现象，原因 **NOT_ESTABLISHED**，不能外推成该网站普遍故障，也不能把这台电脑访问成功写成大陆可用性认证。

## 3. 导航：空间稳定与渐进展开

### 3.1 两层导航值得借鉴

**VERIFIED/UI** 网站层有Products、Community、Markets等，承载找产品与找内容；进入Supercharts后，顶栏变成图表动作。工作站没有把所有营销导航继续塞在每次分析路径里。

**PROPOSED** LPPL全局保留“工作站、市场、复盘、研究”四类目的地；资产搜索作为持续入口。图内工具仅负责当前资产：日/周显示、显示范围、事件图层、定位候选、返回最新、更多。方法说明和数据来源能打开，但不抢第一层。

当前“首页/图表/市场/回测/标的”可以渐进归并，先测用户是否分得清“图表”和“标的”的任务差别，再改路由。没有证据支持一次重写全部页面。

### 3.2 右侧上下文比更多卡片更重要

**VERIFIED/UI** TradingView从社区、概览到图表都可看到右侧自选/详情，减少来回寻标的成本。**PROPOSED** 我们默认右栏展示候选与结论，自选、事件、AI为同一栏的互斥视图；不同时打开三个侧栏压缩K线。AI回答中的“图上查看”应直接定位资产/日期/cluster，而不是只输出文字。

### 3.3 不照搬专业工具密度

几十个绘图工具适合熟练用户，但普通投资者初次进入会难以辨认。第一版只需十字光标、缩放/复位、区间测量、事件图层和候选定位。提供可搜索命令及键盘替代，后续按使用率扩展。官方也提供布局与配置机制，但账户持久化与跨端同步本轮未验收。[布局说明](https://www.tradingview.com/support/solutions/43000746975-tradingview-layouts-a-quick-guide/)

## 4. 图表体验：从“画出K线”到“可操作研究”

### 4.1 主图必须获得足够面积

**VERIFIED/UI** TradingView主图从顶栏下方直接开始；LPPL当前指数终端在资产横条与K线之间还留有较高的标题/图层区域。**PROPOSED** 将资产、行情截止日、日线标识和图层压成一到两行，减少主图上方空白。右栏独立滚动，避免整页滚动后丢失主图。

推荐桌面结构（尺寸为设计目标，未验收）：顶栏56–64px，资产/研究上下文行48–64px；左右容器可伸缩，右栏约320–360px；正文数字采用等宽数字特性，长代码/日期不被省略成无法辨识。

### 4.2 用户要看的顶部区间必须在图上

**PROPOSED** 顶部候选使用轻填充的垂直时间带，上边缘标起止日期，点击打开证据。图表右侧给未来日期留空间，但不制造未来K线和成交量。

- 一致度/结构强度、候选tc时间区间、实际预警效果分三项，不合成未经校准的“顶部概率”。
- 多个聚类分别编号；卡片与图上区间通过cluster_id双向联动。多个重叠填充不能以不断加深颜色暗示独立概率相乘。
- 默认强调主候选，其余候选可展开；不得只保留一个看起来最漂亮的区间并抹去分歧。
- 原首次提醒与后续修订分别保留，时间窗移动用“修订”标记而非动画悄悄覆盖。
- 合格近端候选不能仅因不足5交易日而隐藏；0–4、5–9、≥10交易日为展示/评分切片，过去tc单列，不能当新提前预测。
- 如果没有合格候选，主图仍可使用；展示缺失原因和各尺度状态，不编造未来带。

### 4.3 四种时间必须解耦

| 字段 | 含义 | 用户动作的边界 |
|---|---|---|
| visible_range | 画面看1M/6M/1Y或拖到某段 | 只改变视野 |
| display_resolution | 日线/周线等显示聚合 | 不改变日线模型输入与结果 |
| model_sampling / fit_windows | 模型日线采样和各尺度拟合样本 | 需要明确研究参数与版本；不能被缩放隐式改动 |
| asof / first_visible_at | 当时使用的数据截止时点/预测第一次可见时点 | 决定证据与评分，不等于图表右边缘或计算完成时间 |

日历、停牌、周线聚合、自然日/交易日tc转换必须冻结契约。未来区间端点不可静默吸附到最后一根已有K线。缩放、分辨率变化前后同一result_id的原始日期必须不变。

### 4.4 回放不能只回放价格

**VERIFIED/DOC** TradingView明确说明：Bar Replay中行情列表/交易面板报价仍可为实时，服务器提醒也继续基于实时数据。这是产品边界，不是本报告发现的泄漏漏洞。[官方回放限制](https://www.tradingview.com/support/solutions/43000474024-how-do-i-turn-bar-replay-on/)

**PROPOSED** LPPL研究回放更严格：价格、事件已知版本、LPPL结果、AI证据共用as-of；若保留实时侧栏，清楚标“现在”且不进入历史问答。缺历史来源时显示“无法重建当时状态”。历史补算、事后标签、真实提前公开分别计分。单步回放必须真的切断未来数据，包括悬停、数据表、导出与AI工具。

## 5. 颜色、排版、留白与微交互

### 5.1 它的专业感来自颜色有职责

**VERIFIED/UI** 本账户图表使用白底、浅网格、深色文字、红/青绿行情；成交量更淡，新闻/特定提示另用紫/蓝。营销页为黑底、白色大标题、蓝紫渐变和产品展示。两种密度服务两种任务。

**PROPOSED** LPPL默认浅色工作站可保留。建议下表为自有tokens，不是从TradingView提取的精确色值，也未冒充完成无障碍对比度验收。

| 用途 | 建议颜色/形态 | 约束 |
|---|---|---|
| 页面/图面 | #F6F7FA / #FFFFFF | 用边界和留白分层，不让每张卡都有厚阴影 |
| 主文字/次文字 | #17202E / #586476 | 数据时间不能使用几乎不可见的浅灰 |
| 主操作 | #315BE8 | 搜索选中、聚焦、导航；不表示上涨 |
| A股上涨/下跌 | #C63C4A / #157D68 | 默认红涨绿跌，可切国际习惯；同时显示正负号 |
| 顶部候选 | 琥珀边界+低透明填充+日期 | 候选与正式提醒再以线型/文字区分，不只靠颜色 |
| 底部研究 | 蓝紫边界+标签 | 与上涨绿色分离；不得暗示与顶部同等验证水平 |
| stale/失败/未知 | 独立状态图标+明确文字 | stale不等于跌、未知不等于0、没有合格拟合不等于安全 |

需按实际背景合成后测试正文对比度、图形边界和色觉缺陷模式。区间填充保持K线清晰；选中区间增加边界与标记，不用高亮闪烁来暗示准确率。

### 5.2 排版不是把字体全部放大

标题、资产名称、关键日期、辅助解释四层固定。K线坐标与行情数值对齐，日期格式一致；来源和stale原因放二级展开，但截止日期与状态不能折叠。右栏结论先写“有什么结果”，方法和风险写后面。

建议顶层结果结构：**候选起止日 → 当前/历史时点 → 支持尺度与分歧 → 状态及未满足项 → 定位图表/查看证据**。有多个候选就列多个；没有则明确无候选及原因。不要用大量防御性文案挤走结果，也不能为了文案积极而提升证据等级。

### 5.3 微交互让动作可预期

**PROPOSED** 搜索即刻展开；切资产保留布局但清楚转换上下文；数据未到时有骨架、旧结果日期和取消/重试入口；图层开关即时响应；图中选择和右栏选中同步；新行情到达时不拉走正在查看历史的用户；错误弹窗不要阻断整个工作站。

动效预算建议：按钮/选中态120–180ms，抽屉/布局180–280ms，主动定位图表最多约300ms；这些是待测目标。实时价格、十字光标和区间坐标不做滞后缓动。尊重reduced-motion并提供跳过展示的入口。

## 6. 首页动画：值得借鉴的主线

### 6.1 三种页面不能混为一谈

**VERIFIED/UI** 本账户访问TradingView根首页看到市场概览与指数卡；进入`/features/`才是品牌/功能展示：大标题、蓝紫渐变、动态多图工作台演示，底部出现暂停控件；继续滚动有使用场景图片和悬浮的功能目录。动态演示中图表、资产与菜单发生变化，本轮没有测其编码方式、精确帧率或加载体积。

**VERIFIED/UI** LPPL当前`home.html`已经是浅色文字+主要指数卡，不再是海洋背景。品牌名仍显示“临界点”，但用户明确要求换名；本轮没有改线上名称。不要回到旧海洋/花海方案来评价当前主页。

### 6.2 LPPL推荐“时间展开”的产品主视觉

以下为**PROPOSED**，尚未制作，也不建议仅为营销页立刻上重型3D引擎。

**分镜A：看见结构。** 留出清晰标题和搜索入口，主视觉只有一个精致的价格/时间场：几组透明曲线沿时间轴错落展开，鼠标轻移产生有限视差，选中时能看见对应窗口。它不是装作真实预测的装饰图；固定演示样本必须标“交互示例/历史重放”。

**分镜B：收束到区间。** 滚动时曲线的时间候选逐渐对齐为若干时间带，同时出现尺度支持和分歧。避免强行把所有轨迹收进同一个日期，造成“模型必然精准”的视觉承诺。日历刻度、标签先可读再考虑光效。

**分镜C：进入真实工具。** 点击搜索结果后，主视觉的坐标框连续变成真实K线容器，右侧研究摘要滑入，演示身份清楚退出，真实资产/截止日接管。立即可看缓存行情；计算任务异步出现，不卡住整个页面。允许从A直接进入，不必等动画播完或滚过空白。

回访用户默认进入上次工作站或自选，仍可主动看品牌首页。无声默认播放短展示即可，不加载音频；长时间连续背景动画在工作站停止。动画的验收问题是“它是否解释并缩短了下一步动作”，而非“能否多转一圈”。

### 6.3 对当前首页的具体调整

**PROPOSED** 保留浅色和现有指数卡的可用性；缩短首段模型术语与英文装饰问句，把顶部时间区间和研究能力用直接中文表达；品牌口号可保留一行。搜索是第一主操作，首次访问可附“看一个有完整证据的历史案例”，回访则“继续最近分析”。

首页右侧不应全部长得像同一张“无合格拟合”卡。按数据新鲜度与候选状态显示差异，并允许“只看有候选”“看全部尺度”。**不能**为了更热闹而把0/无证据改成风险信号。新视觉完成前不需要再推倒整个首页。

## 7. 与当前 LPPL、EasyK 的差异

| 维度 | TradingView | LPPL当前已见/已查 | 应新增或重排 |
|---|---|---|---|
| 日常看图 | **UI** 搜索、缩放、光标、列表和详情连贯 | **UI** 已有K线、成交量、图层、左工具与右研究栏 | 缩小图上空白；可视区/上下文统一；候选卡和区间互联 |
| 首页 | **UI** 登录概览与产品展示页各自服务任务 | **UI** 浅色文案+指数卡+搜索 | 品牌页产品主视觉；回访直接继续工作 |
| 资产切换 | **UI** 数据源/市场标识明确，右侧跟随 | **CODE_ONLY** 多入口和统一数据适配层已存在 | 搜索结果规范化、重复入口收敛、旧回答标为旧上下文 |
| 结果解释 | **UI** 图表详情、事件层、指标目录；Copilot入口可见但回答未试 | **UI** 六尺度与历史统计可见，结论较密集 | 候选日期优先；AI只解释现有结构化证据，点击回图 |
| 回放 | **DOC** 图形回放与实时侧栏可并存；本轮截断未验收 | **CODE_ONLY** 指数as-of回放已存在 | 统一事件/模型/AI时间轴；历史补算与首次公开分账 |
| 筛选/热力图 | **DOC** 独立筛选、热图与市场覆盖 | **CODE_ONLY** LPPL已有行业/概念/地域热图等 | 保持同一筛选结果，在列表/热图/事件视图切换；不重复开发已有模块 |
| 用户长期状态 | **DOC** 布局能力；跨端未实测 | **CODE_ONLY** 浏览器自选存在，账户同步未建立 | 先保存资产、视野、图层和最近分析；账户同步后置 |
| 顶部时间研究 | 通用工具能力不证明LPPL顶部效果 | **UI/CODE_ONLY** 已有模型结果，但有效性需逐项验证 | 结构强度、tc区间、真实预警效果分开，成为主任务 |

EasyK前一报告已实测其AI可读取当前图表/空事件，但数值统计并非每次严格完成。我们应组合“TradingView的可操作图表 + EasyK的上下文问答 + 自己的证据账本”，不是把AI聊天窗放在所有页面旁边就算完成产品。

### 当前公开LPPL页面的三个优先问题

1. **VERIFIED/UI** 首页部分指数报价标11月16日，模型截止10月30日并标落后11交易日；终端加载上证现有分析时也显示10月30日。这是已显示的版本差异，不等于报价错误。**PROPOSED** 将“最新报价”与“本次分析收盘价”并排标注，进入旧分析时明确提示，不让大数字看起来像同一时点。
2. **VERIFIED/UI** 右栏先有主尺度无合格拟合，随后是六尺度、情景区间和历史顶后回撤/顶谷时间/估值地板。**PROPOSED** 把历史样本统计移入“历史背景”折叠层；它们不能压过当前候选，也不能被误解成这一次必然的回撤目标。
3. **VERIFIED/UI** 六尺度格子文字小、证据状态与当前结论挤在一起。**PROPOSED** 做可选尺度条：选中后图上高亮对应候选，旁边解释无拟合、无证据与有结构但未正式提醒的区别。本轮没有重算，不能据界面判断哪一尺度预测更准。

## 8. 图表技术选型与集成边界

固定main的引擎核查见[chart-engine-notes.md](chart-engine-notes.md)。当前主图是自写Canvas 2D，不能误写成已经使用Lightweight Charts。

**VERIFIED/CODE_ONLY** 指数已实现K线、成交量、当前顶部区间填色和历史情景；个股已有K线/成交量，但历史情景位于另一张画布。本轮检视的个股主K线绘制函数未接收未来候选图层，因此任务是把已有行情与区间接到同一操作面板，不是声称整个项目没有区间绘图。

**VERIFIED/CODE_ONLY / 优先风险** 指数未来`dateAt`和`idxOf`只跳过周六/周日，没有扣除交易所节假日。未来交易日间距及日期定位需要专项验证；不能据此断言每个当前区间都画错了。[未来日期换算](https://github.com/CareyPang/LPPL/blob/4a5e1375e6dbd9a5b442d16c876b69ccaff7d0b5/frontend/index.html#L408-L412)、[日期到下标](https://github.com/CareyPang/LPPL/blob/4a5e1375e6dbd9a5b442d16c876b69ccaff7d0b5/frontend/index.html#L445-L451)

**PROPOSED** 先用少量同一fixture比较两条实现：A保留Canvas补齐交互；B用Lightweight Charts做单图原型。比较未来日期映射、十字光标、缩放/触摸、图层、无障碍替代、内存和维护成本，再决定迁移。不是为了与TradingView外观相似就立即换库。

**VERIFIED/DOC** Lightweight Charts是开源图表基础设施，数据、证据账本、筛选/新闻/AI/服务端提醒仍由项目提供；Apache 2.0及归属说明需遵守。Advanced Charts、Trading Platform与网站订阅不是同一产品，受各自许可约束，不能把受限库复制到公开仓库。网站订阅也不自动授予行情再分发权。[产品对比](https://www.tradingview.com/charting-library-docs/latest/product-comparison/)、[官方FAQ](https://www.tradingview.com/charting-library-docs/latest/resources/Frequently-Asked-Questions/)、[LWC许可](https://tradingview.github.io/lightweight-charts/docs#license-and-attribution)

技术原型需要验证未来whitespace/自定义图层和绝对日期映射；不能只靠截图看起来覆盖了未来区域。数据更新要保留用户视野、复用已有序列，避免每条报价重新创建整个图表。[更新数据](https://tradingview.github.io/lightweight-charts/docs#updating-the-data-in-a-series)
