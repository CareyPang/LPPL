## 1. 项目要解决的问题

**VERIFIED（用户需求）：**普通投资者输入A股代码，先看到日线行情和已有结果；通常持有1–6个月，希望普通约10%的调整也得到提醒，偏向少漏报，最好至少提前5个交易日、顶部区间不超过10个交易日。还希望了解可能回撤多少、调整后的价格区间及何时适合考虑抄底。主要访问者在中国大陆，后续可能发展为付费研究工具。

产品使命：**帮助用户更早看见持仓风险，并理解不确定性和后续情景；产品投入以实用性证据为依据。**

第一阶段必须回答：在用户愿意承受的提醒次数、持续时间和误报代价内，提醒是否比简单规则更有帮助？

项目不是以“把LPPL网站做完”作为完成标准。LPPL是候选方法；完整周期1.5是已确认的研究起点。若简单模型更有效，主产品可以使用简单模型；若时间定位没有增益，主产品可以没有窄顶部日期。

## 2. 需求、假设与可更换的实现

## 3. 四项能力分别立项

| 能力 | 用户问题 | 必须优于的参照 | 产品启用条件 |
|---|---|---|---|
| A 风险提醒 | 近期是否值得提高警惕？ | 产品候选对比无信息参照；新增复杂方法再对比简单风险模型 | 有足够提前量，漏报/误报/持续时间的交换有价值 |
| B 顶部时间 | 可能在哪段时间结束上涨？ | 同样宽度、同样提前量的简单时间区间参照 | 首次发布区间的真实覆盖有增益，不能只看后续某次命中 |
| C 回撤与价格情景 | 若风险发展，可能跌多少、到哪里？ | 无条件历史分布和波动基线 | 区间校准与宽度兼顾，条件模型有增量信息 |
| D 抄底辅助 | 下跌后继续跌的风险是否下降？ | 简单趋势/波动/收复条件 | 分别检验继续下跌、确认滞后和错过反弹的代价 |

A是第一优先级；B不是A的必要前置条件。C可以独立成立，也不能借用A的成绩。D需要单独的事件、执行和价格证据，不能把顶部模型符号翻转后直接上线。

“时间很准”“跨周期集中就更大概率”“1.5周期足够可靠”均不作为规划前提。公共LPPLS研究把合格拟合比例用于置信指标，并研究多尺度临界时间情景；这不能直接证明本产品在A股普通调整上的效用。[Gerlach等原始论文](https://arxiv.org/abs/1804.06261)

## 4. 先定义什么叫有用

### 4.1 三种价格问题必须分开

1. **从提醒后可执行价格出发的损失**：未来固定期限内，价格相对该起点最多下跌多少。
2. **从某阶段高点出发的调整**：高点之后是否出现约10%的峰谷跌幅；用于检验有没有提前提醒顶部。
3. **提醒后的完整持仓路径**：先涨多少、后跌多少，采取固定动作后回撤和收益如何变化。

例：提醒时100，随后涨到130，再跌到117。它符合“从高点跌10%”，却不等于在100时离场有利。因此不能只凭命中峰后回撤就宣布提醒具有投资价值。

### 4.2 事件与提醒协议

先交付一份版本化协议，再开始新一轮效果比较。协议必须明确：

- 10%使用收盘价还是盘中极值；模型复权序列与实际成交价格分别处理。
- 高点/平台顶识别、同一次调整的重复峰合并、连续下跌期间的新事件规则。
- 调整成熟期限；20/60/120交易日可以作为候选期限，但必须预先选主目标，其他作为敏感性结果全报。用户尚未选择，不能以60日默认替代。
- 提醒有效期、升级/解除规则、冷却期、何时算一次新提醒；连续20天亮灯不能只计一次而不计占用时间。
- 有效提前量必须有上限：至少5日且落在约定观察范围内。建议先讨论5–30交易日作为主提前范围，31–60日另报；这是待确认草案，不能挑选有利范围。
- 预警在日线收盘数据可用后生成，下一真实可执行时点才算可行动；停牌、无法成交、缺数据要保留为状态。
- 首次提醒、区间修订、后续升级均保留。首次区间和后续跟踪分别评分，禁止事后选择最佳一次。
- 冻结提醒—事件匹配算法及分母。主评价建议采用每资产一对一的确定性时序匹配：按提醒发出时间，匹配有效期和提前范围内最早的尚未匹配事件；不能事后最大化匹配数。一条提醒不能重复领取多个事件成绩；重复提醒占用成本分母但不重复增加事件召回。最终算法和重复/无事件提醒分类在V0确认。
- 顶部窗口宽度统一为所包含的交易日数，并明确首尾端点；不能把10个bar间隔与含首尾的10个交易日混为一谈。

研究者先制作约20个正常/平台顶/反复回撤/长熊市/先涨后跌等标签示例，由产品确认其含义；审阅标签时不看模型得分。标签用于事后评价，可以使用未来；生成特征、选股和报警不能使用标签未来信息。

### 4.3 主指标与成本

主指标建议为：**在冻结的提醒预算下，满足实际可行动提前≥5日的事件召回率。** 同时报告精确率、总覆盖和以下成本，不能只优化召回：

| 指标 | 为什么需要 |
|---|---|
| 每股每20/60交易日新增提醒次数 | 控制收到提醒的频率 |
| 处于提醒状态的时间占比 | 防止永久报警取得高召回 |
| 每个事件重复提醒与同一市场事件的跨股提醒 | 控制噪声与组合层通知负担 |
| 未对应目标事件的提醒、提醒后继续上涨幅度 | 量化误报和过早提醒的代价 |
| 可行动提前量分布、迟报和完全漏报 | 不能只报告平均值或成功案例 |
| 首次区间宽度、真实覆盖与联合目标 | 单独检查≤10日与提前≥5日是否同时成立 |
| 关注列表每周卡片数 | 用户同时看多只股票时仍然可用 |
| 无结果/不支持/数据故障比例 | 拒绝输出不能偷偷从全部服务需求中删除 |

可先比较每股每20交易日0.5/1/2次新增提醒的三档研究预算；它们是代价曲线，不是用户已经接受的默认值。通知聚合只能减少重复通知，底层每股信号和全部错误仍计分。

阈值和预算控制策略在开发区确定，最终测试时锁定。测试期实际提醒频率漂移要报告，不能读取测试结果后调阈值凑成相同预算再声称这是可实时执行的策略。

### 4.4 是否真的帮助持仓

风险提醒通过初筛后，再设置独立的动作实验：持有参照、提醒后固定比例降低暴露并按固定期限/预先定义条件恢复等。动作比例、恢复规则、成交价、费用和无法成交规则均在评价前冻结；禁止使用事后最低点买回。

同时看最大回撤、尾部损失、收益损失、换手和恢复风险。它是对提醒效用的研究，不自动生成个性化买卖指令。事件覆盖、概率校准与交易收益是三种不同证据。

未通过动作层验证时，只能主张风险信息的研究价值，不能主张提醒后减仓已经改善收益或回撤。若未来产品提出后一种价值承诺，动作实验必须成为其V3/V4的单独验收项。

## 5. 模型研究的正确顺序

### 5.1 先建立可击败的简单基线

第一轮只建立四类比较，数量上限在协议冻结时确定：

1. 无条件发生率，以及相同预算/持续时间的固定频率或随机提醒参照。
2. 简单风险模型：仅使用当时可见的收益、波动、成交量、距近期高点距离与市场走势。先用简单可校准方法。
3. LPPL研究基准：完整周期1.5、明确未来tc域、参数边界和拟合/过滤版本。
4. 简单模型加入LPPL信息：检验LPPL是否提供额外信息。

门槛分两层：简单模型是否值得成为产品，取决于它相对无信息参照的效用和用户最低要求；LPPL等复杂方法是否值得加入，再以相对最强简单模型的增量裁定。简单模型不需要“胜过自己”才能进入产品。

指数结果不能替代个股验证；成功案例不能替代全部连续扫描；LPPL与简单模型使用同一可评价样本及相同服务覆盖口径。某模型只在少量日期可用时，既报告交集比较，也报告面向全部用户请求的缺失代价。

### 5.2 时间窗选择重新作为待检验问题

拟合历史长度、未来风险期限、tc前视范围分别记录，不能统称“短中长期”。不预设上一轮95窗或28窗就是新产品配置。

开发阶段按下面顺序检查，一次只改变一项：

- 固定、少量、覆盖不同历史长度的窗口组是否已经足够；先避免相邻窗口重复投票。
- 与只使用过去数据的自适应起点/窗口选择相比，固定窗口是否更稳定。自适应规则不得查看未来峰值。
- 在相同报警代价下，增加短窗是否改善≥5日覆盖，还是只增加报警。
- 采用尺度权重和每窗一票后，跨尺度信息是否仍有增量。
- 计算预算受限时，删窗是否损害逐事件首警、尾部漏报和日期稳定性；不能只比较总命中数。

窗口清单及其选择理由先写入实验登记，再读取效果。开发资料已经见过的结果可用于提出候选，不重新包装为独立验证。

### 5.3 聚类服务于不确定性表达

簇回答“哪些拟合给出相近的临界时间情景”，不直接输出见顶概率。重叠窗口、相邻日期和多seed是相关证据；seed属于优化质量诊断，不是独立票数。

每次输出须能追溯成员、原分母、尺度覆盖、权重、选择规则和退化情况。先比较“不聚类”与“增加聚类信息”的增量；再决定是否需要持久跟踪。不要把反复确认设为所有早期提醒的硬条件，除非验证支持这样做。

≤10日是需要验证的目标，不通过强制裁剪来达成。允许输出宽区间或“时间暂不可定位”；但要统计拒绝定位比例，不能只报少数窄区间成功率。若要把支持度转换为概率，必须另做仅用训练资料的校准与独立检验。

### 5.4 优化器与提速

SciPy DE多seed加独立L-BFGS-B，与网格/多起点TRF仍是可比较候选。比较同一目标函数、参数域、输入、收敛要求与实际时间预算；记录成功率、目标值、参数差异、过滤结果、tc稳定性、墙钟时间及CPU占用。最小拟合残差不等于最好预警效果。

优先实施不改变科学任务的提速：精确缓存、日线增量读取、相同请求去重、当前与历史分离。稀疏窗口、减少seed、提前停止、warm start可能改变结果，应单独做质量/延迟对照，不能一概称为无损优化。bootstrap和全历史回放属于研究任务，用户查询默认只需要当前结果。

## 6. 数据与独立证据

先盘点可用数据和样本使用历史，再决定新增数据范围。初期可提出一个按流动性/规模/行业分层、规则选取的有限股票试验池；不要因为某只曾出现漂亮泡沫而纳入，也不要把小池成绩称为全部A股成绩。

必须建立：

- 资产代码/交易所/名称变更与历史上市资格；退市、停牌、上市时间短的处理。
- 原始响应、数据可用时间、修订版本、复权因子、交易日历、缺失原因、来源和哈希。
- 模型用价格与可成交价格的明确对应；现成复权历史不能自动证明严格时点可得。
- 数据使用台账：开发、调参、看过的测试、真正未消费资料、前瞻资料分别标记。
- 数据质量失败与模型无信号分开；不以缺失填0风险。

采用按时间前进的开发/验证流程，训练标签必须在边界前成熟；按最长目标期限处理边界重叠，相关日期与同一市场下跌不能作为独立样本重复扩充统计把握度。时间区块和市场事件组用于不确定性评估；分股票/行业/市场阶段检查效果是否集中。

每条样本记录完整标签规则下的`label_available_at`，训练边界以真实最早可判定时间为准。例如允许未来30日形成顶部、顶部后60日内下跌，一条无事件提醒可能要等90日甚至加上额外确认规则才能判定，不能只隔离60日。测试尾部未成熟样本标为待定，不计成功或误报，也不从服务覆盖统计中消失；完整成熟评价区间和待定数量同时报告。

最终验证只评价冻结方案；样本不足记为**证据不足**，不是通过，也不是证明永远无效。已被反复查看的1990s、指数、金银、纳指或KOSPI资料可以诊断问题，不能通过换名称恢复为未见样本。

独立评价前指定主候选、主指标和裁决规则。若多个候选共同参加最终评价，事先处理多重比较，不从测试结果中择优后只报告赢家；登记尝试次数本身不能代替这一控制。

反复尝试后挑最好回测会产生过拟合风险，因此所有候选、失败和尝试次数都进入登记。本文采用时序验证、冻结规则和前瞻记录；不声称某一种交叉验证方法能够自动消除全部金融回测偏差。[Bailey等作者论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

## 7. 价格层与抄底路线

| 阶段 | 输出 | 比较与通过条件 |
|---|---|---|
| P0 历史描述 | 历史回撤分布、样本数、时期、波动环境 | 正确复现与诚实文案；不称预测 |
| P1 条件回撤 | 从可执行时点出发、固定期限的下行分位和超阈值概率 | 比无条件/波动基线有更好的校准与适当评分 |
| P2 价格情景 | 条件回撤映射成价格区间，并区分终点价与期间最低价 | 区间覆盖与宽度同时评估，价格/复权/时间一致 |
| P3 跌后更新 | 在可实时识别的调整启动条件后更新下行情景 | 启动规则事先固定；不能事后挑破裂日 |
| P4 抄底辅助 | 继续下跌风险、恢复时间、止跌条件变化 | 独立检验新低风险、确认滞后、最大不利变化与反弹机会成本 |

分位预测用适当分位损失，概率用Brier/log loss与校准，区间用覆盖和宽度；各自与简单基线配对。通过一项不自动通过其他项。若价格条件模型无增益，产品保留历史情景即可。

LPPL时间输出不直接推导回撤幅度。既有H1/H2/H3、Q2、MPL、Ising、Q-DD2、PPE失败结果保留；它们既不是成功模块，也不能被泛化为整个问题永远不可解。

## 8. 第一版产品：用于验证的最小研究界面

第一版面向你和少量受控试用者。目的为看清每次提醒、记录用户理解与代价、生成保留原版本的可核验前瞻记录；暂不建设会员支付、社交、全市场实时排行或大型营销首页。

只需要四个工作区：

| 工作区 | 第一版内容 | 通过标准 |
|---|---|---|
| 查询与行情 | 代码/名称识别、日线、来源/日期、已有结果 | 模型未完成时仍能缩放、切股、看旧数据 |
| 提醒与情景 | 当前状态、首次提醒时间、有效期、更新原因、证据等级 | “没信号”“没算”“数据失败”清楚区分 |
| 历史记录 | 当时可见的预测快照和后续结果，默认隔离未来信息 | 不能随新计算覆盖旧预测；修改可追踪 |
| 研究成绩单 | 基线比较、漏报、误报、提前量、拒绝输出、版本 | 好坏结果都能定位到原始样本 |

输入后流程：页面壳和状态立即响应 → 独立读取行情/已有结果 → 缺当前结果时后台任务排队 → 用户继续操作 → 校验资产与版本后更新。历史回放另行请求，绝不作为显示当前页面的必要条件。

同一研究冻结版本的正式提醒应在固定收盘数据截点生成；用户点击查询只读取记录，不能改变前瞻实验的生成时间。按需试算使用独立“研究试算”标签，不混入正式前瞻成绩。候选池中没有覆盖的代码仍可看行情，并明确说明尚无已验证模型覆盖。

前瞻运行事先冻结“应生成的资产×截止日”清单和最迟发布时间。成功有/无信号、不支持、历史不足、数据迟到、计算失败、漏跑与逾期完成都须有状态；按期完成率以全部应产出项为分母，模型可评价覆盖和全部查询中范围外请求另报。不能只保留成功日志，让漏跑从分母中消失。

数据截点、计算完成、封存接收和实际可见时间分别记录，实际可行动时点受可见时间与交易可行性共同约束。失败或逾期后补算保留为补充记录，不能补记成当时已及时提醒；正式运行前演练漏跑、过期和迟到结果如何进入成绩单。

最小验收包含：桌面与390px、慢行情/慢模型/失败/刷新/切股/迟到响应、缓存日期和版本、键盘操作、数据导出。合成测试只验证流程，不能代替真实市场证据。

## 9. 视觉与交互的完整方向

长期方向是安静、清晰、可探索的研究终端，首页可以有海水或其他高质量动效。品牌视觉不决定信号语义，也不先投入大规模重做。

- 分析页采用中性底色，红绿专用于涨跌且辅以符号/文字；风险程度使用文字、图标和单独色阶，避免深墨绿背景与下跌K线混淆。
- 首屏顺序为资产/数据日期、行情、提醒状态、情景，再展开模型细节。概率未经校准时显示支持情况，不出现伪精确百分比。
- 动效用于状态变化、图表联动和历史时点切换；加载时可读旧结果，不用全屏动画遮挡页面。
- 用户点击一个历史提醒，能看到当时数据、当时版本和原始区间；未来结果需明确切换到复盘视图。
- 390px优先展示一列关键内容，详情可展开；图表拖动和页面滚动需区分。键盘焦点、触控目标、颜色对比和reduced-motion一起验收。
- 长期公众网站再扩展首页、分析、关注列表、成绩单、方法证据、账户/任务中心。每个入口共用同一结果与任务契约。

达到研究门槛后再制作两套视觉样板，用完成查询、理解提示、识别过期数据等任务比较，而非只比较首页截图。保留海水版与重新设计都可以，由实际任务测试选择。

## 10. 后端与算力：先简单，保持可替换

逻辑上分为行情接入、研究执行、预测记录、查询服务和界面五层。最初可以在一台现有计算机上运行，不要求一层一个云服务。

```mermaid
flowchart LR
  D[日线与可用时间] --> S[版本化数据快照]
  S --> R[冻结版本的研究执行器]
  R --> L[追加式预测与评估记录]
  L --> A[只读结果与行情接口]
  A --> U[可立即操作的研究界面]
  U --> Q[独立试算任务]
  Q --> R
```

核心契约保留：资产、数据截至日/可用时间、源数据哈希、模型/参数/源码版本、生成时间、任务类型、提醒起止/修订原因、预测区间、证据状态、失败原因。正式前瞻记录和按需试算使用不同记录类型。

本地文件日期或自行填写的生成时间不构成提前发布证据。影子运行要在固定截点封存预测，记录服务端接收时间、内容哈希和追加审计日志，限制覆盖权限；独立复核者在结果揭示前取得封存摘要。具体存储及可信时间机制在V4验收，未实施时不能宣称记录不可篡改或已经证明提前命中。

结果缓存按上述科学身份校验；不能仅凭股票代码拿任意旧版本冒充最新结果。任务去重、超时、恢复和队列优先级独立于网页。当前查询、研究回放和批量扫描分别排队；先限制并发和范围，再考虑扩容。

| 投入阶段 | 建议部署形态 | 购买/迁移触发条件 |
|---|---|---|
| 验证期 | 现有本地CPU、文件/轻量索引、私有研究界面 | 本地容量与可靠性没有阻塞时不采购 |
| 受控试用 | 可持续运行的单个CPU执行器、持久任务与对象/文件结果存储 | 已获得继续投入的研究证据，或需要不中断的前瞻运行；先测固定工作负载 |
| 公众服务 | 按实际负载拆分网页/API、任务执行和存储 | 有真实并发、时延、可靠性和成本记录后再扩容 |

Cloudflare可以作为候选接入/协调服务，腾讯云和阿里云可以作为候选计算/托管供应商；本规划不预选赢家。Workers有明确CPU和内存限制，不能把普通请求运行时等同于无限制云电脑；平台其他计算产品需另做适配评估。[Cloudflare官方限制](https://developers.cloudflare.com/workers/platform/limits/)

性能分别测页面可操作、行情可见、缓存可见、排队、计算、结果更新的p50/p95；先建立实测基线，不许用模型总耗时解释页面卡住。费用账本包括数据、CPU时间、存储、流量、失败重试和运维，不用活动价代替长期成本。本轮不提供未核价的云采购清单。

数据许可、个人信息与运营主体等应在公开试用或收费前核查；大陆访问需实测不同网络。域名、备案、金融信息业务边界本轮未核查，不默认旧讨论已经满足要求。
