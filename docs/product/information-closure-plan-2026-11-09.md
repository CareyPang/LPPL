# LPPL 信息产品四阶段执行规划

版本：2026-11-09；开始基线 `d9f0ca4`；唯一代码交付 PR #50。页面方向沿用用户选择的“海洋观测台”。本轮不合并、不部署、不购买、不发布、不在线 seed，也不修改 LPPL 拟合。

## 1. 下一步与完成定义

下一步首先完成日终复盘的**可恢复采集与证据归档**。判断标准不是“有一个每日定时配置”，而是：同一组来源连续多个交易日取得真实数据；原始响应可核对；当天、失败、修订、部分覆盖能区分；下次运行能恢复前日；缺数据不会成为零值或成功晋级。

当前已经有可操作信息工作台，缺口集中在生产数据闭环。不能因为 UI/接口存在，或因为旧 gate 返回 true，就宣称每日更新已经运行。四阶段按依赖推进，完成代码、真实数据验收、上线运行分别计进度。

| 阶段 | 用户得到什么 | 本轮位置 | 离开阶段的条件 |
| --- | --- | --- | --- |
| 1 日终复盘 | 可查每个交易日完整池、原因、标签、晋级、失败和修订 | 正在执行；新增归档账本、严格质量检查、恢复链路；旧两日研究导入已运行 | 连续至少 5 个真实交易日采集与恢复；完整性有原始证据；失败演练通过；获准信息可被只读接口按日读取 |
| 2 个股资讯 | 输入股票后立即看行情，并查公告、新闻、财务、股东、解禁、龙虎榜、资金 | 13 节契约和 UI 已有；实际逐源内容未全部接通 | 每栏目真实成功/空结果/异常/stale 各有验收；至少茅台和一只不同市场股票跑通；信息加载不启动拟合 |
| 3 统一时间轴 | 在同一个日期坐标看行情、公告和模型提醒/修订 | 已有独立资料与模型账本，尚未完成统一视图 | “当时已知”与“事后补充”可切换；首次可见时间有真实回执；任何未来资料不得进入过去视图 |
| 4 盘中与全球 | 六时点、宏观、全球新闻、获准预测市场概率 | 部分适配/契约已有；生产源和实时运行未成立 | 来源许可、频率、大陆路径通过；盘中不回填；概率书面许可与六小时刷新限制成立 |

建议按可验收的工作包安排，先完成 1 的本地代码和数据质量，再做 2 的真实来源，不以页面数量代替完成度。阶段 2/4 的来源审查可并行；上游数据接入、模型研究和视觉优化各自独立验收。

## 2. 本轮发现与纠正

**VERIFIED（源码及本地实物）**：旧 nightly 每次新 runner，没有恢复前日归档，默认日历为空；旧日期文件写入与 context 冲突检查不在同一事务；完整池判断主要依赖 list 存在，不能排除截断、重复代码或日期错配；抓取器计算了响应 hash，却没有保存响应字节。

**VERIFIED（旧数据审计）**：11 月 5/6 日已有原因/标签 83/84 与 32/32。它们在北京时间 11 月 8 日凌晨才取得，对应原始响应字节未找到。两日结构完整，不等于来源日期、分页、当时可知性或公开许可都已验证。详见 [输入审计](../validation/2026-11-09-eod-input-audit.md)。

因此，本轮不重新给旧结果贴“全量真实日终预测证据”标签；保留旧原件及原晋级结果，在新研究归档中记录质量差异。

## 3. 阶段 1：日终复盘闭环

### 3.1 每日工作流

1. 加载**已核验且覆盖该日期**的交易日历。休市日跳过；北京时间 15:30 前不采集当日日终。日历过期、缺失或来源状态不合格，记失败，不按工作日猜测。
2. 恢复持久化账本，按日历找到前一交易日。只选择本次执行开始前已经归档的前日版本；没有就明确缺失。
3. 在逐源研究访问和频率审核通过后，读取 ZT/ZB/DT、原因标签及昨日池。所有实际响应在 JSON 解析之前保存字节，包括 HTTP 错误和无法解析的响应；不归档认证头、cookie 或秘密查询参数。
4. 分别检查池总数、明细数、唯一代码、连板值、源返回日期与分页覆盖。请求参数带日期不能证明响应日期；明细长度等于本地计数也不能证明供应商全量。
5. 原因与标签报告匹配数、缺失数、额外股票和覆盖率。标签保留来源原文，整段 `A+B+C` 不冒充已经建立标准题材分类；后续拆词须保留原文和拆分版本。
6. 只有两日 ZT 池、相邻交易日和原始响应都满足新校验，才生成新口径晋级；前日表现接口不能替代前日封存池。晋级仍是历史描述，不是次日概率。
7. 用一次事务写入新版本和执行回执。重跑保留同日多版本；失败和进程中断保留执行记录。最新尝试与可用版本分开，失败不覆盖已有结果。
8. 生成可验证备份。恢复时校验数据库、原始响应、快照及执行/修订关联；坏备份停在恢复阶段，不能静默建立一份空历史。

### 3.2 账本与证据

- `events`：开始、结束、失败、跳过；未结束明确为 `interrupted_or_running`。
- `responses`：source_id、脱敏请求 URL、抓取时点、HTTP 状态、真实 body 与 SHA-256。
- `revisions`：资料日、首次本地归档时间、规范化内容、版本号与内容 hash；禁止 UPDATE/DELETE。
- `daily_capture`：每池质量、原因/题材覆盖、原始响应验证、前日版本引用、旧结果保留及回溯状态。
- `first_public_visible_at` 保持 null；本地归档时间绝不冒充首次向用户公开的时间。

SQLite 是本轮本地/单写入者参考实现。腾讯生产服务需要持久卷、备份策略、访问控制与运行监控；不能把 GitHub artifact 的 90 日保留当永久生产数据库。

临时 runner 被强制销毁时，本次尚未上传的回执可能丢失；上次已验证状态仍保留。要保证这类中断也能留痕，需要腾讯持久存储与外部执行监控，不能仅靠 workflow 的 `always()`。

### 3.3 调度与失败恢复

计划时间保留北京时间工作日 18:20，但实际以验证日历和源状态为准。新 nightly 默认关闭：仓库开关与逐源审核文件均需显式满足，而且包含原始响应的 artifact 路径只允许私有仓库。当前公开仓库即使误开变量也不会运行此任务；没有开启任何每日采集。

GitHub 路径用于可恢复采集验证：只从同一 workflow、main、已结束运行恢复已校验状态。无论采集是否成功，都尝试最终备份；只有通过验证的 `state.sqlite` 上传为恢复用 artifact。损坏/未完成输出另存诊断 artifact，避免下次持续恢复同一份坏状态。

生产腾讯路径建议：独立定时采集进程 → 持久账本/对象存储 → 已审核的只读 API → 页面读取。LPPL 计算使用另一队列和并发预算，资讯失败不能占用或阻塞拟合任务。

### 3.4 放行条件

- [ ] 逐源研究访问、供应商频率与大陆路径完成实测，审核证据可追查。
- [ ] 连续至少 5 个交易日真实原始响应与完整池证明，不是 fixture 或事后重命名。
- [ ] 至少一组相邻两日新严格晋级成功；分母、分子和缺失数可解释。
- [ ] 同日重试、断网、无原因、截断池、进程中断、损坏备份均按设计降级。
- [ ] 每天成功/失败/跳过回执可见，采集失败不清空前端已有结果。
- [ ] 独立确认数据公开权限后，才准备受控公开投影与在线 seed；没有把研究导入翻转布尔值发布。

## 4. 阶段 2：个股资讯闭环

| 工作包 | 来源与字段审查 | 页面行为 | 必须保留的边界 |
| --- | --- | --- | --- |
| 公告与新闻 | 优先核验交易所/公告发布源及既有 a-stock-data 目录；标题、链接、发布时间、股票、hash | 先展示缓存；按公告/新闻分类、搜索、收藏；原文在新页打开 | 新闻只保存索引；无转载许可不保存正文；没有因果/利好利空评分 |
| 公司概况与财务 | 公司身份、报告期、公告日、指标/币种/单位、修订版本 | F10 分节与财务表；缺值保留为空 | 当前简介不得贴到过去；报告期不等于可用日；修订不覆盖旧版本 |
| 股东与解禁 | 报告期/披露日、持股/变动单位、计划事件日及修订 | 关联股东表和解禁日历 | 季度持仓不标实时；计划不标结果；数量单位未知不换算 |
| 龙虎榜与资金 | 日期、证券、买卖额、来源分类、历史覆盖和换源记录 | 表格、来源说明、同口径历史 | 席位不等于最终投资者身份；供应商资金分类不等于交易所官方资金；不拼接不同来源做分位 |
| 股票目录 | 六位代码、交易所、名称/别名及目录取得时间 | 输入代码优先；名称检索清楚显示市场 | 当前目录不得充当历史 PIT 股票池 |

每个来源按“原始样本 → 解析测试 → 历史/权限检查 → 独立只读接口 → UI → 真实状态验收”交付，不一次整包接入完整 TradingAgents 或 AI 交易流程。首批验收资产保留贵州茅台，再加不同市场股票检查代码和接口差异；指数与个股不能混淆。

## 5. 阶段 3：统一时间轴

时间轴分为行情、信息事件、LPPL 输出三条展示轨道，使用相同交易日期坐标。事件有发生日、发布时间、首次取得时间；模型有运行日、数据截止日和首次可见回执。只有显示层关联，不建立从新闻/资金/题材到 LPPL 拟合输入的连接。

默认“当时已知”视图只展示截止时点已存在的记录；用户可主动打开“事后补充”，后取得资料要有显著标记。修订连接旧版本；新提醒与修订沿用原规则，不能因补了一条公告就生成新模型提醒。

验收：对同一资产/日期固定 cutoff，晚取得文章、财务修订、重跑模型不得改变旧视图；旧请求不得覆盖新日期。没有真实首次可见凭证的历史重放仍标研究，不能被计为真实提前发布。

## 6. 阶段 4：盘中与全球信息

- 六时点：09:25、09:35、10:00、11:30、14:00、15:00。记录应采样和实采样时间、源时间、会话和迟到；错过记 missing，不从收盘数据补造。盘中发布资格和授权单独核验。
- 宏观：按原路线优先 Treasury、NY Fed、BIS、ECB、BLS、EIA；区分初值/修订、观测日/发布日期。VIX、DXY、金油和汇率逐源授权，不能因为其他软件能展示就默认可再分发。
- 全球新闻：保存标题、来源、时间、原链接及 hash；来源失效与没有新闻分开，标题不作为 LPPL 特征。
- 预测市场：仅在书面许可后启用约六小时异步刷新；标 Polymarket/Kalshi、“预测市场隐含概率”、合约定义、时点、流动性和 stale。不是官方 FedWatch，不喂入 LPPL。

## 7. 验收与发布分层

**代码完成**：测试与失败路径通过、接口可联调。**真实数据完成**：有原始响应和持续采集记录。**上线完成**：实际授权后的部署、读取、监控和恢复成立。三者不得互相代替。

本轮证据见 [日终实现与验收](../validation/2026-11-09-eod-closure.md)。未验证的来源许可、供应商频率、大陆网络和生产运行保持 **NOT_ESTABLISHED**；未运行的线上性能与用户试用保持 **NOT_INSPECTED**。H1/H2/H3、Q2、MPL、Ising、Q-DD2、PPE 的历史失败不会因资讯功能增加而升级为预测能力。
